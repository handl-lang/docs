Retro — derive-DSL root ops: closing the measured sqrt/rsqrt refusal ​

Scope: mlopt_core/laws/cond.py (the dspec expression bank), mlopt_discovery/dspec_synth.py (the synthesizer's search bank), lab/probes/weightspace_fold_probe.py, tests/test_cond_laws.py, tests/test_discovery_dspec_synth.py.

Depends on: project/retros/weightspace-fold.md (the measured gate-by-gate refusal this closes one named blocker of), plan 0025 §D3 (the weight-space family — derive-or-refuse).

What the refusal measured, and what changed ​

The weight-space lane measured the conv+BN fold W' = W·g/√(var+eps), b' = (b−μ)·g/√(var+eps) + β as structurally derivable but inexpressible: the pre-scaled tier fit (W' = mul(W, scale); b' at depth 3), so the missing piece was exactly scale = γ·rsqrt(σ²+ε) — and the DSL had no root op (gate 3: dsl_has_sqrt/dsl_has_rsqrt were False; float pow declines). This round adds the measured ops, nothing more:

  • mlopt_core.laws.cond — _DUNOPS gains "sqrt": math.sqrt and "rsqrt": λa. 1/√a. Both are float-valued and strict: math.sqrt raises ValueError on a negative operand, rsqrt's reciprocal turns a zero operand into ZeroDivisionError — both land in the _unop handler's (ArithmeticError, TypeError, ValueError) decline set, so the strictness contract (decline, never a fabricated complex or inf) needs no bespoke handler. Grammar doc updated (("sqrt"|"rsqrt", e)); both round-trip through derive_to_data/derive_from_data like every other op.
  • mlopt_discovery.dspec_synth — the search bank widens to match: UNOPS gains sqrt/rsqrt, BINOPS gains fdiv (the true division the refusal formula spelled literally — γ/√(σ²+ε). fdiv is load-bearing, not decorative: g·rsqrt(·) differs from g/√(·) in the last ulp, so only the fdiv+sqrt spelling can reproduce a /-spelled hook exactly under the synth's signature-equality gate). _vbin/_vun already route through _DBINOPS/_DUNOPS, so no per-op machinery was needed — the ops are data, per "laws are data".

pow stays int-only (a float exponent would smuggle a root the strictness contract can't bound — the probe's pow_float_exp_declines still measures True).

What this does and does not buy ​

  • Closed: refusal reason 1 of the weight-space retro ("the DSL has no square root") — both as spellability (eval_derive computes the scale) and as discoverability (the synthesizer mints the scale expr from measured bindings).
  • Open, named: (a) the derive value domain is still int | float — a per-channel tensor scale cannot be a derived value (gate 4 unchanged); this is the real gate on the conv+BN fold and is an architecture question (bound carries terms, not tensor values; derived attrs must stay JSON-safe; Const.value is typed scalar) — not a one-line op. (b) Enumeration depth: the complete fold expr is depth 4 over a 7-attr bank; the streamed synthesizer found the scale subexpr but the full-expr sweep is budget-bound. (c) Content, not capability: no law LHS names batch_norm (probe gate 5) and batch_norm is unpriced in _OP_FLOPS (gate 6).
  • Also fixed en passant: the probe's _load_audit resolved dspec_audit.py relative to lab/probes/ (stale tools/-era path); it now resolves lab/audit/dspec_audit.py.
