Task 0128 — Target-repo split (ADR-0128) ​

Split platform into the reference platform plus target/ecosystem repos. Repo = target; module = one implementation of one port; modules register named targets. Resolution: git deps + [patch], local-only. See project/adrs/0128-target-repos.md for the full extraction list.

Deferred ​

Resolved ​

  • FragmentSource::DataFile (ADR-0128 §Deferred) — implemented.handl-kit-data now reads a serialized Language from a data file (FragmentSource::DataFile; parser chosen by extension — JSON / YAML / TOML) and loads a kit manifest from a file or inline text (DataKitManifest::load / DataKitManifest::load_from_text). Read and parse failures name the file. A module repo can therefore ship fragment data and kit manifests as data instead of include_str!-pinning them into another crate.
  • The module-name import fallback the .hnl moves need — already implemented; no platform work required. Verified by crates/handl-runtime/tests/bare_module_import.rs (2 tests): a module file containing from "libc" import socket resolves, and applying the module's exported arrow reaches libc.socket through the module chain.
    • File-loader path: ModuleLoader::strip_module_decl_lines (handl-runtime/src/lib.rs:1805) lowers a non-file-resolving from "<name>" import <fn> to <fn> := "<name>.<fn>" via module_prep::host_import_bindings (module_prep.rs:494); the string callee dispatches through ModuleLookup.
    • HandlModule path: DependencyImportResolver (plugin-lib-handl/src/lib.rs:194) is auto-wired when a HandlModule has deps (lib.rs:1449), and TableImportResolver (stdlib/.../packages.rs:1142) does the same over the package table.
    • So the only requirements are registration + spec rewrite, below.

The .hnl move — landed via [dependencies] name resolution ​

The prescribed module-registration route (c/modules/lib-c, wire-name additions) was superseded by the lighter, already-built Phase-9.5 seam: .handl.toml [dependencies] maps an import name to a package directory and ModuleLoader resolves first-segment matches into it — so the specs became from "libc/socket" / from "ws-c" / from "concurrent-epoll" and the repo boundary is a manifest dep. c/ and web/ each hold a handl-packages/ subtree split pruned to their keep sets plus a manifest; the ws-c↔concurrent-epoll cross-repo cycle resolves both ways via the two manifests (c self-declares its own names because dep files loaded under its context carry name specs). import_preamble (plugin-engine-test) and host-cli's decl-stripping/splice-seeding gained dep awareness; the tooling kit is Kit::discover-based. Regression: handl-runtime/tests/dependency_import.rs.

The git-package→dir bridge (landed). [dependencies] entries also accept a repo-hosted source — name = { git = "…", rev|branch|tag = "…" } — and the manifest carries a [patch] table (name = "../sibling-dir") as the consumer-side local override, mirroring the Cargo [patch] + dev-link.sh story: the committed manifest names the package portably, and a patch whose directory exists wins (a missing patch dir is inert). An unpatched git dep resolves to package_cache_dir()/name ($HANDL_PKG_DIR, else ~/.handl/pkg) — the slot the ADR-0010 fetch hook materializes; nothing populates it yet, so the fetch half remains the follow-up seam. See handl_platform::config::resolve_dependencies and handl-runtime/tests/dependency_import.rs.

Residual, if module-chain registration is ever wanted on top: dep names take precedence over module lowering by design, so registering libc et al. as modules remains compatible. math-c and generated/icu{,-uc}* stay in platform (uncoupled / stdlib-owned artifacts) superseded — math-c → handl-lang/math-c, generated/icu{,-uc}* ports + configs → handl-lang/icu (see Phase-5 note above); per-repo dogfood gates for the moved packages are a c//web/ follow-up.

Finding 1 — the generated dirs are build artifacts, not source. Every handl-packages/generated/<lib>/ port and <lib>-<backend>-<target>/adapter is produced by hnl sdkgen from a *.sdkgen.yaml config plus spec inputs (*.idl, curl-spec/curl.h). The c backends already live in c/ and the webidl/js ones in web/. So the moved trees are regenerated in the target repo, not hand-rewritten: hnl sdkgen c handl-packages/generated/libc.sdkgen.yaml --output c/handl-packages/generated.

Finding 2 — the web and -c blocks are one unit. fetch-c and ws-c import ../concurrent-epoll/concurrent-epoll, and concurrent-epoll imports ../generated/libc-c-*, ../generated/curl-c-*, ../tls-libssl, ../ws-c. That is a cycle across the two "blocks" — they cannot move independently. (They decouple once the specs are names: c/'s modules import "concurrent" and web/ registers it.)

Blocker: the move needs git subtree split, which needs a clean tree — platform currently has uncommitted WIP (plugin-lib-handl/src/transform.rs, handl-kit-arrow-lower/src/lib.rs, handl-packages/desugar/, …). Commit or stash first.

Sequence ​
