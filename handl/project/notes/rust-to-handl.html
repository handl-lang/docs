Rust → Handl cheat-sheet ​

Reference for porting Rust code to idiomatic handl. Lookup tables first, idiom rules after. For why the seams exist, see ADR-0044/0077/0083/0096.

What stays Rust ​

Only the calculus vocabulary and irreducible atoms: combinators, effect ops (cap/op + handle ... with rust_* natives — the host/FFI seam, not the abstraction mechanism), FFI marshalling primitives. Everything else — including interfaces to those atoms — is handl.

Bindings and syntax quick-ref ​

hnl
export f: T ~> U := (x) ~> expr   -- top-level, typed
x := expr                         -- definition / binding (top level, do, for-body)
a == b                            -- equality (= / :: assigns are legacy
                                  -- spellings, being removed from grammar)
do { a := f(); b := g(a); a + b } -- sequential block; last expr is value
for x in xs { acc := f(acc, x) }  -- imperative sugar → rec lowering;
                                  -- := writes back to enclosing scope;
                                  -- the for expression itself is []
while { n: 5, acc: 1 } {          -- stateful loop: init record, step arrow
  [n, acc] ~> if n == 0
    return acc
  else { { state: { n: n-1, acc: acc*n } } }
}

Bytes are {"__bytes__": [n, ...]}; plain arrays also accepted on input. errno flag on ffi.call maps negative returns to errno extraction — wrap in result.err at the adapter edge (see generated/libc).

Gap: ffi.call raises on dlopen/dlsym failure — incompatible with the Result-only error model. A non-raising probe op (ffi.load / ffi.sym returning Result or Option) is needed before handl-side library/symbol probing (e.g. ICU version sniffing) can be written idiomatically. error.try exists as a host atom but is not the idiom.

Idiom rules ​

  1. Contract = a type; impl = a value of that type. Declare the interface as a record/arrow type (I := { f: T ~> U, ... }, plus axiom/guarantee: laws where refinement matters) in a neutral package; a backend (name-handl / name-c / name-native / name-stub) exports a value of that type — usually a do { ...; { f: impl } } record. Callers pick the backend by import path (from "time-c" import { now_ms }). cap/op/handle ... with are for effects (host/FFI ops), never for trait-style abstraction.
  2. Errors are values — no raise/throw. Fallible arrows return Result<T, E>; error.raise/error.try are host atoms for runtime internals, not the handl idiom (legacy corpus usage like collections/*.hnl pop is slated to move).
  3. Fail loudly, never approximate. If a backend can't implement an op correctly, omit it — callers get a loud failure (unicode-handl omits nfc/nfd rather than shipping identity).
  4. Semantic names, not implementation names — nfc, never nfc_icu4x; graphemes, never graphemes_utf16.
  5. Effects are inferred, not annotated — effectfulness comes from the cap/op declaration, not the signature. ~[N]~> is an arrow dimension annotation (ADR-0119), not an effect row — don't write it for effect marking.
  6. for for iteration, while for stateful loops — for x in xs when you're walking a list; while {state} {step} when the loop is a state machine or terminates on a condition. Avoid self-application recursion.
  7. Docs are --- + @details/@param/@returns/@example
  8. Marshal at the edge. Convert Bytes/handles/{ret,buf,outs} into semantic handl types inside the backend — never leak C shapes upward.
