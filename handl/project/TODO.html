Done — wrongly-placed Rust reifications retired (ADR-0040 kernel rule) ​

Rust holds the kernel (Plugin, Host, Operation, Behavior, RuleAcceptor, Contribution — ADR-0040) plus generic tooling; everything else is Handl over a C ABI / SDK-gen contract. A dead-code sweep (static cargo check --all-targets plus llvm-cov over the whole workspace) found 15 crates that nothing live depends on — ideas reified as Rust crates no binary ever linked. They are retired, not deleted from history.

High priority — package manager and import ​

The import op is now implemented in all three eval engines and the runtime has a module loader. The remaining blockers are dependency resolution in .handl.toml and a clear module-resolution policy.

High priority — handl stdlib in handl (ADR-0092) ​

plugin-lib-test is deleted; the test runner is now plugin-engine-test (ADR-0089). The framework is now pure handl: handl-packages/test/ holds assert.hnl/property.hnl/benchmark.hnl/fuzz.hnl/snapshot.hnl/ test.hnl and the canonical kit registers them. The pure-handl ops use the result pattern (ok/err tagged values) and do not rely on error.raise/ error.try; the runner's per-case EvalError → failed TestOutcome path remains unchanged.

Engine genericity and known issues ​

See AGENTS.md § "Known issues" for the source of truth. These are the residual hard-codings that break the "language as data" invariant and the current failing/warning tests.

Status: no open failing or warning items. The engine-genericity debt is closed except for the sites listed below, which are blocked on adding new Language vocabulary (a language-design decision, not a sweep); the design write-up lives in project/tasks/0081-remaining-kind-dispatch.md.

  • [~] Engine-genericity debt: the structural-token residuals in plugin-engine-parse-pratt (block opener, dimension bracket, block separators, keyword-as-identifier), the positional field-access/ type-annot reads in plugin-engine-transform-rewrite's desugar.data, the token.identifier probes in handl-runtime, and the duplicated kind: export lookups in plugin-lsp are closed — they resolve through Language token data (token_kind_for_label / token_in_category / token_pair) and child_role_index, with canonical fallbacks. See AGENTS.md §"Engine-genericity residual audit" (a2) for the full per-site list. What remains is blocked on missing vocabulary, not effort: plugin-ext-refinement/src/arrow_parser.rs is documented bootstrap (the arrow combinator vocabulary is calculus-kernel syntax), and handl-kit-arrow-lower (assign/bind/op/function/rec/ var/call) + host-cli/transform_categorical.rs (dim_arrow/ stmt.import/var/value) name specific canonical constructs. Closing those needs a new Language field (e.g. binding_kind / arrow_kind / pattern_role: tag) — a language-design decision, not a sweep fix.

High priority — bootstrap tooling integration (ADR-0085..0094) ​

Phase 1 crates are now plugin-ext-diag, plugin-ext-fmt, plugin-ext-lint, plugin-engine-typecheck (+ plugin-engine-typecheck-nbe), plugin-engine-test, and host-cli / plugin-ext-cli. The CLI subcommands are fmt, lint, typecheck (not check), test, run, eval, transform, gen-grammar.

Unblocking — test/perf infrastructure ​

These are still open and should be picked up alongside the above.

  • [~] Extend the tooling coverage gate beyond the tooling adapters.plugin-ext-diag is done (commit 9e1a1cda): 97.85% -> 99.42% with 6 targeted tests, and it is now in the gated set, which passes at 99.60% over five crates. The nine plugin-exec-* rule crates remain, and the assessment stands: they are 166-293 src lines each with only 2-3 unit tests each, so a 100% gate there means writing ~10 crates' worth of new tests — plan for that, it is not a config tweak.
