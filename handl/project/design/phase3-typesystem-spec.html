Phase-3 implementation spec — unified type system ​

Normative design: ADR-0106 (kernel, as amended) + 0152 (data) + 0153 (~[n]~> dimension index) + 0154 (identity/equality/universes/ literals/erasure) — same as phases 1–2. This spec orders what remains: the genuinely-hard items plus the polish that makes the dependent surface a real language. Waves of ≤4 parallel workstreams. New semantics that settle here get their own ADRs; several items are parked behind an explicit needs user decision section below.

A — Instance resolution (implicit evidence args) ​

The phase-2 {…} binders solve index args by unification and erase them at exec (eval.index_app projects the callee). The next step is implicit evidence args — ADR-0106 §11 already fixes the semantics: no interface/trait/impl; an algebra is an ordinary object, a "trait instance" is a value you hold and pass. Eq a/Semiring a are nominal formers; a dictionary is an object whose type link is the constraint former-app. Resolution = search, not unification.

  • Constraint formers: Eq : Type ~> Type-shaped declared formers; a dictionary value carries {"type": Former{C, args}, ops…}. First instances in lib-type: Eq/Ord/Show over the builtin nominals.
  • Evidence binders: {…} binder whose domain is a constraint former-app is discharged by search, not by unify_index. Surface marker is a decision (below); the elaboration slot is the existing implicit-pi drain (dependent.rs ~L4199-4270, dep_synth_call_type ~L2267, implicit_binder_head ~L4547).
  • Search: candidates = declared instances whose head nominal unifies with the constraint head; index args unify through unify_index/ctx.vcheck.conv; recursive goals (Eq(List a) needing Eq a) resolve depth-first under fuel; backtracking = store_mark/store_restore (checker.rs ~L1052). No candidate → honest stuck diagnostic (never silent type.unknown); ambiguous → decided by policy (decision 1).
  • Erasure class — the real fork: index args erase; evidence args are runtime arguments (the body calls dictionary methods), so the resolved dictionary materializes as a real call argument at elaboration. eval.index_app's callee-projection scheme needs a per-binder classification (Language data — e.g. the binder's declared domain marks evidence vs index), not blanket erasure.
  • Import story: instances ride Sig_m exports or a module-level registry — decision 2. Importable instances are what makes Ord resolution work across module boundaries.
  • Exit: sort{a} ⦃Ord a⦄ : List(a) ~> List(a) — call site writes sort(xs), the Ord(Nat) dictionary is resolved and passed; Eq(List(Nat)) composes; missing instance → diagnostic naming the constraint; ambiguity decided per policy; a dictionary-bearing call runs with the resolved instance (not erased); dependent_structure/ parity stay green.

B — Higher coherence (generic Hom(n) + comp-tree normalization) ​

Honest framing stays: this is research-shaped; the tractable slice is the existing boundary law made dimension-generic plus definitional equality for cell composition — not the full globular structure. (User direction superseded decision 6's n=4-then-stop scoping: the checking went generic, not "4 then stop".)

  • Hom(n) checking — generic: infer_hom (checker.rs) checks every literal n ≥ 1: cell_faces_at's boundary walk was already level-generic, so the n ≤ 3 gate was the only artificial cap — Hom(n, c₁, c₂) checks infer(c₁)/infer(c₂)'s (n-2)-faces by conv at any n. >>>[k] (infer_comp_axis/ infer_comp_axis_tys) and id_k (infer_id) got the same treatment — the vertical/horizontal laws are level-uniform — k > dim keeps its Dim error at any level; k ≤ 0, open dimension indices, and open endpoint types stay stored (the open-dimension bound, unchanged).
  • Comp-tree normalizer for conv (landed in kernel nbe.rs): cell.comp(k,·,·)/cell.id applications normalize to a canonical CellNf form — flatten same-axis chains into ordered Axis(k,·) nodes (associativity), drop ∘ₖ units (id_j(x) absorbs at j ≤ k+1 or recursively through its payload; objects are degenerate id towers and absorb at every axis), and transpose uniform j-grids at j < k (interchange — smaller axes sort outward, a terminating canonicalization: each transpose strictly decreases the preorder axis sequence). Bounded fuel; non-uniform grids, open axes, and non-unit leaves stay stuck — structural compare, never wrong-equal.
  • Effect: e >>>[2] eInv ~[3]~> id(f) (and its dim-4+ counterparts) checks under the generic boundary law; dependent.hnl's comp_assoc/id_left/id_right/interchange are definitionally convertible where the normalizer discharges them; the tagged-side Hom(m ≥ 3) unification escape stays as the proof-relevance stuck-contract.
  • HIT/quotient evaluation — document, don't implement: can a data ctor target Hom(k≥1,·,·)/Path(a,b) (a higher-inductive constructor)? The former machinery admits the declaration, but F.rec computes on 0-dim ctor values only — a path ctor needs the eliminator to specify its action on paths (an ap/map clause), which the fold machine has no rule for. Write the verdict as a short design/ note or parked ADR (probably: needs a new eliminator clause + a story for whether quotient equations are definitional or propositional) — not a workstream.
  • Exit: Hom(n) boundary law enforced by conv at every literal n; comp assoc + unit laws convertible; interchange convertible on uniform grids (verdict recorded); HIT note filed; the stored fragments restated in dependent.hnl comments (open dims, open endpoint types, non-literal axes — no dimension cap).

C — Dependent pattern unification (split-tree coverage) ​

Current: unify_index (dependent.rs ~L954) covers ctor-injective App heads (~L984-993), ring normal forms, IndexSolver linear solving; synth_match_dependent/synth_match_with_motive (~L3063+) instantiate ctor sigs and unify indices per arm — decided-impossible rejects the arm, absurd discharges it. The gap: unification is arm-local; nothing computes the split tree — which ctors the scrutinee's indices leave possible, and which are uncovered.

  • Kőszegi-style coverage: unify the scrutinee's index term against each ctor's result indices → per-ctor {split under substitution | impossible | undecided}; the possible set is the coverage requirement; missing possible ctor → "non-exhaustive: VCons not covered" diagnostic; all-impossible → absurd-context match (legitimate). Undecided ctors → a named "coverage unknown" warning — stuck ≠ error, but never silent.
  • Ctor-vs-numeral disjointness: App{Succ}-head vs Const 0 must be decided-impossible both directions (verify and pin — likely already follows from injector-head mismatch; this is what makes match (v : Vec(Succ n, a)) { VCons(h,t): … } provably total).
  • Ctor-form index patterns (Vec(VCons…)-shaped index terms in patterns) and nested patterns — extend unify_index's App arm; record what stays stuck.
  • Scope: dependent.rs (synth_match_*, ctor-sig instantiation, unify_index), a coverage judgment op if the split is op-shaped; types.yaml type.match rewiring if the check moves.
  • Exit: head{n,a} : Vec{Succ n,a} ~> a checks as total on a VCons-only match; uncovered-ctor match errors naming the ctor; disjointness decided both directions; undecided coverage warns; dependent_structure/parity green.

D — Succ-arithmetic bridge (ctor-aware index equality) ​

Flagged open in phase-2 WS-D: Vec(n+1+0) ≡ Vec(Succ n) is stuck — n+1 normalizes, the App{Succ} index term doesn't read as +1. The ctor-result instantiation gives ?k+1 one direction; the bridge is the other.

  • Design options (decision 3): (a) builtin rewrite — the index normalizer reads App{Succ, x} as x+1: needs the ctor table as Language data or it violates engine-genericity (a hardcoded Succ in Rust is a kind check); (b) data-declared index projection — the former's declaration carries a per-ctor index map (Succ ↦ n~>n+1), emitted by desugar.data and applied in eval_index before polynomial normalization — generic, the ctor's arithmetic is declared, not baked; (c) keep stuck — users write n+1 (the dependent.hnl convention). Leaning (b): only declared ctors bridge, and any inductive can opt in.
  • Scope: eval_index/eval_index_fuel (dependent.rs ~L370-374), unify_index, the IndexSolver boundary (~L905-949 — the bridge lives upstream of prove, in normalization), desugar.data emission in both impls (engine-transform-rewrite native + lib-desugar overlay — parity required), kit data for the declaration shape.
  • Exit: Vec(Succ n, a) ≡ Vec(n+1, a) convertible both directions; Zero/0 decided per the declared mapping; undeclared ctors stay stuck (no silent accept); decided-vs-stuck contract unchanged.

  • Compiled-backend parity: scope_value/global_value exist in all three engines (tree-walk ~L4113, bytecode vm.rs ~L538, cranelift lib.rs ~L630), but interpret_io_former is tree-walk-only (tree-walk ~L2243 — bytecode/cranelift eliminate handlers statically and never interpret IO former objects). Verify match ctor-object dispatch + seeded-Sym handle round-trip under bytecode/cranelift; port interpret_io_former or document the parity bound.
  • Artifact sizes: measure the erased artifact on stdlib-size modules (arrow_model.hnl precedent); the per-call O(module) prepare_exec_artifact walk on the eval_shared_* bridge is a carried perf edge.
  • Exit: hnl exists; the demos run identically under all three exec engines (or the divergence is named and bounded); hnl-gate.sh green on WS-F's migrated libs; artifact-size baseline recorded.

G — Diagnostics + user docs ​

The checker reports kinds and paths but no positions: every TypecheckDiagnostic emits span: None (lib.rs ~L308) even though AstNode.span: Option<Span> rides the AST (kernel ast.rs ~L193), and unify failures render internal encodings, not source-level types.

  • Spans: thread node.span into synth/check/unify diagnostics; plugin-ext-diag already owns Span/render_diagnostic — the lint pipeline renders, the typecheck one doesn't yet.
  • Expected-vs-actual: render Val through quote/domain_quote (dependent.rs ~L153) with zonking first — "expected Vec(n+1, a), got Vec(Succ n, a)" at the failing node's span; meta solutions shown, not ?m handles.
  • User docs: host/docs/site/ is Diátaxis-shaped and has nothing on the dependent surface — an explanation/ page (data families, F.rec, match refinement, Path/Hom, IO(sig), implicit binders) + how-to/ pages (write a data family; handle an IO effect; migrate a tag-string consumer). ADRs stay the spec; docs are the user surface.
  • Exit: a failing unify prints expected-vs-actual with a source span through hnl typecheck and the LSP path; docs pages landed and indexed in site.yaml.

Cross-cutting invariants (unchanged) ​

  • One value space: checker and exec share Val; arrow values stay self-contained serializable data (body_def+binds) — defunctionalized data, closures only as domain machinery (0106).
  • Types-as-values; every type-level entity is an index on a nominal former; nominal heads + structural bodies (0154 §3). Instance dictionaries are ordinary objects with type links (0106 §11) — search is an elaboration rule, not a new kind of value.
  • Dimension ≠ mode ≠ effect axes (0153): the ~[n]~> bracket is cell dimension; evidence args enter the implicit-binder slot, not the bracket.
  • Indices are type-level, erased at exec; evidence args are not — the implicit-binder slot has two erasure classes now, classified by declared domain, not ad hoc. The artifact lint stays the verifier (0154 §6).
  • Honest bounds stay honest: n≥5 stored-unchecked, undecided coverage is a named warning, non-normalizing comp-trees store — never a silent accept.
  • Engine-genericity: calculus vocabulary may be fixed in Rust; language constructs are Language data — the Succ bridge must be declared metadata, and new surface forms get AstShapeDef roles.

Progress log ​

  • Dogfood: real .hnl collections lib (lib-collections/ src/collections.hnl — full repros in /tmp/dogfood-report.md). Writing Maybe/Nat/Vec/List, implicit-binder vmap/vhead/ filter/zipWith/append, IO(sig) ops, instance evidence exposed every surface friction point:

    • Clean: data families (sorted + unsorted params), implicit {…} index binders + call-site inference, Vec{Succ n} bridge, single-arm dependent match (provably total on Vec{Succ n}), absurd discharge + unreachable-arm rejection, IO({puts}) sig records + handle coverage rules, instance search discharging {ev : Eq(a)} at eqv(Zero), Forall(K, x ~> B), export on implicit-binder fns and data, Sigma(Nat, m ~> Vec(m,a)) as the existential encoding.
    • Broken (silent-wrong or unwritable): runtime match on a parameterized family misdispatches without an inline (v : Fam(i⃗)) annotation + all-ctor arms — bare Nope: patterns act as binders (match Jx(9) { Nope: Nope } → Jx(9)), and the annotation can't be written inside a {…}-bound body (binders appear as unsolved metas in the domain: expected [?m1,?m0], got [n,a]; bare index names in paren annotations read as SORTS — Vec(n,a) ≡ Vec(Nat,Type_0), only n + 0 keeps var).
