Handl Ecosystem ​

Handl is a modular language infrastructure built around a categorical, runtime-independent IR. Its foundation is a closed arrow calculus with globular higher-categorical structure, allowing computation, laws, and transformations to share a common representation.

The ecosystem separates this foundation from the engines that process it, the abstractions built on top of it, and the environments in which it operates.

1. Kernel ​

The Kernel defines Handl's computational foundation: its arrow calculus, IR, value representation, and language schema.

The calculus is based on LWY (Lindley–Wadler–Yallop) and Sanada's arrow calculus, extended with graded effects and higher-categorical structure.

Key properties:

  • Closed arrow calculus: computation is expressed through six fundamental combinators (arr, >>>, first, choice, loop, app), rather than lambda calculus.
  • Globular structure: the IR represents morphisms across dimensions. Programs are 1-morphisms, laws and rewrites are 2-morphisms, and higher transformations extend this structure.
  • Composition and coherence: dimension-indexed composition, boundaries, rewriting rules, and coherence relationships allow higher-dimensional structures to compose consistently.
  • Graded effects: based on the Graded Modal Sanada Arrow Calculus, using graded operations and handlers to represent and interpret effects.
  • Language as data: inspired by Cimini's work, languages are described declaratively through syntax, grammar, AST shapes, evaluation schemes, type rules, and transformations, rather than being hardcoded into engines.
  • Serializable computation: arrows are represented as data, enabling inspection, transformation, serialization, and interpretation by different engines.

The Kernel provides a stable foundation without prescribing a particular runtime or execution strategy.

2. Engines ​

Independent components that process Handl representations. Engines can analyze, transform, compile, or execute the IR.

  • Compilation: LLVM (native), Triton, CUDA — compile-llvm, compile-triton, compile-cuda.
  • Execution: Cranelift, bytecode, tree-walk interpreter — engine-exec-cranelift, engine-exec-bytecode, engine-exec-tree-walk.
  • Transformation: IR-to-IR rewriting, desugaring, optimization — engine-transform-rewrite.
  • Language processing: lexer, parser, typechecker, linter, formatter — engine-lex-pattern, engine-parse-pratt, engine-typecheck, engine-lint, engine-fmt.

Engines are interchangeable consumers and processors of the shared representation, not intrinsic parts of the Kernel.

3. Libraries (lib-*) ​

Reusable Handl libraries (.hnl) providing foundational and domain-specific functionality, such as mathematics, strings, logic, and other utilities.

Libraries provide runtime-agnostic abstractions: the same APIs can be used across different execution environments, with runtime-specific implementations preserving compatible interfaces and semantics.

This allows application code and higher-level libraries to remain independent of the underlying runtime.

4. Kits (kit-*) ​

Curated collections of libraries and components targeting particular environments or use cases — testing, server-side development, and web services, for example.

Kits provide ready-to-use environments by assembling compatible libraries, engines, and supporting components.

5. Tools ​

Developer utilities and generators that facilitate development and interoperability with external systems.

SDK generators produce type-safe Handl APIs from existing interfaces:

  • sdkgen-python — Python interoperability.
  • sdkgen-c — C interoperability, including libc, libcurl, and zlib.
  • sdkgen-webidl — Web APIs, including Fetch and Console.
  • sdkgen-cli — type-safe APIs for spawning and interacting with CLI processes, providing SDK-like interfaces for tools such as Git.

6. Host & Extensions ​

The distribution and integration layer exposing Handl to users and development environments.

  • Host: CLI and LSP — host-cli, host-lsp.
  • Extensions: VS Code and Neovim integrations — extension-vscode, extension-neovim.

8. Products & Research ​

Domain-specific applications and research projects built on Handl.

  • MLOpt — optimization of existing machine learning models for embedded architectures. github.com/handl-lang/mlopt

Architectural principle: The Kernel defines a compositional, higher-categorical computational model. Engines interpret and transform its representations. Libraries provide runtime-agnostic abstractions, while Kits assemble them into usable environments. Tools bridge Handl with external systems, and Hosts expose the ecosystem to users and development environments.
