Libraries ​

lib-* is the largest family in the ecosystem — 130+ repositories of reusable Handl code. The organizing rule is the port/impl split:

  • A port (lib-<name>) is a contract — .hnl signatures, axioms, and laws every backend must satisfy. Ports are pure data + arrow declarations; they never pick a runtime.
  • An impl (lib-<name>-<backend>) satisfies the contract for one backend: -c over the C FFI, -js over the JS interop surface, -handl as a pure-.hnl implementation, -stub as a deterministic fallback.

One package per repo, .hnl sources only — Rust appears solely as const-only *_HNL exporter crates that embed the sources. Each repo carries a pkg.hnl manifest declaring { deps, modules }; dep keys map to handl-lang/lib-<dep> git deps.

Compression ​

RepoWhat it is
lib-compressCompression contract — codec types + backend laws
lib-compress-gzip-c · lib-compress-zlib-cgzip (zlib gz*) / raw-deflate backends over libz

Adding a library follows the same rule as adding a language: declare the contract as a port, ship at least one impl, and let pkg.hnl deps carry the wiring. The kits curate these into ready-to-use environments.
