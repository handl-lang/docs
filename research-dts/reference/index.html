Lean 4 formalization (lean/) ​

A Lake project (lakefile.toml, lean-toolchain).

modulecontents
Dts/Basic.leanhandlers, bodies, the core terms
Dts/Precedence.leanthe precedence relation and its well-formedness
Dts/Synthesis.leansynthesize: precedence → nested handle
Dts/TopoSort.leanthe topological sort and its properties
Dts/Semantics.leanoperational semantics of nested handlers
Dts/SemanticEquivalence.leansynthesis preserves semantics
Dts/Commutativity.leanwhen unrelated handlers may be reordered
ListDigraph/Basic.lean, ListDigraph/TopSort.leanthe digraph + topological sort the proof is built on

Python reference implementation (python/) ​

modulecontents
dts.precedence_parserparse_spec, format_spec, Spec, Handler, ParseError
dts.case_studies.http_middlewaresynthesize(body, ordered) over an HTTP middleware precedence
dts.case_studies.event_driven_partial_orderthe same over an event-driven partial order
dts.case_studies.cyclic_detectiona spec with a cycle: parse + reject with a diagnostic
dts.eval.property_testsgenerated specs asserted against the synthesis

synthesize lives with each case study on purpose: the interesting part is the linear extension the parser derives, and each study exercises a different precedence shape.
