Function

Whether ch is whitespace (skipped by the lexer). \n is not skipped: it lexes as a layout token (TokenKindDef::layout — token.newline in the canonical kit) so layout-aware constructs such as record literals can treat a line break as an element separator.

hnl_engine_lex_pattern::is_word_literal ​

Function

Whether a Literal pattern's text is "word-like": composed entirely of identifier-continue characters (a-zA-Z0-9_). Such literals (keywords like let, if, true) require a word boundary after matching so they don't greedily consume the prefix of a longer identifier. Operator literals (==, ->, () contain non-identifier characters and are unaffected.

rust
fn is_word_literal(text: &str) -> bool

hnl_engine_lex_pattern::try_delimited ​

Function

Try to match a delimited block (string, comment, template).

When nesting_open is Some, the scanner tracks nesting depth: each occurrence of nesting_open increments the depth, and the close delimiter only terminates the block when depth returns to zero. This allows brace-balanced blocks (e.g. json{...}) where inner { / } pairs must not prematurely close the token.

rust
fn try_delimited<'r>(rule: &'r handl_language::LexerRuleDef, open: &str, close: &str, escape: bool, close_at_eof: bool, nesting_open: Option<&str>, src: &str, pos: usize) -> Option<(&'r str, String, usize)>
