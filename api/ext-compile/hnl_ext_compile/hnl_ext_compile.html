hnl_ext_compile::js_module_graph ​

Function

The .hnl import graph for hnl compile js (ADR-0128 Phase 5): walk the entry file's top-level stmt.import specs — the same statement granularity compile-js's module emit sees — resolve each with [resolve_spec_path] ([dependencies] name first, then the ModuleLoader bases: the importing file's directory, the module root, the working directory), and recurse into each resolved file.

The result rides to the compiler in JsConfig::modules + entry_imports; the compiler itself never touches the filesystem. Specs that resolve to no file (host modules like js/str, or plain missing paths) produce no edge and keep their __handl_rt/ES-import emit.

rust
fn js_module_graph(entry: &std::path::Path, entry_src: &str, lang: &handl_language::Language) -> (Vec<handl_plugin_compile_js::JsModule>, Vec<(String, String)>)

hnl_ext_compile::resolve_dep_spec_path ​

Function

Resolve a [dependencies] specifier: when the first /-separated segment of spec names a declared dependency, the remainder resolves inside that package's directory (dep/lib/file → <deps["dep"]>/lib/file; a bare dep name resolves the package dir's index.hnl/<name>.hnl main file). Returns None for non-dep specs.

hnl_ext_compile::spec_resolves_to_file ​

Function

Whether <spec> resolves to an existing file — first as a .handl.toml [dependencies] specifier (a dep name shadows a same-named relative directory, mirroring ModuleLoader::resolve_path), then under any of bases (checked in order — mirroring ModuleLoader relative resolution: importing module's directory, module root, working directory).

A directory is treated as a package if it contains an index.hnl or a <dir>/<name>.hnl main file; a bare name without .hnl is tried with .hnl appended.

rust
fn spec_resolves_to_file(spec: &str, bases: &[std::path::PathBuf], deps: &std::collections::HashMap<String, std::path::PathBuf>) -> bool
