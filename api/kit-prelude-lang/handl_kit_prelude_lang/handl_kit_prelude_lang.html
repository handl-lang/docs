handl_kit_prelude_lang::EXCLUDED_FRAGMENT_IDS ​

Constant: &[&str]

Fragment ids that were excluded when generating the YAML files.

These are non-canonical duplicate fragments (behavioral, non-union types) that share an identity key with a canonical fragment:

  • eval.call.postfix — call's eval.call is the canonical eval scheme.
  • grammar.call.postfix — call's grammar.call.infix is the canonical infix rule for (.
  • grammar.apply.prefix — paren's grammar.paren.prefix is the canonical prefix rule for (.

handl_kit_prelude_lang::language_from_dir ​

Function

Build a [Language] from the eval-path YAML data files in a directory.

Reads tokens.yaml, grammar.yaml, eval.yaml, types.yaml, ast.yaml, caps.yaml, options.yaml, lexer_rules.yaml and (optionally) transforms.yaml / globals.yaml from dir and merges them the same way [language_from_yaml] merges the embedded files. lints.yaml / lsp.yaml are tooling fragments — layer them via [merge_lints] / [merge_lsp] when the consumer wants them.

Errors ​

Returns [LangError] if dir is not a directory, any required YAML file is missing or unreadable, or a fragment fails to deserialize/merge.

rust
fn language_from_dir(dir: &std::path::Path) -> Result<handl_language::Language, handl_language::LangError>

handl_kit_prelude_lang::language_from_yaml ​

Function

Build the canonical eval-path [Language] from the embedded YAML files.

Each file contains a YAML list of fragments of one type. The fragments are deserialized and merged into a single [Language]. eval.yaml holds the arrow-calculus Term definitions (ADR-0052 kernel).

The full parse is cached on disk: the merged Language is serialized to ~/.cache/handl-lang/language-<key>.bin, keyed by a content hash of every embedded fragment plus the package version. Reading the snapshot is ~100× faster than re-parsing ~10k lines of YAML, which matters under runners that spawn a process per test (nextest) — every test paid the parse. A corrupt or stale snapshot simply falls back to parsing.

Errors ​

Returns [LangError] if any YAML file fails to deserialize or a merge fails (should not happen — the files are pre-resolved).

rust
fn language_from_yaml() -> Result<handl_language::Language, handl_language::LangError>

handl_kit_prelude_lang::merge_globals ​

Function

Merge ambient global value bindings (globals.yaml) into lang.

globals.yaml is a YAML mapping of name: <literal value> — the values are data (numbers, strings, booleans, records), not evaluated source, so no eval engine is needed at merge time. Runtime seeds them into the engines' global scope at build time (Language::globals).

rust
fn merge_globals(lang: & mut handl_language::Language, globals_yaml: &str) -> Result<(), handl_language::LangError>

handl_kit_prelude_lang::merge_lang_fragments ​

Function

Merge the eval-path YAML fragment strings into a single [Language].

Each argument is the raw YAML text for one fragment type — the eval-path set only: tokens, grammar, eval, types, ast, caps, options, lexer_rules, transforms. Tooling fragments (lints, lsp) are intentionally absent; consumers that want them merge them on top (see handl-kit-data-prelude).

Errors ​

Returns [LangError] if any YAML fails to deserialize or a merge fails.

rust
fn merge_lang_fragments(tokens_yaml: &str, grammar_yaml: &str, eval_yaml: &str, types_yaml: &str, ast_yaml: &str, caps_yaml: &str, options_yaml: &str, lexer_rules_yaml: &str, transforms_yaml: &str) -> Result<handl_language::Language, handl_language::LangError>
