hnl_engine::CompositeModel ​

Struct

A composite model that delegates specific Term tags to a delegate model while using a primary model for all other tags.

This is the ADR-0103 Phase 4 infrastructure: HoTT-specific tags (Path, Equiv, CellId, etc.) delegate to a Handl-authored model (data), while core arrow-calculus tags stay in the Rust engine (bootstrap). As the migration progresses, more tags move to the delegate model.

The delegated_tags predicate determines which Terms go to the delegate. For run, the decision is based on the term itself. For rewrite, the decision is based on the source or target — if either is delegated, the entire rewrite goes to the delegate.

  • M2 — the delegate model (e.g. HandlModelAdapter). Must share the same Value type as M1.

hnl_engine::ModelData ​

Trait

A data-driven model that runs on [TermData] / serde_json::Value instead of the Term enum (ADR-0103 continuation).

Parallels [Model] but operates on the tagged-record data representation, avoiding the Term enum round-trip for Handl-authored models. The incoming value is borrowed (data models do not own it) and ctx is shared immutably — data models read handler_stack / node_ref rather than mutating the context.

hnl_engine::is_hott_tag ​

Function

ADR-0103: identify Term variants that are HoTT-specific (type/proof judgments) and should delegate to the type model, not the kernel.

These tags "leaked into the computational kernel" per the ADR. They represent type-level semantics (paths, equivalences, cells, etc.) that belong in type_model.hnl, not in the Rust execution engines.

As the ADR-0103 migration progresses, more tags move from the kernel (Rust ValueModel) to the delegate model (Handl-authored .hnl). This predicate is the boundary function used by [CompositeModel] to decide which model handles each Term.

Module: nbe ​

NbE evaluation of Term → handl_value::nbe::Val (phase-1 spec WS-A). The arrow calculus evaluates into the shared semantic domain: constants become Val::Const, Seq/Choice/First/ App thread the incoming value through the combinators (the same arrow semantics as [crate::term_interpreter]), and Op nodes dispatch to a caller-supplied [OpHandler] — judgment ops belong to the checker, not the kernel (engine-genericity: the kernel knows only the calculus vocabulary).

Scope: the fragment the typechecker evaluates (Arr/Const/Op/ Seq/First/Choice/App/RecordProj/RecordWith). Handle/ Rewrite/Tag/Cobind/Loop/Iter/Child/Opaque and the 2-cell faces return NotImplemented — they are runtime/effect or derived-data positions that never appear inside type-level computation (ADR-0054 pure-eval boundary); globular Seq axes k > 0 delegate to the handler as a cell_comp_axis op.

Module: term ​

The arrow-calculus Term kernel (ADR-0104b).

Term is the arrow-calculus evaluation kernel. A Term is an engine-agnostic description of what to evaluate, not how. Engines (tree-walk, bytecode, cranelift) interpret schemes; the scheme itself is pure data. Surface constructs are lowered to a small set of core combinators. [Term::desugar] recursively expands any remaining derived forms into this core set before interpretation.

Value here is [serde_json::Value] — no new value type is invented.

Module: term_data ​

ADR-0103 Phase 6: TermData — the data representation of Term.

TermData is a newtype around serde_json::Value representing a Term as a tagged JSON record. Each Term variant becomes an object with a __tag__ field and one field per variant payload:

json
{"__tag__": "Arr", "value": 5}
{"__tag__": "Seq", "fst": {...}, "snd": {...}}
{"__tag__": "Op", "name": "add", "args": [...], "source": "Native", "lit": null}

This is the target representation per ADR-0103: the Term enum disappears, replaced by serde_json::Value (tagged records). The existing Term enum stays as the bootstrap representation; TermData is the data target.

Conversion ​

[TermData::from_term] converts a Term to TermData. [TermData::to_term] converts back (for bootstrap compatibility). The conversion is lossless for every variant of the kernel vocabulary.

Why not serde? ​

The Term enum derives Serialize/Deserialize, but serde's default (externally tagged) representation ({"Arr": {"value": 5}}) does not match the ADR-0103 tagged-record shape ({"__tag__": "Arr", "value": 5}). The tagged-record shape is what Handl-authored models consume (see plugin_lib_handl::model::term_to_value), so TermData uses that shape directly. The conversion is implemented manually to stay lossless and to keep the JSON shape stable independent of serde's enum representation.

Module: term_interpreter ​

Pure-data interpreter for the arrow-calculus Term kernel.

This is a proof-of-concept evaluator for lowered Term graphs. It returns Err for any construct it does not (yet) handle, which lets callers fall back to the existing AST eval engine.
