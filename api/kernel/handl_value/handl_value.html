handl_value::BINDS_ID_BASE ​

Static

Encode context for [tagged_to_value]: dedups Rc-shared binds maps so a binds DAG does not expand exponentially into JSON.

Sibling arrows in a rec region share binds maps whose entries hold further arrows carrying their own binds — inlining expands the shared DAG into an exponentially duplicated tree (the same blowup the removed __envref__ registry fixed for the old env field). A shared map's first occurrence serializes inline with a "__binds_id__": <n> marker; later occurrences emit {"__bindsref__": <n>}. Refs always point backward in document order (the DFS emitter visits the definition first), so the encoding is self-contained — no process-local registry — preserving ADR-0106's "arrow = self-contained serializable data" contract.

Unshared maps (Rc strong count 1) always serialize inline: they cannot recur, so the plain-object form keeps the exact round-trip.

Serialization-scoped base for __binds_id__ numbering.

Ids must be unique across a decoded document, and one document can embed values that were serialized separately -- a module's bindings are serialized once and later embedded in a module record -- each starting its own numbering at 0. Colliding ids make a __bindsref__ resolve to the wrong definition, which is how an arrow ends up carrying another arrow's binds (its body_def from one arrow, its binds from another). A process-wide counter keeps ids unique across serializations; ids are opaque u64 labels in the JSON.

handl_value::BUILTIN_TYPE_GRAPH ​

Constant: &[(&str, Option<&str>, Option<&str>)]

The canonical builtin type.* nominal graph — data, not code (ADR-0154 §1/§2). Each row is (seed, parent_seed, type_seed): parent is the <: edge, type the membership edge (every declared type is a member of Type). The parent graph encodes Nat <: Int <: Number <: Value, Float <: Number, and every other builtin type directly under Value (the top).

Seeds are the qualified declared names (type.Int), matching the data.<DeclName> former convention — identity, so every engine that mints or reads these nominals agrees on the seed spelling.

handl_value::ForeignResource ​

Struct

An opaque foreign resource tracked by RAII (ADR-0083 §2.2 — finalizable values, a Phase 4 prerequisite).

Wraps a raw C pointer (ptr) and an optional finalizer cleanup function. When the last [Rc] reference to a ForeignResource drops, [Drop] runs the finalizer exactly once (guarded by the dropped flag to prevent double-free). This is the mechanism that lets opaque handle-typed FFI pointers (file descriptors, mmap regions, socket handles) get cleaned up automatically when the handl value holding them goes out of scope — no GC, no manual close.

Safety invariants ​

  • ptr must be a valid opaque handle obtained from a C function (e.g. a file descriptor cast to a pointer, an mmap region, a socket handle). This type never dereferences ptr — it only passes it to finalizer.
  • finalizer, when Some, must be safe to call with ptr exactly once and must release the underlying resource (e.g. libc::close).
  • This type is held inside an [Rc] (single-threaded), so it is notSend or Sync. The dropped flag uses [AtomicBool] to prepare for a future Arc migration that would make resources thread-safe; the atomic is harmless in the single-threaded case.

handl_value::Sym ​

Struct

A nominal identity object — the sym() primitive of ADR-0106 §2.

A Sym is a first-class nominal identity with:

  • a unique handle minted from a global counter (the identity — used for equality and hashing),
  • a display name (presentation only; two syms with the same name are never equal — only the handle decides),
  • an optional parent, which must itself be a [Sym]. The parent structure is a single-parent tree by construction (diamonds are impossible: each sym has exactly one parent, fixed at construction), and cycles are impossible because a parent is always constructed before its child (and JSON decoding is a tree, so it cannot create one either).

Equality ​

Identity equality, not structural equality: a sym equals itself, and two distinct syms are never equal — even with identical names and identical parent chains. Sym's PartialEq compares handles; the display name is not part of identity. Hashing agrees (Hash hashes the handle), so hash/eq consistency holds.

Serializability ​

The JSON encoding is {"__sym__": {"handle": &lt;n>, "name": "...", "parent": &lt;nested sym or null>, "type": &lt;nested sym or null>}} — explicit data with no closures and no hidden state. Round-tripping preserves the handle, so a deserialized sym compares equal to the live sym it was serialized from (within a process; cross-process identity is a follow-up ADR per ADR-0106).

The two links (ADR-0154 §2) ​

Membership and subtyping are two links, not one chain:

  • parent is the subtyping link: T <: U walks parent (Nat <: Int <: Number). Read by has_ancestor/is_descendant_of.
  • ty is the membership link: a value that is itself a type carries ty → the nominal of its type (Int.ty = Type, i.e. Int : Type). Ordinary member values carry their type link as an object field instead (the {"type": …} field of ctor values) — it lives on Sym only for nominals, which have no other carrier.

Neither link is part of identity: PartialEq/Hash compare handles.

handl_value::TensorValue ​

Struct

A dense, row-major f64 tensor — the payload of [TaggedValue::Tensor].

Mirrors the {"__tensor__": {"shape": [d, ...], "data": [x, ...], "dtype": "f64"}} wire form host-tensor emits across its Function boundary: shape is the extent per axis (rank = shape.len()), data the flat row-major payload with data.len() == product(shape). dtype is implicit — "f64" is the only element type this variant carries.

Unlike [ForeignResource], a tensor is a value, not an opaque handle: equality is structural over shape + data (elementwise f64 ==, matching [TaggedValue::Float]'s comparison — so 0.0 and -0.0 compare equal and a NaN element makes a tensor unequal to itself), and hashing agrees (elements hash as f64 bits with -0.0 normalized to +0.0, since 0.0 == -0.0 but their bit patterns differ).

handl_value::check_portable ​

Function

Verify a serialized [serde_json::Value] document is safe to send past a process boundary — a file write, network send, or foreign consumer that cannot see this process's decode context.

[tagged_to_value] output is self-contained within one document, so in-process round-trips through [TaggedValue::from] never need this. Call it at egress points before the document leaves. It rejects:

  • {"__envref__": <id>} — the removed process-local env registry. The env field it referenced is ignored on decode, so a persisted document silently loses the closure environment.
  • {"__bindsref__": <id>} with no {"__binds_id__": <id>} definition in the same document — a dangling document-local ref (e.g. a subtree extracted from a larger document); decode resolves it to an empty binds map.
  • {"__resource__": {"ptr": <n>}} — a raw process-local pointer; in another run it decodes to a dangling [ForeignResource].
  • {"__compiled__": <id>} — a compiled-program handle whose artifact lives in this process's COMPILED_REGISTRY (handl-runtime's COMPILED_VALUE_KEY; spelled out here because the registry crate depends on this one, not the reverse). In another process the id indexes an empty or unrelated registry.

Returns Err describing the first offending reference found.

rust
fn check_portable(v: &serde_json::Value) -> Result<(), String>

handl_value::comp_at ​

Function

∘ₖ of two normalized n-cells (k < n): the globular pasting law.

The boundary law tgtₖ(a) = srcₖ(b) is checked first; then the composite's k-boundaries are srcₖ(a)/tgtₖ(b) and every other axis j pastes the operands' j-boundaries pairwise (∘ₖ applied one dimension down), which recursively enforces the lower boundary laws.
