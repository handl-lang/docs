handl_defining_handl::corpus ​

Function

Build the self-hosting corpus: a set of programs using the data-driven subset constructs that all three eval engines (tree-walk, bytecode, cranelift) can evaluate.

Each case's [Ast] is constructed manually using the canonical data-driven node kinds and the payload conventions documented by the Phase 4 emitters. The Pratt grammar for delimited forms (call/if/function) is a placeholder per Phase 4 deviations, so ASTs are hand-built rather than parsed from source.

The corpus covers the following constructs. Cases marked (tw-only) use a Prim op implemented in the tree-walk engine but not yet in the bytecode or cranelift engines — they set [CorpusCase::tree_walk_only] and are skipped by the compiled-engine tests. Currently no case is tree-walk-only; the flag is retained for future engine-coverage gaps.

Note: the call construct targets 2-argument calls (the canonical emitter's fixed arity), so the function-call case uses a 2-arg function f(x, y) -> x + y applied as f(3, 4). The pipe construct's scheme is App { callee: Child 1, args: [Child 0] } — it applies the right child (a function) to the left child (a value) — so the pipe case uses a 1-arg function.

handl_defining_handl::language ​

Function

The self-describing Language assembled from the canonical YAML data files.

This is the canonical data-driven language: the same Language produced by [handl_kit_data_prelude::assemble] — the full language (tokens, grammar, eval, AST shapes, capabilities) merged into one Language value from the 7 YAML files in handl-kit-data-prelude/data/. It is "handl defining handl" for the subset.

handl_defining_handl::proc_corpus ​

Function

Build the arrow-authored corpus: a set of programs authored using arrow notation (x ~> body), the authoring surface introduced in ADR-0052 Phase C.

x ~> body parses as function(params, body) — a function node with params and body. The function eval scheme produces a closure.

Each case's [Ast] is constructed manually using the canonical data-driven node kinds. The function node has payload {"params": [...], "body": idx} (matching the existing corpus convention). Cases that apply a function to a value use the pipe construct (App { callee: Child 1, args: [Child 0] } — applies the right child to the left child).

All cases produce concrete values (numbers), not closures, so they can be run through every engine (v1 and v2, tree-walk and compiled) for cross-engine conformance.
