handl-defining-handl ​

The self-hosting infrastructure for ADR-0044 Phase 8.

ADR-0044 Phase 8 specifies: "Language carries an eval capability; a Language value describes handl itself. Ship a handl-defining-handl data file loaded as a Language value, evaluated under itself. The bootstrap becomes compile(handlLanguage, native) via the cranelift engine."

This crate produces a [Language] value that describes the subset of handl the data-driven engines can evaluate — the constructs migrated to the data-driven model in Phases 4–5 (value, var, the binary arithmetic / comparison ops, unary not, block bindings (do { x = v; ... }), if, ternary, function, call, pipe, paren, apply). It is the "handl defining handl": the language spec as data.

Scope (honest deliverable) ​

Phases 4–5 migrated a representative subset of handl's ~50 constructs to the data-driven model. Full self-hosting of the entire handl language is not achievable yet — constructs whose eval schemes dispatch to Foreign host functions (match, handle, flow, fanout, field-access, import, export, module, template, resolve, json, hello.greet) are not compilable by the bytecode/cranelift engines, and several Prim ops (array, object, index, assign) are not yet implemented in any engine. The type-annot construct uses a Bind with $payload (reads payload["name"]) but a type annotation has no natural bind name, so it is blocked until the payload convention is clarified. This crate does not attempt to describe the full handl language as data. Instead it:

  1. Builds the self-hosting infrastructure: a [Language] value describing the subset, assembled from the canonical YAML data files via [language].
  2. Provides a self-hosting corpus ([corpus]) of subset programs used by the integration tests (self_host.rs, bootstrap.rs, futamura.rs) to prove the self-hosting mechanism. ADR-0052 Phase D adds an arrow-authored corpus ([proc_corpus]) demonstrating the arrow-calculus authoring surface (x ~> body).

What is proven: a Language value can describe a language and be evaluated under itself (across all three eval engines: tree-walk, bytecode, cranelift), and compiled to native code via the cranelift engine — the Futamura projection sanity check.

What is deferred: full handl self-hosting (pending migration of the remaining constructs — primarily Foreign-dispatched constructs and the unimplemented Prim ops), and a standalone-binary bootstrap (writing an executable to disk). Phase 8 proves the mechanism, not the standalone-binary artifact.
