handl_language::AST_VALUE_KEY ​

Constant: &str

The sentinel object key marking a [Value] as carrying a serialized [Ast] subtree — an unevaluated expression (ADR-0041 §6, ADR-0045).

A vau-bound unevaluated child is a JSON object {"__ast__": <serialized Ast>}. The embedded [Ast] is the subtree rooted at the child (the child node plus all transitively-referenced descendants, reindexed into a standalone arena), so the meta eval host function can consume it directly: eval(self, ast_value). Use [ast_value] to construct one and [as_ast] to extract it.

handl_language::LANGUAGE_VALUE_KEY ​

Constant: &str

The sentinel object key marking a [Value] as carrying a serialized [Language] (ADR-0041: Language is a first-class value).

A language value is a JSON object {"__language__": <serialized Language>}. The full [Language] data is embedded in the value — this is a genuine first-class value, not a string handle into a registry. Use [language_value] to construct one and [as_language] to extract it.

handl_language::REGISTRY_VALUE_KEY ​

Constant: &str

The sentinel object key marking a [Value] as carrying the host type registry identity of a type value (ADR-0054 — Generic Typecheck Engine).

A type value minted by a host type registry is a JSON object {"__tag__": <tag_name>, "__registry__": <registry_id>, ...payload}. The __registry__ key records which registry minted the type value, so equality and matching can be scoped to a single registry (ADR-0054 §"construct"). Like __tag__, this key is reserved: user object literals cannot produce it, so a type value's registry identity is unforgeable.

handl_language::TAG_VALUE_KEY ​

Constant: &str

The sentinel object key marking a [Value] as a tagged value (ADR-0055 — Tagged Values).

A tagged value is a JSON object {"__tag__": <tag_name>, ...payload} minted by the host tag capability. The __tag__ key is reserved: user-constructed object literals cannot produce a __tag__ key (the eval engines reject it), so the only way a value acquires a __tag__ key is through the host tag.tag host function. This is the forgery-prevention mechanism — tagging is a host capability, not a user-constructible convention (ADR-0055 §3). Use [tag_value] to construct one, [as_tag] to read its tag name, and [is_tag_value] to test for it.

Module: capabilities ​

Capability set derivation. Capability set derivation (ADR-0044 §7 safety, ADR-0052 kernel).

A Language's capability set is the transitive closure of Foreign source names across all its eval schemes, plus any explicitly declared capabilities. This makes "does this Language touch the filesystem?" a static data query — no runtime sandbox required for a pure Language.

In the arrow-calculus kernel the capability boundary is structural: an Arr with source: Foreign(name) is capability-tracked (matched on by the typechecker and the load-time capability audit), not a string prefix convention.

Module: dynamic_handlers ​

Dynamic handler law verification over the Term IR (ADR-0076 OQ#2). Dynamic handler law verification over the production Term IR (ADR-0076 OQ#2).

Ports the research PoC in research/arrow-calculus-kernel-poc/src/dynamic_handlers.rs to the production Term kernel. ADR-0076 OQ#2 asks: "Can we verify laws for runtime-chosen impls?" The ADR's tentative "likely no" is corrected here: dynamic law checking IS possible because the arrow calculus graph is always inspectable (a finite combinator tree) and CutElim normalization is decidable for the six-rewrite fragment. There are THREE modes, not two:

  • Mode 1: Static (compile-time verify) -- the impl is fixed at compile time; laws checked once at installation; proof travels. This is the existing [crate::effects::eliminate_and_check] and Term::eliminate_handlers path. This module does NOT re-implement Mode 1.

  • Mode 2: Dynamic, closed set (pick among pre-verified) -- multiple impls are registered, each pre-verified at REGISTRATION time via infer_laws. At runtime a predicate picks one; laws hold regardless of which is picked because all were already proven. No runtime CutElim. See [VerifiedImplStore] and [dynamic_dispatch].

  • Mode 3: Dynamic, open set (runtime verify) -- the impl graph is produced at runtime (not known at compile time). The handler runs CutElim on it AT RUNTIME via [verify_at_runtime]. If it normalizes to satisfy the law -> accept; if not -> runtime rejection. This has a runtime cost (normalization per law) but handles truly dynamic impl generation (plugins, ArrowApply-synthesized graphs, input-driven generation).

Simplification vs the PoC ​

The PoC uses Bundle / BundleLaw / VerificationReport from decoupled_traits.rs. The real compiler does NOT have these. A "verified impl" here is just a [Term] plus its Vec<InferredLaw> (from infer_laws) -- no separate Bundle type needed. The normalizer, law_equal, uses_first, LawPattern, LawCheckResult, and the inference engine are reused from [crate::law_inference] -- the normalizer is NOT duplicated.

Mode 3 vs infer_laws (Violated vs NotApplicable) ​

The key semantic difference between Mode 3 ([verify_at_runtime]) and inference (infer_laws) is how a structural mismatch is reported:

  • In inference mode, a structural mismatch returns [LawCheckResult::NotApplicable] -- the law doesn't apply to this arrow's wiring, so skip it. The question is "which laws does this arrow satisfy?"

  • In verification mode (Mode 3), a structural mismatch returns [LawCheckResult::Violated] -- the graph was claimed to satisfy this law but doesn't even have the right structure. The question is "does this graph satisfy THIS law?" If not, it's a violation, not a skip.

This distinction is what makes Mode 3 rejection possible: a bare arr("not_a_functor") scheme doesn't use first, so it VIOLATES the functor laws (it's not a valid functor implementation), rather than being "not applicable." The runtime check functions ([check_functor_identity_runtime], [check_functor_composition_runtime]) mirror the PoC's separate runtime check functions that return Violated instead of NotApplicable on structural mismatch.

Module: fragment ​

The Fragment trait. The Fragment trait — the common interface every fragment type implements.

A fragment is one tiny concern of a Language: one token kind, one grammar row, one eval scheme, one capability declaration, one option schema, or one AST shape. Fragments carry an id, an optional replaces list (declared override, see ADR-0044 §5), and an optional requires list (composability, see ADR-0044 §7). Each fragment type also has a per-type identity key used by FragmentSet to detect collisions.

requires vs optional ​

Phase 1 models only the hard requires check: every id in requires must be present after merge or the merge fails. The optional dependency concept (silently ignored when absent) is not modeled as a field in Phase 1 — a fragment with a missing optional dependency simply merges successfully because it declares no requires for it. This keeps the data schema minimal; optional may be added in a later phase if needed.

Module: fragment_set ​

FragmentSet<T> merge with declared-override policy. FragmentSet<T> — a mergeable collection of fragments with an explicit conflict policy (ADR-0044 §5).

Overrides are allowed and recorded in an auditable override_chain; collisions are errors. CapabilityDecl uses union (idempotent) semantics instead.

Module: instantiate ​

Free-variable substitution for arrow bodies (ADR-0106). Free-variable substitution for arrow bodies (ADR-0106 closure elimination).

[Ast::instantiate] extracts the subtree rooted at a closure body into a fresh standalone arena — like [Ast::subtree] — while replacing every free variable with a lit node carrying the definition-site value (already serialized to [Value]). The result is a closed term: an arrow minted over it needs no captured environment.

Binder tracking is data-driven over AstShapeDef metadata and the eval schemes, never kind == checks:

  • params/param/pattern child roles introduce binders scoped over the sibling body role (function, arm, for, pi/sigma).
  • A node declaring target + value roles is a binding (assign-like): its target names a binder scoped over the body role child when one is occupied (x = v in body), or over subsequent siblings when the node sits in a statement sequence (x := v in a block/rec/for).
  • A bind-shaped node (payload name + [value, body], no declared roles) scopes name over its second child.
  • A node with a subject role and a string name payload (type-annot-like) scopes name over the subject child.
  • Nodes whose eval scheme is the eval_rec op pre-bind every statement's names over the whole region (mutual recursion); eval_block sequences accumulate statement binders left-to-right.
  • stmt.import-style statements contribute their names/alias payload entries as sibling binders; stmt.export and other declaration statements contribute name.
  • Children in literal_children-declared roles (e.g. entry.key) copy raw — a var there is data, not a reference.
  • Named arena references (payload["body"], the closure payload form {params: [...], body: <idx>}) substitute under the payload's own params/rest names.

Substituted literals use the lit node kind: it declares no eval scheme, so every engine's scheme-less fallback evaluates it as TaggedValue::from(payload) — exactly the inverse of the caller's tagged_to_value serialization.

Module: law_inference ​

Structural law inference over the Term IR (ADR-0076 OQ#5). Structural law inference over the production Term IR (ADR-0076 OQ#5).

The research PoC in arrow-calculus-kernel-poc/src/law_inference.rs implements law inference: given an arrow graph, discover which CutElim-proven structural laws it satisfies WITHOUT the user declaring them. The PoC operates on PolyGraph (a separate IR). This module ports the concept to the production Term kernel.

What this is ​

ADR-0075's "primary mode" (trait inference), scoped to single-arrow laws. Instead of requiring the user to write law map_id: first(id) = id, the system has a library of known law patterns (the "law catalog") and checks each one against a Term:

  1. Structural match -- does the scheme's wiring match the law pattern's expected structure? (e.g. functor laws need a First-shaped graph.)
  2. CutElim verify -- do both sides of the law equation normalize to the same form under CutElim?

If both pass, the system reports: "this arrow satisfies law functor_identity" -- without the user declaring it. This mirrors the Lean mechanization (TraitInference.lean): the UsesFirst structural recognizer triggers the check, and CutElim normalization discharges it.

What this is NOT ​

Inference works ONLY for the CutElim-proven STRUCTURAL fragment -- the functor laws (first identity/fusion). These laws ARE the CutElim rewrites, so the system can discover them from wiring alone. Non-functor laws (roundtrip, semigroup associativity, sortedness) CANNOT be inferred -- they are semantic facts about specific base arrows that require explicit axioms, which cannot be discovered from wiring. This matches EquationalLawInference.lean: structural recognition triggers the check, but an axiom discharges it. This module does not attempt to infer axiom-requiring laws; it documents the boundary explicitly.

Porting notes ​

The PoC's PolyGraph has six rewrites; four are portable to Term:

  • ceIdLeft : Seq(id, G) ==> G
  • ceIdRight : Seq(G, id) ==> G
  • ceFirstFusion: Seq(First(G), First(H)) ==> First(Seq(G, H))
  • ceFirstId : First(id) ==> id

The two Left rewrites (ceLeftFusion, ceLeftId) are NOT portable: the production Term has no coproduct functor (Left) variant. The Choice variant routes on Either but is not a functor, so the coproduct functor laws are not inferable here.

Module: quantified_laws ​

Explicit forall f g. lhs = rhs quantified law syntax over the Term IR (ADR-0076 OQ#4). Explicit forall f g. lhs = rhs quantified law syntax over the production Term IR (ADR-0076 Open Question #4).

The research PoC in arrow-calculus-kernel-poc/src/quantified_laws.rs prototypes higher-order law quantifier syntax: laws that explicitly universally quantify over arrows (forall f g. first(f;g) = first(f);first(g)), distinct from concrete base arrows. The PoC operates on PolyGraph (a separate research IR). This module ports the concept to the production Term kernel.

What this is ​

A [QuantifiedLaw] is forall vars. lhs = rhs where lhs/rhs are [LawExpr]s — graph expressions with quantified variables. Variables are explicitly bound by vars (a [LawVar]), distinct from concrete base arrows ([LawExpr::Const]). The checker instantiates variables under multiple test substitutions (the cartesian product of a representative set of test arrows) and verifies each instantiation via law_equal (CutElim normalization).

What this is NOT (honesty note) ​

Testing under multiple substitutions is a heuristic, not a proof. We cannot test ALL possible arrows (infinite). The real proof is in Lean (TraitInference.lean proves these laws for all arrows via CutElim). This module demonstrates the syntax (explicit forall quantifier) and the checking mechanism (substitution-based testing), not completeness. The heuristic is strong for CutElim-proven structural laws (the rewrites are schema-level — they fire for any inner arrow), but it is NOT a substitute for the Lean proof.

Porting notes ​

The PoC's PolyGraph has a Left variant (coproduct functor) and an Id variant. The production Term has no Left variant (no coproduct functor — Choice routes on Either but is not a functor) and no Id variant (identity is the base arrow arr_native("id", [])). Accordingly:

  • [LawExpr] has no Left variant. The coproduct functor laws (coproduct_functor_identity, coproduct_functor_composition) are NOT ported.
  • [LawExpr::Id] instantiates to TermData::op("id", [], &ArrSource::Native, None).
  • [LawExpr::App] mirrors TermData::app(callee, args: Vec<TermData>) (a callee plus a vector of argument schemes), not the PoC's unary App.

The CutElim normalizer is NOT duplicated: this module reuses law_equal from law_inference.

Module: quote_ast ​

Val → Ast reification — the AST-surface half of quote (phase-2 spec WS-G; metaprogram term materialization). Val → Ast reification — the AST-surface half of quote (phase-2 spec WS-G; ADR-0154 §6 runtime-minted cells are legal values).

[handl_value::nbe::quote] reifies the semantic domain to boundary data (__former__/__neutral__/__arrow__/__type__ tagged values). [reify_ast] goes one step further: it materializes a Val into an [Ast] arena whose nodes are the same surface shapes the engines consume — lit/var/call — so a metaprogram's product can re-enter the pipeline (inspect the arena, hand it to eval/ typecheck, embed it as an arrow body_def {"__ast__": <arena>}).

The boundary — what reifies to what ​

A lit node's payload is a boundary value: every exec engine evaluates it as TaggedValue::from(payload) (the [crate::instantiate] convention — lit declares no eval scheme). Reification therefore targets boundary-faithful payloads, not new node kinds:

  • Val::Const(tv) → lit carrying tagged_to_value(tv) verbatim. Evaluates back to the identical TaggedValue on every engine.
  • Val::Nominal(sym) → lit carrying the {"__sym__": …} encoding. Decodes to TaggedValue::Sym; lift recovers Val::Nominal.
  • Val::Universe(i) → lit carrying {"__type__": i}.
  • Val::Former{head, args} → lit carrying {"__former__": {"sym": …, "args": […]}} — quote's own spelling, which lift reads back as Val::Former and nominal_head/instance_of accept directly. A call-shaped reification is deliberately not emitted: a former head is a nominal value, and applying a Const(Sym) callee is NotAnArrow in the domain — the literal is the faithful form.
  • Val::Arrow(a) → lit carrying the [TaggedValue::Arrow] wire encoding ({"__arrow__": true, "params": …, "body_def": …, "binds": …}). Unlike quote's display-only {"__arrow__": {"params", "binds"}} — which drops body_def — this reifies the whole self-contained arrow (params + body + residual binds, binds quoted recursively), so the literal decodes back to a runnable TaggedValue::Arrow.
  • Val::Unfold{name, spine} → var/call over name: an unfold is a named top-level definition, so re-resolution by name is faithful.
  • Val::Rigid{lvl, spine} → var/call when names[lvl] supplies the binder's declared name; otherwise the honest {"__neutral__": …} literal. A var re-entered under a binder of that name resolves again — how a metaprogram closes an open term.
  • Val::Flex{meta, spine} → lit {"__neutral__": {"head": "meta", "id": …}}. Unsolved metas never re-enter as vars — a meta is a hole; its reification is honest stuck data, not a guessable name.

What stays engine-internal ​

Flex/Unfold never serialize (ADR-0106 domain doc): a meta is a MetaStore index, an Unfold's lazy OnceCell is a process-local thunk — neither has meaning outside the checking context that allocated it. Reification emits their stable encodings (__meta__ ids, the unfold head's name + spine) as data, but a metaprogram that feeds a __neutral__/__meta__ literal back into checking gets a fresh stuck neutral — store identity does not round-trip. That is the documented bound: closed values round-trip; open terms reify honestly but re-enter fresh.

handl_language::tag_value ​

Function

Mint a tagged value (ADR-0055).

Returns {"__tag__": tag_name, ...payload}. The payload object's fields become the tagged value's payload. If payload is Null, an empty payload is used. If payload is a non-object, non-null value (e.g. a number or string), it is wrapped in {value: payload} so that tag.tag("ok", 42) produces {"__tag__": "ok", "value": 42} (ADR-0077). Module: verdict ​

Proof verdicts for the partial-evaluator typechecker (ADR-0068). Proof verdicts for the partial-evaluator typechecker (ADR-0068).

The outcome of checking a type-position proposition. The typechecker is a partial evaluator with a termination guard: to verify x: T = e, it normalizes T(e).

  • [Verdict::Proven]: normalization succeeded and the equality holds — the annotation is accepted statically.
  • [Verdict::Disproved]: normalization succeeded and the equality is false — the annotation is rejected.
  • [Verdict::Blocked]: normalization could not finish (a symbolic value it cannot reduce, an effect, a termination-guard budget exhausted). Per ADR-0068 the caller should accept the annotation with a runtime backstop assert T(e) rather than reject it.

This is the "graduated guarantees" switch: static proof where the checker can normalize, runtime fallback where it cannot.
