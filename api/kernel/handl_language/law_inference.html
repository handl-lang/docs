handl_language::law_inference::LawPattern ​

Struct

A known law pattern the system can check against an arrow. This is the "law catalog" -- a library of laws the system knows about. Given a Term, the inference engine checks each pattern.

This is the single-arrow analogue of ADR-0075's CatalogEntry. Where CatalogEntry bundles multiple laws under a named trait, a LawPattern is ONE law that attaches to ONE arrow -- no bundle needed (ADR-0076: "A single-arrow law needs no bundle").

Constant: usize

Fuel budget for normalization. Generous for these small graphs; the bound exists only as a termination safety net (the CutElim rewrite relation is not proven strongly normalizing for all graphs, but the four rewrites here are size-non-increasing and terminate quickly in practice).

handl_language::law_inference::check_functor_composition ​

Function

Check the functor composition law: first(f >>> g) = first(f) >>> first(g) (ceFirstFusion).

If the arrow uses First, construct both sides with concrete base arrows f, g and verify via law_equal. The law is a CutElim rewrite, so it holds for any First-shaped scheme. The inference: "G uses First, therefore it satisfies the functor composition law (by ceFirstFusion)."

rust
fn check_functor_composition(arrow: &crate::term::Term) -> LawCheckResult

Function

Check the functor identity law: first(id) = id (ceFirstId).

If the arrow uses First, construct lhs = First(id), rhs = id, and verify via law_equal. The law is a CutElim rewrite, so it holds for any First-shaped scheme. The inference: "G uses First, therefore it satisfies the functor identity law (by ceFirstId)."

handl_language::law_inference::infer_laws ​

Function

Infer which laws an arrow satisfies, without declaration. This is the "primary mode" from ADR-0075, scoped to single-arrow laws.

The engine checks each law pattern in the catalog against the arrow:

  • NotApplicable -> skipped (the law does not apply to this wiring).
  • Satisfied -> reported (the law holds, CutElim-proven).
  • Violated -> reported (the law applies but does not hold).
rust
fn infer_laws(arrow: &crate::term::Term) -> Vec<InferredLaw>

handl_language::law_inference::law_equal ​

Function

Two schemes are law_equal iff they normalize to the same form under CutElim. Term derives PartialEq, so structural equality of the normalized forms is the comparison. Arr names are compared structurally (the name is opaque data -- two Arrs are equal only if their names, args, source, and lit match). This is what lets the composition law First(Seq(f, g)) === Seq(First(f), First(g)) verify: both sides normalize to First(Seq(f, g)) with matching f, g.

rust
fn law_equal(a: &crate::term::Term, b: &crate::term::Term) -> bool

handl_language::law_inference::normalize ​

Function

Normalize a scheme by repeatedly applying the four CutElim rewrites bottom-up until a fixpoint is reached or fuel passes are exhausted.

If fuel is exhausted before a fixpoint, the result is the partially-normalized scheme (law_equal may then report false negatives).

handl_language::law_inference::rewrite_pass_td ​

Function

One bottom-up pass: normalize children first, then apply root rewrites repeatedly until no root rule fires. Returns the pass result and whether anything changed.

Recurses into every child scheme of every variant: Seq (fst, snd), First (inner), Choice (l, r), Loop (body), App (callee + args), Arr (args), Handle (body, impl_). Then applies root rewrites to fixpoint so a cascade like Seq(First(id), First(id)) -> First(Seq(id, id)) -> First(id) -> id completes within a single pass.

rust
fn rewrite_pass_td(td: &hnl_engine::TermData) -> (hnl_engine::TermData, bool)

handl_language::law_inference::rewrite_root_td ​

Function

Try to apply ONE CutElim rewrite at the root of scheme (TermData form). Returns the rewritten scheme if a rule fired, else None.

The four portable rewrites:

  • ce_id_left : Seq(id, G) ==> G
  • ce_id_right : Seq(G, id) ==> G
  • ce_first_fusion: Seq(First(G), First(H)) ==> First(Seq(G, H))
  • ce_first_id : First(id) ==> id
rust
fn rewrite_root_td(td: &hnl_engine::TermData) -> Option<hnl_engine::TermData>
