handl_language::dynamic_handlers::VerifiedImpl ​

Struct

A pre-verified impl: a named [Term] plus the laws it was verified to satisfy at registration time. The verification result travels with the impl -- no re-verification needed at dispatch.

This is the Mode 2 "verified impl." Registration runs infer_laws once and stores the satisfied law names; dispatch just looks up the pre-computed result.

  • scheme: crate::term::Term - The impl graph (the arrow-calculus description).
  • verified_laws: Vec<String> - Names of the laws this impl was verified to satisfy at registration.

handl_language::dynamic_handlers::check_functor_composition_runtime ​

Function

Check the functor composition law: first(f >>> g) = first(f) >>> first(g) (ceFirstFusion), in verification mode (Mode 3).

If the scheme uses First, the law holds by CutElim (ceFirstFusion is a universal rewrite). If the scheme does NOT use First -> [LawCheckResult::Violated].

This mirrors the PoC's check_functor_composition_runtime and differs from [crate::law_inference]'s check_functor_composition only in the structural-mismatch case: here it is Violated, there it is NotApplicable.

fn check_functor_composition_runtime(scheme: &crate::term::Term) -> crate::law_inference::LawCheckResult

handl_language::dynamic_handlers::check_functor_identity_runtime ​

Function

Check the functor identity law: first(id) = id (ceFirstId), in verification mode (Mode 3).

If the scheme uses First, the law holds by CutElim (ceFirstId is a universal rewrite). If the scheme does NOT use First, it is not a valid functor implementation -> [LawCheckResult::Violated] (the scheme was claimed to satisfy this law but doesn't have the structure).

This mirrors the PoC's check_functor_identity_runtime and differs from [crate::law_inference]'s check_functor_identity only in the structural-mismatch case: here it is Violated, there it is NotApplicable.

handl_language::dynamic_handlers::dynamic_dispatch ​

Function

Dynamic dispatch: pick among pre-verified impls at runtime. Laws hold regardless of which is picked -- all were verified at registration. No runtime CutElim needed.

The predicate returns an index; idx % impls.len() selects the impl. This simulates a runtime decision (e.g. "if list_size > 1000, use the parallel impl; else use the list impl").

fn dynamic_dispatch<'a, impl Fn() -> usize>(store: &'a VerifiedImplStore, capability: &str, predicate: impl Trait) -> Result<&'a VerifiedImpl, DispatchError>

handl_language::dynamic_handlers::verify_at_runtime ​

Function

Verify a runtime-generated scheme against a set of law patterns. Runs CutElim (via the law patterns' check functions, which call law_equal) on the scheme. This is the runtime cost of Mode 3 -- but it's possible because the scheme is inspectable.

For each law pattern:

  • [LawCheckResult::Satisfied] -> law holds, add to checked list.
  • [LawCheckResult::Violated] -> law fails, return [RuntimeVerification::Rejected] immediately.
  • [LawCheckResult::NotApplicable] -> skip (reserved for future axiom-requiring laws that CutElim cannot verify).

If all applicable laws are satisfied, returns [RuntimeVerification::Accepted].

rust
fn verify_at_runtime(scheme: &crate::term::Term, law_patterns: &[crate::law_inference::LawPattern]) -> RuntimeVerification
