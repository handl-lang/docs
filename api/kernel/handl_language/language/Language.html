handl_language::language::Language::child_role_index ​

Function

Resolve a named child role (ADR-0081) to its positional index for a node kind, using this language's AST shapes.

This is the runtime-resolution entry point engines call to replace kind == shape checks: instead of testing node.kind == "assign" and assuming child 0 is the target, an engine resolves lang.child_role_index(node.kind, "target") and projects that position.

Returns Ok(Some(index)) when the role is declared, Ok(None) when the node kind has no shape or no such role (opaque/positional fallback), and Err when a shape exists but the resolved index is out of bounds for the node's children (a load-time data inconsistency).

The returned index is the shape's full-form position — every declared role occupies a slot, including optional ones. For shapes with optional roles the correct position depends on the node's actual arity; use child_role_index_for to resolve a concrete node (e.g. match's block is at index 1 without a motive and 2 with one).

rust
fn child_role_index(self: &Self, node_kind: &str, role: &str) -> Result<Option<usize>, LangError>

handl_language::language::Language::child_role_index_for ​

Function

Resolve a named child role (ADR-0081) to its positional index for a concrete node, accounting for optional child roles.

The node's arity is its payload["children"] length (0 when absent). Occupied optional slots are the first arity - required optional roles in declaration order — see [AstShapeDef::role_index_at].

Returns Ok(Some(index)) when the role is declared and its slot is occupied at this arity, Ok(None) when the kind has no shape, the role is undeclared, or the role's optional slot is absent (e.g. body on a 2-child assign, motive on a 2-child match). Callers keep their positional fallback on None, exactly like child_role_index.

fn child_role_index_for(self: &Self, node: &AstNode, role: &str) -> Result<Option<usize>, LangError>

handl_language::language::Language::is_array_pattern ​

Function

Whether a params node is an array-destructuring pattern.

A positional parameter list ((x, y) ~> body) has no pattern_role on its params node, while an array pattern ([x, y] ~> body) uses a node whose AstShapeDef declares pattern_role: "sequence" and a variadic child role (e.g. elements for array). This check is data-driven over AstShapeDef metadata rather than a kind == "array" test.

rust
fn is_array_pattern(self: &Self, params_node: &AstNode) -> bool

handl_language::language::Language::literal_child ​

Function

Whether a child node of child_kind occupying role of node_kind is declared literal — its payload is the datum itself rather than an expression to evaluate (ADR-0081 extension).

Engines use this to replace key_node.kind == "var" || kind == "string"-style literal-vs-computed heuristics: e.g. an object entry shape declares literal_children: { key: [var, string] } so { a: 1, "b": 2 } keys are read from the payload while [expr]: / paren keys are evaluated.

Returns Some(bool) when the shape declares a literal-kinds list for role, None when it declares none — callers keep their legacy fallback heuristic for role-less shapes.

rust
fn literal_child(self: &Self, node_kind: &str, role: &str, child_kind: &str) -> Option<bool>

handl_language::language::Language::merge_ast_fragment ​

Function

Merge a single [AstShapeDef] into this language, lowering any desugar rule it carries into a [TransformDef] in the transforms set (ADR-0094 §6).

This is the merge path every ast-fragment loader should use: it merges frag into ast and, when the fragment is actually kept by the merge (AST shapes are union fragments — a duplicate declaration is dropped, and so is its desugar rule) and declares desugar: Some(..), synthesizes a TransformDef with id = "transform.desugar.<node_kind>", pass = "desugar", and priority = 0.

The merge is atomic: on failure self is left unchanged.

Errors ​

Returns [LangError] if either the shape merge or the synthesized transform merge fails.

rust
fn merge_ast_fragment(self: & mut Self, frag: AstShapeDef) -> Result<(), LangError>

handl_language::language::Language::param_name ​

Function

Extract the parameter name from a param node, unwrapping type annotations (ADR-0081 data-driven: uses the subject child role declared by type-annot's AstShapeDef, never a kind == check).

A bare var node has a string payload (the name) and is returned directly. A type-annot node (e.g. x: Int) has a subject role pointing at the inner var; this resolves that child and reads its string payload. Returns Err if the name cannot be extracted.

rust
fn param_name(self: &Self, ast: &Ast, param_node: &AstNode) -> Result<String, LangError>
