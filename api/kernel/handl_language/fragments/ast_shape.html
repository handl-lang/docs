Enum

A specification for a single child of a desugar replacement node (ADR-0053 §7 — data-driven desugar pass).

A child is either [AstDesugarChild::Keep] (reuse the original node's child at the given index, remapped into the output arena), [AstDesugarChild::KeepPath] (navigate through descendant children by index path, e.g. [0, 0] takes child 0's child 0), or [AstDesugarChild::Create] (allocate a fresh node, optionally with its own children — the rewrite is recursive).

handl_language::fragments::ast_shape::AstDesugarCondition ​

Struct

A condition that guards whether a desugar rule applies (ADR-0058).

When present on an [AstDesugarRule], the pass only rewrites nodes whose child at child_index has the AST node kind child_kind. Nodes that don't match pass through unchanged. This lets a single shape carry a desugar rule that only fires for a specific child variant (e.g. only entry nodes whose key child is an array).

Fields:

  • child_index: usize - The index into the original node's children array to test.
  • child_kind: String - The AST node kind the child must have for the rule to fire.

handl_language::fragments::ast_shape::AstShapeDef ​

Struct

A definition of an AST node kind and its payload shape.

Identity key: node_kind (see ADR-0044 §5). The payload_schema is a serde_json::Value describing the payload shape (e.g. a JSON Schema fragment), kept as opaque data so the crate stays engine-agnostic.

children, when present, declares the named child roles (ADR-0081). Absent = opaque node whose children are referenced positionally (backward compatible). When present, engines resolve child positions by role instead of hardcoding kind == shape checks.

AST shape declarations are structural facts ("this node kind exists with this payload shape"), not behavioral definitions: two emitters declaring the shape for binary.add are agreeing it exists, not conflicting. Merge therefore uses union (idempotent) semantics — merging a shape whose node_kind already exists is a no-op (the first declaration is kept), not an error.

handl_language::fragments::ast_shape::ChildRoleSpec ​

Struct

A named role for a single child position of an AST node (ADR-0081).

Children are referenced by role (e.g. target, statements, params) rather than by positional index. Engines look up the positional index from the [AstShapeDef] at runtime instead of hardcoding kind == shape checks.

variadic: true means the role covers all children from its start index to the end (e.g. statements in a block). A non-variadic role maps to exactly one child position.

optional: true means the role may be absent from a node's children — e.g. match's optional motive child ([scrutinee, (motive,) block]) or assign's optional trailing body ([target, value, (body)]). Optional roles make child positions arity-dependent: the index of a role after an optional slot depends on the node's actual child count. Use [AstShapeDef::role_index_at] (or Language::child_role_index_for) to resolve a concrete node; [AstShapeDef::role_index] resolves the full-form index (all optional roles present).

YAML accepts either the map form ({role: motive, optional: true}) or a bare string shorthand (- scrutinee ≡ {role: scrutinee}).

  • variadic: bool - Whether the role spans this start index to the end of the children
  • optional: bool - Whether the role may be absent from a node's children. Absent/false
