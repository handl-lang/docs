handl_language::fragments::grammar::KeywordClause ​

Struct

An optional keyword-delimited clause that may appear between fixed child after_child and the following child or delimited block (ADR-0053).

When the parser has just parsed fixed child after_child and the next token has kind open, the clause fires: open is consumed, a clause expression is parsed at binding_power, close is required and consumed, and the clause expression is spliced into the node's children immediately after after_child. When the next token is not open, the clause is skipped entirely. Example: match's return ... with motive clause is KeywordClause { after_child: 0, open: "token.keyword.return", close: "token.keyword.with", binding_power: 0 }.

The engine resolves the string generically from the child's payload: a bare string payload (e.g. a var node), an existing name property, or the callee-role child of a call-shaped node. handl_language::fragments::grammar::PayloadTokenSpec ​

Struct

A specification for a token to consume and optionally extract into the node's payload before parsing children (ADR-0053 §7b — payload extraction).

Some prefix forms (e.g. let x = 42 in x) need to consume non-expression tokens (the binding name x, the = sign) and store the name's text in the node's payload so that type rules can access it via payload_field. Each [PayloadTokenSpec] specifies a token kind to consume and an optional field name. When field is Some, the token's text is stored in the payload under that key; when None, the token is consumed but not stored (e.g. the = sign).

handl_language::fragments::grammar::TokenStep ​

Struct

A single trailing token step consumed after a node's children ([AstShapeRef::trailing_tokens], ADR-0053).

The step matches when the next token's kind is in kinds; the token is consumed and, when field is set, its text is stored in the node's payload under that key. When optional is true and the next token does not match, the step is skipped without consuming. This is the tail-form counterpart of [PayloadTokenSpec] (which consumes before children) and generalizes multi-keyword suffixes — e.g. from &lt;path> import * as &lt;alias> is kinds: [import], kinds: [star], kinds: [as], kinds: [identifier, string], field: alias.
