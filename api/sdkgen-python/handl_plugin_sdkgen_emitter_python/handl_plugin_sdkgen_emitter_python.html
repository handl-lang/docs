handl_plugin_sdkgen_emitter_python::emit_struct_class ​

Function

Emit a ctypes.Structure that reproduces the declared offsets exactly. _pack_ = 1 makes ctypes lay fields out contiguously, so a gap before a field becomes an explicit c_ubyte * n pad and any layout — packed or naturally aligned — is reproduced without guessing. Every offset is asserted at import; total_size adds the trailing pad and a size assertion when the caller knows the C size.

rust
fn emit_struct_class(out: & mut String, name: &str, fields: &[FieldSpec], records: &std::collections::HashSet<&str>, total_size: Option<usize>)

handl_plugin_sdkgen_emitter_python::register ​

Function

Register the python sdkgen target on reg (ADR-0128 §0.1/§0.2): the python emitter plus the target record (backend: "c", emitter: "python"). The backend id resolves by name through the registry — python/ depends on c/'s module at resolution time, never at the crate level. .yaml/.yml/.json inputs take the spec-driven path ([generate_python]) and bypass the backend entirely.

rust
fn register(reg: & mut handl_plugin_sdkgen::SdkgenRegistry)

Module: spec ​

Spec-driven Python binding generation — the non-backend input path of the python sdkgen target (ADR-0128 §0.2).

A .yaml/.yml/.json spec describes an embedded-CPython shim: the generated .hnl module calls Py_Initialize/PyRun_SimpleString over ffi.call and returns each function's output through an env-var side channel. This is the target's spec path — it bypasses the C-backend pipeline entirely.
