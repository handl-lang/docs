handl_plugin_ffi::FfiOpFunction ​

Struct

A generic FFI dispatcher function implementing [Function].

Each call resolves the library (cached dlopen), resolves the symbol (cached dlsym), marshals the JSON arguments to C types per arg_descriptors, calls the C symbol, unmarshals the return per return_descriptor, and optionally checks the error clause.

When error_on_lt_zero is true and the integer return value is negative, the dispatcher reads errno synchronously and returns Err(EvalError::Other(format!("errno: {errno}"))) instead of the raw return value.

Handle lifecycle (ADR-0083 §2.2) ​

When return_descriptor is "handle", the raw C return pointer is wrapped in the JSON debug form of a TaggedValue::Resource ({"__resource__": {"ptr": N}}). The optional finalizer field is the mechanism for attaching a cleanup function (e.g. libc::close) to the resource so it is released automatically when the handl value goes out of scope (RAII). Because the current dispatcher returns serde_json::Value (which cannot carry a function pointer), the finalizer is not yet wired into the return path — it defaults to None. Once the dispatcher is upgraded to return handl_value::TaggedValue directly, the finalizer will be attached to the Resource on return.

Fields:

  • library: String - Library name passed to dlopen (e.g. "libc.so.6").
  • symbol: String - Symbol name passed to dlsym (e.g. "getpid").
  • arg_descriptors: Vec<String> - Per-argument marshalling descriptors (e.g. ["i32", "cstr"]).
  • return_descriptor: String - Return-value descriptor (e.g. "i32", "void", "handle").
  • error_on_lt_zero: bool - When true, a negative integer return triggers an errno extraction.
  • finalizer: Option<fn(...)> - Optional finalizer for "handle" return values (ADR-0083 §2.2).

  • fn with_finalizer(self: Self, finalizer: fn(...)) -> Self - Attach a finalizer to this FFI op function for "handle" return

handl_plugin_ffi::FfiRead ​

Struct

ffi.read(ptr, descriptor) -> Value

Generic pointer dereference: reads memory at ptr (a number address or {"__resource__": {"ptr": N}} handle) and decodes it per descriptor — the same field grammar as struct descriptors (i8..u64/isize/usize scalars, ptr, bytes:N, arr:N:T, rec:{...}, cstr). This is the primitive that lets handl chase out-pointer results (T **res), linked lists (ai_next), and pointed-to payloads (ai_addr) — ffi.call marshals arguments, but only ffi.read reaches memory C did not hand back by value.

handl_plugin_ffi::call_c ​

Function

Call a C function pointer with the given marshalled arguments.

Resolves (compiling on first use, then cached) a cranelift-generated call stub for the flat signature (ret_kind, classes(args)) and invokes it. There is no arity ceiling — the stub loads each argument from the int/float slot arrays and issues an indirect call with the exact C ABI signature. See [crate::cranelift_shim] for the trampoline contract.

rust
fn call_c(sym: *mut std::ffi::c_void, ret: crate::marshal::CRetKind, args: &[crate::marshal::CArg]) -> Result<crate::marshal::CRet, handl_platform::EvalError>

Module: cranelift_shim ​

Cranelift-generated FFI call stubs (ADR-0083 §4, Phase 8.1).

This module replaces the former arity-0..=6 macro-generated transmute dispatch with JIT-compiled call trampolines. For each distinct flat C signature (a return kind plus one [ArgClass] per marshalled C argument) a native stub is generated via cranelift and cached for the process lifetime. Because the argument list is emitted as a loop over the signature, there is no arity ceiling.

Trampoline contract ​

Every generated stub has the uniform C signature

c
void shim(void *sym, const i64 *int_args, const f64 *float_args, i64 *out);
  • sym is the raw dlsym pointer of the target C function.
  • int_args holds all integer/pointer arguments (in argument order), one i64 slot each.
  • float_args holds all f64 arguments (in argument order).
  • out receives the result: the integer return value, the f64::to_bits of a float return, or 0 for void returns.

Inside the stub the known-static signature selects which array and offset each argument loads from, builds a cranelift [Signature] with the exact C ABI parameter/return types, and performs an indirect call through sym. The caller (FfiOpFunction) therefore sees one uniform calling convention regardless of the target signature.

Integer/pointer arguments are passed as i64 (sound on x86-64 SysV and AArch64, matching the previous dispatcher — a 32-bit int argument is sign/zero-extended in its calling register). A 32-bit integer return is sign-extended from i32 to i64 inside the stub, matching the CRetKind::Int32 semantics documented in [crate::marshal].

Module: error ​

errno extraction for the FFI error clause.

When an [crate::FfiOpFunction] is configured with error_on_lt_zero, a negative integer return triggers an errno read. On Linux this calls __errno_location() to obtain the thread-local errno pointer and reads its value synchronously, before any other libc operation can clobber it.

handl_plugin_ffi::lock_cache ​

Function

Lock a cache mutex, recovering the guard when a previous holder panicked. The caches only ever hold fully-inserted entries — a panic mid-operation can at worst drop an in-flight insert, never corrupt the map — so the poisoned state is safe to reuse. Without this, one panicking worker would poison the process-wide cache and fail every subsequent FFI call on all threads.

rust
fn lock_cache<T>(mutex: &std::sync::Mutex<T>) -> std::sync::MutexGuard<T>

Module: marshal ​

Marshalling between serde_json::Value and C ABI types.

The dispatcher marshals each handl argument to a C type per a descriptor string, calls the C symbol, and then unmarshals the return value back to a JSON value.

Marshalling descriptors ​

DescriptorC typeJSON source
"i32"int32_t (value)number (range-checked)
"i64"int64_t (value)number
"u8"-"u64"uint8_t..uint64_tnumber (range-checked)
"f64"double (value)number
"cstr"const char *string (NUL-checked)
"strv"char *const *list of strings/Bytes
"ptr"void *number (address)
"handle"void *{"__resource__": {"ptr": N}} (opaque handle, ADR-0083 §2.2)
"void"void (return)— (returns null)
"in_buf"const void * + size_tBytes
"cbytes"const void * + size_tBytes
"in_ptr"const void *Bytes
"out_buf:N"void * + size_t— (allocates N)
"out_ptr:N"void *— (allocates N)
"io_buf:N"void * + size_t *— (allocates N)
"io_scalar:T"T * (value-result)number (seed value)
"in_struct:{…}"const T * (built)record
"io_struct:{…}"T * (filled)— (allocates struct)
"out_struct:{…}"T * (filled)— (= io_struct)

Struct field specs are name:kind[@offset[:slotwidth]] — explicit offsets/sizes carry the backend's real target layout (libclang); without them fields lay out sequentially. Kinds: scalars (i8..u64, isize, usize), bytes (Bytes → ptr), buf:N (alloc → ptr), iov/iovbuf:K:M (iovec arrays), ptr (raw pointer slot), arr:N:T (inline array), rec:{...} (inline nested struct).

in_buf / cbytes / in_ptr / out_buf:N / out_ptr:N / io_buf:N are the buffer descriptors introduced with the Bytes type (ADR-0078 Phase 2 / ADR-0083 §2.1). in_buf and cbytes each expand to two C arguments — (ptr, len) — and consume one handl Bytes argument. out_buf:N allocates N bytes, passes (ptr, N) as two C arguments, consumes no handl argument, and produces an out-slot trimmed to the ret byte count. out_ptr:N allocates N bytes and passes the bare pointer as one C argument (e.g. int sv[2] in socketpair) — the slot is the full N bytes. in_ptr is the input counterpart: the Bytes pointer alone as one C argument, for signatures whose length travels separately or with a non-size_t width (e.g. ICU's UChar * + int32_t pairs). io_buf:N allocates an N-byte buffer plus a size_t cell initialised to N and passes (ptr, &len) — the POSIX value-result pattern (sockaddr * + socklen_t * in accept, getsockname, recvfrom); the slot is trimmed to the length the callee wrote back.

strv consumes one handl argument — a list of strings (a Bytes element is also accepted, for byte-exact argv entries) — and expands to one C argument: a char *const *, a NULL-terminated array of pointers to NUL-terminated C strings (the argv/envp shape of posix_spawnp, execv*). An empty list yields the bare {NULL} array.

The return becomes { ret, buf, outs }: buf is the first out-slot (kept for the common single-out case) and outs lists every out-slot in descriptor order.

Bytes values are carried as serde_json::Value using the {"__bytes__": [n, ...]} encoding (matching TaggedValue::Bytes in handl-value). For input, a plain JSON array of numbers is also accepted as a convenience.
