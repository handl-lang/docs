handl_plugin_ffi::marshal::CArg ​

Enum

A marshalled C argument ready to be passed across the FFI boundary.

All integer and pointer descriptors (i32, i64, ptr, cstr) are widened to i64. This is sound on x86-64 SysV and AArch64 where a 32-bit integer argument is sign/zero-extended in its calling register, so passing the full 64-bit slot is equivalent. Floating-point values stay f64 because they travel in separate (XMM) registers and must not be bit-cast to an integer slot.

Variants:

  • Int(i64) - An integer or pointer argument, widened to 64 bits.
  • Float(f64) - A double-precision floating-point argument.

handl_plugin_ffi::marshal::CRetKind ​

Enum

The kind of return value expected from the C function.

This drives which function-pointer signature the dispatcher transmutes the raw symbol to. Crucially, Int32 and Int64 produce different return types in the transmuted signature: on x86-64 a function returning int only writes the lower 32 bits of rax (the upper 32 are zeroed, not sign-extended), so reading the full 64-bit rax as i64 would turn a -1 int return into 4_294_967_295. Reading it as i32 and then sign-extending to i64 gives the correct -1.

Variants:

  • Int32 - 32-bit integer return (read as i32, sign-extended to i64).
  • Int64 - 64-bit integer or pointer return (read as i64).
  • Float - Double-precision floating-point return.
  • Void - No return value.

handl_plugin_ffi::marshal::marshal_strv ​

Function

Marshal a strv argument into res, returning the array pointer.

Builds one CString per list element (kept in res.keep_alive), then a char *const * array of their pointers with a trailing NULL (kept in res.strv_keep_alive) — the NULL-terminated argv/envp shape. An empty list marshals to the bare {NULL} array, a valid char *[]{NULL}. Elements are strings; a Bytes value ({__bytes__: [...]} or a plain number array) is also accepted for byte-exact, non-UTF-8 argv entries. Embedded NULs are an error, same as cstr.

fn marshal_strv(value: &serde_json::Value, res: & mut MarshalResult) -> Result<i64, handl_platform::EvalError>
