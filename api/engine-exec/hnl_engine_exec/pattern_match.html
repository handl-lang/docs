hnl_engine_exec::pattern_match::PatternMatchCtx ​

Trait

Engine-specific context for pattern matching (ADR-0061).

Abstracts the two operations pattern matching needs from the engine: binding a name in the scope stack and evaluating a pattern AST node as a runtime value. Each engine implements this trait and passes &mut self to [try_pattern].

The scrutinee and bound values are [TaggedValue]s, not serialized serde_json::Values: serializing a scrutinee that contains arrows deep-copies every body_def and transitively every binds entry — exponential on the sibling-arrow graphs eval_rec produces.

Methods:

  • define_binding: Bind name to value in the current (innermost) scope.
  • eval_pattern_node: Evaluate a pattern AST node as a runtime value.
  • global_value: Resolve an ambient global binding by name (the engine's globals
  • scope_value: Resolve a name through the visible scope stack (innermost-out) —

hnl_engine_exec::pattern_match::try_ctor_object_pattern ​

Function

Constructor-object pattern (Ctor(binder, …) against a {"__ctor__": sym, <fields…>, "type": …} scrutinee — ADR-0152 §2).

Called from [try_tag_pattern] when the scrutinee has no matching __tag__: an object whose __ctor__ is a [Sym] whose display name equals the callee name matches (the seeded ctor sym's name is the constructor's source name — Sym::seeded takes the seed's last .-segment, so data.Vec.VCons mints VCons). Any other __ctor__ value, a name mismatch, or a missing __ctor__ is a miss.

Binders bind positionally to the constructor's declared argument fields. Declared order comes from the constructor arrow itself — the callee name resolved through [PatternMatchCtx::scope_value] yields the VCons = (x, xs) ~> {…} arrow whose params are the declaration order (a TaggedValue::Obj is unordered). When the callee does not resolve to an arrow the binders fall back to the tag-pattern convention — alphabetical field order, excluding the nominal __ctor__/type members.

hnl_engine_exec::pattern_match::try_object_pattern ​

Function

Object destructuring: { x: a, y: b, ...rest }.

Each entry's key is a field name (from a var or evaluated to a string); the entry's value is a sub-pattern matched against the corresponding field. A ...rest element captures the unmatched keys as an object.

The scrutinee's object test is the tagged-object view ([TaggedValue::object_view], ADR-0083 §2.1): an Obj destructures directly, and the opaque variants (Tensor/Bytes/Sym/ Resource) destructure through their canonical {"__x__": …} wire record — a { "__tensor__": inner } pattern matches a kernel Tensor exactly as it matches a .hnl-authored wire record. The binders see the record fields (shape/data/dtype), never the opaque variant. Variants with their own .hnl projections (Pair/Either/Arrow) and scalars do not match.

hnl_engine_exec::pattern_match::try_tag_pattern ​

Function

Tag pattern: tag_name(binder1, binder2, ...) (ADR-0077).

The pattern is a call node with a var callee (the tag name) and var arg nodes (the binders). Matches if the scrutinee is a tagged value (__tag__ key) whose tag name equals the callee name. Binds each binder to the corresponding payload field:

  • Single binder + single-field payload ({value: v}): bind to value.
  • Multiple binders + multi-field payload: bind each to the field at the corresponding position (alphabetical key order, excluding __tag__).
  • Wildcard binder (_): matches without binding.
