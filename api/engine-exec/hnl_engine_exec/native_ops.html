hnl_engine_exec::native_ops::ResumeTableScope ​

Struct

RAII guard marking one engine evaluation on this thread — the finalization pass for the multi-shot resume tables.

Suspension bookkeeping is retained after its handle returns (that is what makes an escaped resume callable), so nothing reclaims it while the eval runs. This guard closes the leak at the eval boundary: the outermost evaluation (success or error) clears the shared driver table and runs the engine-supplied cleanup. Nested evaluations — a host callback re-entering an engine, a .hnl module function evaluating another — only bump the depth, so an in-flight journal is never collected out from under an outer run.

hnl_engine_exec::native_ops::arrow_free ​

Function

Convergence comparison for eval_rec bindings.

Closures (TaggedValue::Arrow) are compared by params and body_def only, NOT by their residual binds. In a rec fixpoint, each pass re-evaluates a closure binding and mints a new arrow whose binds include the other rec-region names (which stay residual — they are excluded from substitution). The binds map naturally differs each pass even though the closure's code is identical, so a full structural eq would never converge. Comparing only params + body_def lets the fixpoint converge. Non-closure values use the standard structural eq.

Whether v contains no Arrow and no Resource — i.e. it is safe to substitute into a body_def as a literal. Arrows carry their own serialized data and embed transitively (exponential on diamond graphs); Resources carry unserializable finalizers. Both stay in binds.

rust
fn arrow_free(v: &handl_value::TaggedValue) -> bool

hnl_engine_exec::native_ops::binding_target_name ​

Function

Resolve the bound name of a binding's target child: a bare var-like node carries the name in its payload; a wrapper whose shape declares a subject role (e.g. a type annotation — the subject/annot role convention, ADR-0081) delegates to that child. This makes f: T = v-shaped statements bind f without any kind check.

Mirrors the checker's binding_target_name scope-pass resolution so the exec artifact binds the same names the checker scoped:

  • field first — a field-access target (type.Score := Nat, or obj.field := v) binds the field name, resolved before the generic role loop: descending its target role would "bind" the namespace (type) instead.
  • callee — a call target (type.Id(A) := A, f(x) := body) binds the callee head's name.
  • source precedes target in the role loop — a dim_arrow (X: (A,B) ~[N]~> R) keeps the declared name under source while target is the return-type expression.
  • params precedes body — a function target (narrow : T ~> U := f parses as assign(function(type-annot(narrow, T), U), f)) keeps the annotated name under params, the result type under body.
  • expr last — runtime-assert wrappers (the ADR-0068 pass rewrites type-annot nodes in-place when blocked-predicate diagnostics exist, so an annotated name may sit under expr).
rust
fn binding_target_name(ctx: & mut dyn NativeOpCtx, target_idx: usize, err_ctx: &str) -> Result<String, handl_language::LangError>

hnl_engine_exec::native_ops::handle_dyn_shell ​

Function

The shared handle <body> with <handler> dynamic-extent shell (ADR-0076 + ADR-0153 §4), mirroring the tree-walk Handle arm:

  1. evaluate the impl child into a handler value;
  2. push it onto the runtime handler stack;
  3. evaluate the target (body) child under it;
  4. interpret an IO(sig) former result through [interpret_io_former] (the handler is still on the stack, so [NativeOpCtx::handler_lookup] resolves covered ops exactly like an arr <op> dispatch);
  5. pop the handler — on every exit, hit or error;
  6. attach the carried handler for deep dispatch ([attach_carried_handler]) and return the value.

target/impl positions resolve by named role (ADR-0081) with the positional 0/1 fallback for role-less shapes — the same convention [match_shell] applies.

hnl_engine_exec::native_ops::match_shell ​

Function

The shared match/handle shell (ADR-0061 pattern algorithm + ADR-0081 role resolution).

Node layout: match carries children: [scrutinee, (motive,) block] — motive is an optional role (Phase 6.3 dependent motives, ignored at runtime), so block's position resolves arity-aware via [NativeOpCtx::child_role_index_for]. handle carries children: [target, impl] (the target value is clause-matched against the impl block's arms). The block node's children are arm indices; each arm's pattern/body positions resolve by named role (arity-aware on the arm node) with the positional 0/1 fallback for role-less shapes.

Per arm: push a scope, run [NativeOpCtx::try_pattern] (binders land in that scope), and on a hit evaluate the arm's body child under the bindings — for handle the body position is the handler. The scope pops on every exit — hit, miss, or pattern error. (The pre-unification tree-walk leaked the pushed scope when try_pattern errored; bytecode/cranelift popped first. The pop-then-propagate convention won — a caught error, e.g. inside an eval_rec pass, must not leave a stale scope.)

No-match default: match errors "match: no arm matched"; handle returns the evaluated target value as-is.

rust
fn match_shell(op: &str, ctx: & mut dyn NativeOpCtx) -> OpResult
