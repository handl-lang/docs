hnl_engine_test:🏃:TestKitSource ​

Type Alias: std::sync::Arc<dyn Fn>

The injected base-runtime factory (ADR-0128 §"The 0.8 seam").

Each call must produce a fresh [Runtime] on the calling thread — the module chain is Rc-based, so a runtime cannot cross threads and scheduler workers invoke the factory inside the job closure rather than sharing a runtime value. What the runner needs from it: lang() (the base language, pre test-fragment merge), modules(), and import_resolver()/module_root() — the pieces a kit's runtime() carries. The host wires this from its own kit cache (e.g. a thread_local + capture-less closure, which is what keeps the factory Send + Sync).

hnl_engine_test:🏃:TestRunCache ​

Struct

Opt-in, in-memory and disk-persisted test-result cache (ExecutionCache in ADR-0089).

The generic eval-result memoisation concern lives in plugin-exec-cache; this is the thin test-domain layer over it. Keys reuse the generic fingerprint machinery — an [AstKey] whose kind is "test.result" and whose payload_json serializes the test identity (module path + name + body_source), so a test is re-evaluated when its source changes. Values are recorded (TestResult, FailureDetail) pairs.

For pure tests same test + same source + same runtime = same result, so a cached second run replays Pass/Fail outcomes without re-evaluating — identical in ordering and content to a fresh run.

The handle is caller-provided and reusable across runs; it is not used unless passed to [run_selected_cached]. Result caching is opt-in per the ADR-0089 --cache flag. Disk persistence is provided by [TestRunCache::load] and [TestRunCache::save].

Function

Discover tests in the given paths.

Each path is either a .handl/.hnl file or a directory to search recursively. Tests are discovered by parsing each module and extracting test declarations (bindings whose name starts with test_). Tests are ordered by source position within each module, and modules are ordered lexicographically by path.

source is the injected base-runtime factory (see [TestKitSource]); discovery uses only its language.

hnl_engine_test:🏃:tag_expr_predicate ​

Function

Build a [Filter] from a tag expression.

Grammar (per --tag flag value):

text
expr := term ("," term)*     — comma separates alternatives (OR)
term := "!"? name            — `!` negates the tag (NOT)

So "slow,net" selects tests tagged slow OR net, "!slow" selects tests NOT tagged slow, and "a,!b" selects tests tagged a OR not tagged b. Repeated --tag flags are combined with AND via [Filter::and]. An empty expression (or one with only empty terms) selects all tests.
