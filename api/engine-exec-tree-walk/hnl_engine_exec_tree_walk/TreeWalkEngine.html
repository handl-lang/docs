hnl_engine_exec_tree_walk::TreeWalkEngine::apply_app ​

Function

Apply a callable value to args: arr <op> dispatch objects, bound-arrow records ({__term__, __bound__}), >>> composite records, and TaggedValue::Arrow closures.

Public so sibling engines (the cranelift JIT) can delegate arrow application to this reference path — an arrow's body_def arena is self-contained data (ADR-0106), so any engine can interpret it here without re-JIT-compiling per arrow.

ast/node_ref/current_node supply ambient context for the dispatch-object paths' error reporting; env supplies the globals a body's free host references resolve against. The Arrow arm runs the arrow's own body_def arena under a fresh scope seeded with its binds.

hnl_engine_exec_tree_walk::TreeWalkEngine::dispatch_op ​

Function

Dimension-typed Op dispatch (ADR-0120 Phase 3): search the runtime handler stack (innermost-last) for a handler value whose impls map provides an implementation for op, then — when no stack handler applies — the incoming value's own impls field (a tagged value {"__tag__": <sort>, "grades": [...], "impls": {...}} may embed per-dimension op implementations), then the language-level handler table via [Language::handler_for_grade] (already dimension-typed — the key IS the dim label).

A Handler value is a tagged object {"__tag__": "Handler", "impls": {"<op>": <Term>, ...}} where each impls entry is a serialized [Term] run with the op's incoming value. Returns Ok(None) when no handler provides op, so the caller can fall back to native op dispatch.

dim_label is the op's dim resolved to a named dimension label (what the graded-effect surface called a grade). When present, a stack handler that declares a grades list — the set of named dimensions it interprets — covers the op only if the list contains the label; a handler with no grades field is dimension-agnostic (a bare handle <target> with <record>) and serves any dimension. Numeric/unnamed dimensions (dim_labelNone) impose no coverage constraint — every pushed handler is eligible, preserving pre-Phase-3 behavior.

fn dispatch_op(self: &Self, op: &str, dim_label: Option<&str>, incoming: Option<&TaggedValue>, ast: &Ast, node_ref: AstRef, lang: &Language, env: & mut ScopeStack, current_node: &AstNode) -> Result<Option<(TaggedValue, bool)>, LangError>

hnl_engine_exec_tree_walk::TreeWalkEngine::eval_ast_rc_with_args ​

Function

Like eval_ast_rc, but merges call_args directly into the call frame's ScopeStack globals map — without cloning the engine via with_global.

The call args are bound into the same globals field that host-provided globals (e.g. self) use, so they are:

  • resolvable via [ScopeStack::lookup] (globals fallback),
  • excluded from capture() — they are never deep-cloned into closures ("no env capture", ADR-0106), and
  • not stored on the engine struct, so no box_clone is needed.

This is the tree-walk override of [EvalEngine::eval_shared_with_call_args], used by plugin-lib-handl's HandlFunction::call to bind __arg_0.. __arg_{n-1} directly on the call frame instead of injecting them as per-call engine globals.

rust
fn eval_ast_rc_with_args(self: &Self, lang: &Language, ast_rc: Rc<Ast>, call_args: &[(String, Value)]) -> Result<Value, LangError>

hnl_engine_exec_tree_walk::TreeWalkEngine::eval_inner ​

Function

Internal recursive interpreter. Returns the value and whether a scope was pushed that the caller is responsible for popping.

Only extend_env pushes a scope. Seq pops the scope its fst reported and propagates whatever snd reported (so an extend_env in the inner Seq's snd position — the Bind lowering shape — is popped by the enclosing Seq after its snd completes). The other combinators (First/Choice/Loop/ App) pop any scope their sub-evaluation pushed immediately, since they have no "binding persists down the pipeline" semantics.

hnl_engine_exec_tree_walk::TreeWalkEngine::eval_scheme ​

Function

Interpret a given [Term] in the context of current_node.

This is the core handler entry point. incoming is the value fed by an enclosing Seq/First/Choice/Loop; top-level calls pass None.

Scope discipline ​

extend_env pushes a scope and returns the value flowing through. The scope's lifetime follows the arrow pipeline: it is popped by the enclosing [Term::Seq] whose fst (transitively) contained the extend_env, after that Seq's snd completes. This realizes the Bind lowering value >>> extend_env "x" >>> body = Seq(Seq(value, extend_env), body): the scope pushed by extend_env (the inner Seq's snd) is reported up through the inner Seq and popped by the outer Seq after body. A bare extend_env with no enclosing Seq is popped here.
