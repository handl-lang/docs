hnl_engine_exec_tree_walk::STACK_RED_ZONE ​

Constant: usize

Remaining-stack budget at which [stacker::maybe_grow] moves the next eval step onto a fresh segment. The tree-walk recurses natively once per arrow application (eval_node_inner → scheme → apply_app → apply_arrow_body → eval_node_inner), so a self-recursive arrow — or a handle … with reinstalling deep handlers each level — would overflow the platform stack at a few thousand calls. Checking at the two recursion funnels bounds eval depth by total growable stack. Mirrors hnl-engine-typecheck-nbe's STACK_RED_ZONE.

hnl_engine_exec_tree_walk::STACK_SEGMENT ​

Constant: usize

hnl_engine_exec_tree_walk::ScopeStack ​

Struct

A scope stack: Vec<FxHashMap<Rc<str>, TaggedValue>> searched innermost-first.

Used by the tree-walk interpreter for extend_env binding and for installing an arrow's residual binds at application time (captured, ADR-0106). The scopes field is pub(crate) so the engine can manage the binds install/restore.

Host-provided globals (e.g. self) are kept in a separate globals field (a cheaply-cloned Rc<FxHashMap>) rather than in scopes[0]. This prevents the (potentially massive) globals from being collected into every minted arrow's binds and re-cloned on every arrow call. lookup() falls back to globals after searching the scope stack, and capture() only collects user-created scopes — never globals.

Clone: multi-shot resume snapshots the handle-entry environment into a replay journal so each resume re-run starts from the same scope state (globals shares its Rc; scopes deep-clone).

It evaluates bare [Term] schemes by mounting them on a minimal dummy AST / Language context and reusing the existing tree-walk evaluation logic.

ADR-0103 continuation: arrow-model delegation ​

The optional second field (arrow_model_delegate) is a Handl-authored Model (e.g. handl_plugin_lib_handl::HandlModelAdapter wrapping arrow_model.hnl). hnl_engine_exec_tree_walk::cached_def_arena ​

Function

The standalone arena carried by a body_def, deserialized at most once per definition value (ADR-0106).

def is the arrow's body_def: a {"__ast__": <Ast>} value produced by Ast::instantiate + ast_value. Applying a self-describing arrow needs that arena; deserializing it on every application allocates per call, so this memoizes it per thread:

  • Key: the Rc<TaggedValue> pointer of def. Safe because the cache entry stores an Rc::clone of def, so the allocation cannot be freed (and the address reused for a different value) while the entry lives. Two structurally identical but distinct definitions have different addresses and different entries.
  • Bound: the table is cleared once it reaches [ARROW_ARENA_CACHE_CAP] entries, so memory stays bounded; the cost of clearing is at most one re-deserialization per live arrow.

Returns None when the definition is not a well-formed __ast__ value or the arena is empty — the arrow is malformed and the caller errors.
