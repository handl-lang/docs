handl_host_tensor::ops::codec::FromList ​

Struct

The Rust handl for op "tensor.from_list" : Array -> Tensor.

Infers the shape from the nesting of number arrays and requires the input to be rectangular: at every level all siblings must have the same inferred sub-shape, so [[1, 2], [3]] and [[1], 2] are errors. A scalar argument is not a list — TypeMismatch. [] is the rank-1 empty tensor (shape [0]); [[], []] is shape [2, 0].

handl_host_tensor::ops::codec::decode_tensor ​

Function

Decode a tensor argument. Accepts {"__tensor__": {"shape": [...], "data": [...], "dtype"?: "f64"}}; anything else — a missing tag, a non-array shape/data, a negative or non-integer extent, a data length that is not product(shape), or a dtype other than "f64" — is a TypeMismatch (malformed wire value) rather than a silent coercion.

rust
fn decode_tensor(arg: &serde_json::Value) -> Result<Tensor, handl_platform::EvalError>

handl_host_tensor::ops::codec::encode_tensor ​

Function

Encode a tensor as the canonical {"__tensor__": {...}} wire value.

Non-finite f64 elements (inf, -inf, NaN — e.g. a div by zero or an add/mul overflow) have no serde_json representation: Number::from_f64 rejects them and they serialize as null in data, which [decode_tensor] rejects on the way back in. The wire is therefore closed over finite f64 only — the kernel TaggedValue::Tensor carries them inside an engine, but any serde_json crossing still degrades them to null.

rust
fn encode_tensor(t: Tensor) -> serde_json::Value
