Module: egraph ​

The e-graph: union-find interned representation, matching, and bounded equality saturation.

Ports the spec's EGraph (core.py) with three deliberate divergences, all named:

  • Eager per-class match enumeration. The spec streams matches through a frozen-read _Epoch so apply_rule can union between yielded substitutions while the enumeration keeps its call-time view. An eager per-class enumeration is the same observable semantics — the epoch machinery exists to reproduce exactly the list the pre-streaming matcher returned. We enumerate that list directly; memory stays bounded per class by the same [EGraph::MATCH_CAP] the spec applies.
  • Structural ordering (ENode: Ord) replaces the set + _member_key rescan, and a typed [Subst] replaces the "$attr:" key-mangling. Same total order, same determinism.
  • check/derive see a resolved [BoundEnv] computed before the hook runs — the hooks themselves are pure, so they can never mutate the graph mid-application.

Module: extract ​

Extraction: deterministic minimum-cost member selection.

Ports the spec's extract_best core — the DAG-aware greedy walk — minus its domain payload: no FOLD_OPS param-only discount, no fusion tie-break, no roofline/overhead memo probes (those are cost-model policies the domain injects, not substrate). What stays is exactly the contract the domain relies on:

  • members are scanned in canonical ([ENode]) order;
  • each e-class in the extracted DAG is charged once (the used-set billing — a shared child contributes its subtree cost only for classes not already accounted for);
  • local = max(cost(term) - Σ cost(children), 0);
  • ties resolve on fewest ops (nops), then canonical order;
  • cyclic classes are unextractable;
  • overrides/bans steer the pick (coordinated extraction and bounded-ε filtering plug in here).

extract_min_depth, dag_cost, extract_alternatives, and diverse_classes port verbatim modulo the same domain strip.

Module: node ​

E-nodes and e-classes: the interned node representation.

An [ENode] is a (op, children, attrs) triple where children are canonical e-class ids. Ordering is structural — (op, children, attrs) lexicographic — which is the spec's _member_key contract: a total, process-independent member order consumed by every decision-reaching member scan (matching order, congruence drain, any_term, extraction tie-breaks). The spec computed it as (op, children, repr(attrs)); structural Ord keeps the invariant without the repr (named divergence — strictly better complexity, same determinism guarantee).

Module: pattern ​

Compiled patterns — the spec's _PVar/_PLeaf/_POp/_Prog.

Each rule's pattern compiles once per e-graph into a PNode tree carrying everything the match needs precomputed: the normalised attr tuple, the attr-name keyset for the exact-equality gate, the prebuilt leaf [ENode] for the registry probe, and the per-child op constraints feeding targeted eligibility (_opk).

Module: rewrite ​

Rewrite rules, side-condition environments, and provenance records.

Ports the spec's Rewrite minus its domain-law bookkeeping (derivation/cond/dspec are catopt_core.laws.cond machinery — the crate keeps the generic core: patterns, check/derive hooks, tags, and the ε-law bound fields).

Module: subst ​

Substitutions: metavariable bindings produced by a match.

The spec keeps one flat dict with two namespaces — term metavariables under their own names, attribute metavariables under "$attr:<name>" keys. The Rust port splits the namespaces into two ordered maps (named divergence — typed beats key-mangled), which is also what derive hooks and the recorded ProofEdge subst see.

Module: term ​

The crate's term type — patterns and concrete terms share it.

Mirrors the spec's dual use of Op trees: a rule's lhs/rhs, the terms interned into the graph, and the terms extraction produces are all [Term]. Two positions are pattern-only:

  • [Term::Var] — a metavariable binding an e-class (the spec's bare str leaf).
  • [TermAttr::Meta] — an attribute metavariable (the spec's string-valued attr, bound under the "$attr:" namespace — the separate [crate::Subst::attrs] map replaces that key-mangling).

EGraph::add_term rejects both — a metavariable is not a term — where the spec would silently leaf-intern a str (named wart).

Module: term_bridge ​

The kernel bridge: hnl_engine::Term / serde_json::Value ↔ the crate's [Term].

Encoding contract — every Term variant maps to an Op node whose op is the variant tag (except Term::Op, whose enode op is the domain operator name), with Term-typed fields as child positions in declaration order and scalar/Value fields as literal attrs. Term::Op additionally encodes dim as child position 0 so rewrites can reach it; source/lit ride attrs:

Self-describing leaf keys replace the spec's global _LeafRegistry (a named wart — process-global mutable state whose decode depended on registration order). A leaf term serializes to its own JSON Term encoding as the key, so to_term decodes it standalone; an unrecognized key decodes to Term::Opaque, keeping the round-trip total.

Module: union_find ​

Union-find (disjoint-set): path halving + union by rank.

A straight port of the spec's UnionFind — the rank rule decides which root survives a merge, so canonical-id choice is identical to the Python version (higher rank wins; first argument on a tie).

Module: value ​

Attribute values: the hashable, totally-ordered scalar/composite domain carried by e-node attributes.

Ports the Python spec's two-tier attr semantics:

  • Identity is spelling-strict. The spec's ENode._sig repr-keys every attr value, so 0 and 0.0 (and 0.0 and -0.0) are distinct enode payloads. AttrValue's Eq/Hash mirror that: floats compare by bit pattern, ints never equal floats.
  • Matching is numerically lenient. The spec compares pattern attrs to node attrs with != — Python's value equality, where 1 == 1.0, True == 1, and (1, "a") == (1.0, "a"). That is [AttrValue::match_eq]: recursive numeric leniency, including the bool↔int coercion the Python tower admits.

Ordering is structural, not repr-derived — the deliberate fix for the spec's repr(attrs) sort keys. The invariant the spec protects is a total, process-independent member order; structural Ord provides it directly (and without recomputing a repr per compare).
