hnl-engine-exec-cranelift ​

The cranelift eval engine for the eval operation (ADR-0044 §4, §7).

This engine compiles [handl_language::Term] data to native code via [cranelift] and executes it via an in-memory JIT. It shares the same Term vocabulary as the [hnl_engine_exec_tree_walk] reference interpreter and the hnl_engine_exec_bytecode(hnl_engine_exec_bytecode) bytecode engine; conformance tests verify all three produce identical results.

Compilation strategy: boxed values + native control flow ​

The handl value space is [serde_json::Value] — dynamically typed. A full type-inferred native compiler is out of scope for Phase 7. The realistic approach (and what ADR-0044 §7 "compilers erase data dispatch" means in practice):

Cranelift generates native functions where:

  • Control flow is native: [Term::Choice] compiles to native brif/jump instructions. extend_env/proj_env scope push/pop is native. [Term::App] closure dispatch is a native call to a helper.
  • Value operations call Rust helpers: native Arr ops ([Term::Arr] with ArrSource::Native), foreign Arr ops ([Term::Arr] with ArrSource::Foreign), proj_child, variable load/store, and payload access are native calls into Rust functions that operate on [Value] (boxed as a pointer). The native code passes/receives *mut Value handles.
  • The per-node scheme lookup is erased: at compile time, each node's [Term] is lowered to a fixed sequence of cranelift IR instructions + helper calls. The compiled function has no lang.eval[node.kind] hash lookup at execution time — the scheme is baked into the native code. This is the ADR §7 property.

This is a legitimate JIT: native control flow + erased data dispatch + helper calls for value ops. It is faster than the bytecode VM (native jumps vs interpreted dispatch) and demonstrates the compilation pipeline that enables the self-hosting bootstrap (compile(handlLanguage, native)).

Per-node compilation ​

Every node in the [Ast] arena is compiled to its own native function with the signature fn(*mut EvalCtx) -> *mut Value. The scheme for each node is resolved at compile time (one-time lang.eval[node.kind] lookup) and baked into the IR. At execution time, proj_child dispatches to the child's pre-compiled native function via a function-pointer cache — no scheme lookup occurs.

Constant pools ​

Literal values and string names (variable names, primitive operators, foreign function names) encountered during compilation are collected into constant pools stored in [EvalCtx]. The compiled code references them by index, avoiding raw string pointers in native code.

Conventions (matched to the tree-walk and bytecode) ​

  • Child(n) = nth child of current node: reads node.payload["children"][n] to get the absolute [AstRef], then calls the child's compiled function.
  • Var("$payload") reads node.payload as the variable name.
  • Bind{name: "$payload", ...} reads node.payload["name"] as the bind name.
  • No-scheme fallback: if a node kind has no eval scheme, returns node.payload directly.
  • Closure representation: Value::Object with {"__arrow__": true, "params": [...], "body_def": {"__ast__": &lt;Ast>}, "binds"?: {...}, "handlers"?: [...]} — self-contained serialized data (ADR-0106), created by the "closure" primitive.
  • Primitives: add, sub, mul, div, mod, eq, lt, gt, not, and, or, neg, closure, bind — identical semantics to the tree-walk.
  • Scope: Vec<HashMap<String, Value>> scope stack; Bind pushes a child scope; lookup searches innermost-first. Arrow application delegates to the tree-walk engine: an arrow's body_def arena is minted at runtime, so it is interpreted rather than JIT-compiled.

Safety model ​

Raw pointers + JIT is inherently unsafe. The safety is encapsulated:

  • The public API ([CraneliftEngine], [EvalEngine] impl) is safe.
  • The [EvalCtx] is owned by the engine on the Rust side; native code receives a raw pointer. The engine guarantees the [EvalCtx] outlives all native code execution.
  • [Value] handles are heap-allocated Box<Value> leaked into pointers (Box::into_raw). Helpers that consume a value pointer reclaim the box (Box::from_raw + mem::take). The final return value is reclaimed by the engine. Intermediate values that are checked but not consumed (e.g. a Branch condition) leak for the duration of evaluation — acceptable for Phase 7, documented here. On error, the scope stack and any leaked values are dropped with the [EvalCtx].
  • Bind scope pop (pop_scope) is only called on the success path. On error, the native code returns immediately, skipping pending pop_scope calls. The scope stack is dropped with the [EvalCtx] on error — no memory corruption, just extra scopes that are never popped. This is a documented safety tradeoff for Phase 7.
