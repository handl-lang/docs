hnl_engine_exec_cranelift::compile::CompileMode ​

Enum

Compilation mode for the compiler: in-memory JIT or on-disk object file.

Selects which cranelift backend the compilation logic targets. Mirrors the [crate::compile::CompileMode] but produces function pointers.

Variants:

  • Jit - In-memory JIT — compile and execute via function pointers. Helper
  • Object{ output_path: std::path::PathBuf } - On-disk object file — compile to a relocatable .o file for linking.

hnl_engine_exec_cranelift::compile::CompiledBackend ​

Enum

The backend holding compiled code alive.

For JIT mode, the [JITModule] must be kept alive so the compiled code remains in memory (the function pointers point into JIT-allocated memory). For Object mode, the code has already been written to disk by ObjectModule::finish (which consumes the module), so there is nothing to keep alive — the variant is unit.

Variants:

  • Jit(cranelift_jit::JITModule) - The JIT module, kept alive so compiled code remains in memory.
  • Object - Object mode — the module was consumed by finish to emit the file.

hnl_engine_exec_cranelift::compile::CompiledFn ​

Type Alias: fn(...)

Type alias for a compiled native function pointer.

The function signature is fn(*mut u8, *mut u8) -> *mut u8, where the actual types are *mut EvalCtx, *mut Value (incoming), and *mut Value (result). The raw *mut u8 is used because cranelift works with opaque pointers. Arrows flow an incoming value through the computation.

hnl_engine_exec_cranelift::compile::compile_all_nodes_jit ​

Function

Compile all nodes in the AST to in-memory native functions (JIT).

Each node is compiled to a function with signature fn(*mut EvalCtx, *mut Value) -> *mut Value. The scheme for each node is lowered to Term at compile time and baked into the IR. V2 helper functions are registered with the JIT builder so the compiled code can call them directly.

hnl_engine_exec_cranelift::compile::compile_all_nodes_object ​

Function

Compile all nodes in the AST to an on-disk relocatable object file (v2).

Uses [ObjectModule] instead of [JITModule]. V2 helpers are declared as external imports resolved by the linker at link time. After compilation and finalization, ObjectModule::finish produces the object file, which is written to output_path.

hnl_engine_exec_cranelift::compile::compile_scheme ​

Function

Compile a [Term] into cranelift IR, returning the result Value and whether a scope was pushed that the caller is responsible for popping.

incoming_val is the cranelift IR value representing the incoming value pointer flowing through the arrow. After this function returns, the builder is in the block containing the result value.

This is the &Term entry point: it converts the scheme to [TermData] (ADR-0103 Phase 6) and delegates to [compile_scheme_td], which dispatches on the __tag__ field instead of matching the Term enum.

hnl_engine_exec_cranelift::compile::compile_scheme_td ​

Function

The [TermData]-driven counterpart of [compile_scheme].

Dispatches on [TermData::tag] and reads variant fields via the get/get_str/get_term/get_term_list accessors. Derived forms (CellId/Src/Tgt/CellCompV/Whisker/Const/RecordProj) are rewritten to their Op/Arr lowering using [TermData] constructors and recompiled recursively, so no Term enum value is constructed for them.
