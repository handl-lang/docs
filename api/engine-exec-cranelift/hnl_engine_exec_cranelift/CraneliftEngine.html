hnl_engine_exec_cranelift::CraneliftEngine::compile_to_executable ​

Function

Compile the language + AST to a standalone executable.

This is the full ADR-0044 Phase 8 compile(handlLanguage, native) step: compiles the AST to a relocatable .o file, then links it with a generated C main driver and this crate's static library (which exports the helper_* runtime stub and the handl_standalone_* entry points) to produce a standalone executable.

The resulting executable, when run, evaluates the AST and prints the result (as JSON) to stdout — producing the same output as the host-built handl.

Foreign functions ​

The standalone executable does not support foreign Arr ops (Term::Arr with ArrSource::Foreign) — there is no host functions registry at runtime. Corpus cases that use foreign functions will fail at evaluation time; this is a documented limitation of the Phase 8 proof-of-concept.

hnl_engine_exec_cranelift::CraneliftEngine::run_compiled ​

Function

Run a pre-compiled [CompiledResult] against lang and ast.

This is the execution half of compile + run: a [CompiledResult] produced by [compile_all_nodes_jit] is executed without recompiling. The lang and ast must be the same values used to produce result (the compiled function pointers reference constant pools and per-node functions keyed by arena index). The [CompiledResult] must outlive this call — its backend keeps the JIT-allocated native code in memory, so the function pointers in result.compiled remain valid as long as result is alive.

The engine's module registry (set via with_modules) is used for foreign Arr op dispatch, matching eval.
