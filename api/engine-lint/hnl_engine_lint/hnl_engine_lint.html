Module: module ​

Module-level linting: statement splitting, parsing, and the shared per-statement ModuleAnalysis. Module-level linting (ADR-0097 — Lint Rules as Language Data).

The bootstrap Pratt parser parses one top-level statement per call, so a source file is split into statement chunks at bracket-depth zero (respecting strings and -- comments) and each chunk is parsed individually — the same convention the bootstrap typechecker and test runner use. A [LintModule] bundles the source text with the parsed statements; [ModuleAnalysis] is the shared per-statement classification (bindings / references / arrow params / imports) the scope.* natives consume.

Positions come from [AstNode::span] (populated by the Pratt parser), offset by each statement's byte offset in the source — no token-stream rescanning.

Module: native ​

Native lint rules and the NativeLintRegistry. Native lint rules — the disciplined escape hatch (ADR-0097 §3).

A LintRuleDef whose check is !Native "name" defers detection to a registered function. Natives see the whole module — all parsed statements plus the source text — so they can express scope analysis (scope.*), convention checks that need renaming (naming-convention), and whole-source checks (source.*) that the node-local LintCheck::Match predicate vocabulary cannot. This mirrors TransformRule::Native / with_desugar_natives (ADR-0094): dispatch stays in data, only the implementation is Rust.

[canonical_lint_natives] registers the canonical surface's semantic residue: scope.unbound-wire, scope.shadowed-binding, scope.unused-import, naming-convention, source.missing-module-doc, source.fmt (a no-op overridden by hosts with a formatter), and the builtin.* per-statement AST checks (empty-block, unreachable-code, shadowed-binding, unused-binding). Hosts register their own natives on top (e.g. plugin-ext-lint overrides source.fmt with the real formatter-backed implementation).
