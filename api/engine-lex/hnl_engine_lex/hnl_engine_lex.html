hnl_engine_lex::Lexer ​

Struct

The lex operation marker.

A zero-sized type identifying the lex stage. It carries no state; its purpose is to be the Operation type that pairs with [LexerRequest] and to serve as a namespace for the lex abstraction.

hnl_engine_lex::LexerEngine ​

Trait

The trait a lex engine implements.

An engine reads lang.tokens (the [handl_language::TokenKindDef] fragment set) to decide which token kinds exist and how to recognize them, then produces a [Tokens] stream. The engine is pure data-driven: it does not call Rust Behavior impls.

Errors ​

Returns [LangError] on lexing failure (e.g. an unrecognized character).

Methods:

  • lex: Lex req.source into a token stream using the language's token
  • box_clone: Produce an owned boxed clone of this engine.

hnl_engine_lex::LexerRequest ​

Struct

Request passed to a [LexerEngine].

Carries the source text to tokenize plus a serializable options map. The options are opaque to this crate — a concrete engine interprets them against the Language's options fragment set.

Fields:

  • source: handl_language::Source - The source text to lex.
  • options: serde_json::Value - Engine-specific options (opaque key/value pairs).

Methods:

  • fn with_options(self: Self, options: serde_json::Value) -> Self - Attach an options value (builder style).
