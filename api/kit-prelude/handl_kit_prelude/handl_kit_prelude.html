handl_kit_prelude::HelloGreetHostFn ​

Struct

hello.greet(name) host function — the canonical handl greeting.

The canonical kit data declares eval.hello.greet as a Foreign scheme (name hello.greet) and ast.hello.greet. Source syntax hello.greet(x) parses as call(field-access(hello, greet), x): the hello global (injected by [Kit::new]) is {"greet": "hello.greet"}, so field-access yields the string "hello.greet", and the tree-walk engine's apply_closure dispatches a string-named host function to this impl.

The greeting logic itself is handl-authored in greet.hnl; this impl only validates arguments and delegates to [greet_via_handl].

All staged methods (lex, parse, eval, run) delegate to the underlying [Runtime].

Module: library_registry ​

The prelude kit's library-module table (ADR-0128 §0.4).

Moved out of plugin-ext-kit: a kit manifest's modules: names resolve through a [LibraryRegistry] the kit supplies. The table is composed, not monolithic — module-runtime lives here (the shared host every kit registers first) and each kit-* crate contributes its own rows: kit-stdlib the hello/stdlib/cli manifests' libraries, kit-server the config/server manifests'. Hosts wire [prelude_library_registry] (or a subset) into BasicKitLoaderPlugin; other kits supply their own.

handl_kit_prelude::prelude_engine_registry ​

Function

Build the canonical [EngineRegistry] — the name→engine map Kit::build_kit and [runtime_for_lang] wire into every runtime (ADR-0047 §2).

Statically registered: data lex, pratt parse, tree-walk and bytecode eval, bytecode compile, and the handl typecheck engine — plus, under the cranelift Cargo feature (on by default), the cranelift eval engine and the native compile engine backed by hnl-engine-exec-cranelift.

The registry is the ext contract for exec engines (ADR-0128 §0.5): engines are selected by name through RuntimeConfig, never dispatched statically, so a consumer that builds this crate with default-features = false can register its own implementations on the returned map and pass it to [Kit::new_with_registry] or [runtime_for_lang_with_registry].

handl_kit_prelude::prelude_wire_names ​

Function

The wire names a .hnl source can reference without a source-level binding, derived from the same module chain Kit::build_kit wires (ADR-0096 "Unified import model").

At eval time an unbound identifier falls back to its name string and module.name(args) wires resolve through [ModuleRegistry::lookup]: qualified mod.fn names resolve via the module-name prefix, and flat names (map, pipe, greet, …) match any module's local function names. The returned set therefore contains:

  • every registered module name (str, char, json, tag, array via the collections aggregate's dotted dispatch, error, assert, test, …);
  • every local function name of every registered module (flat wires);
  • every module name in the package table (stdlib::MODULES), since KitResolver/DEFAULT_RESOLVER can materialize them — this covers the collections aggregate's vec/list/array/… prefixes, which are dispatched by dotted name rather than enumerated;
  • the ambient globals build_kit injects (self, hello) and the fixed host-function wires of the hello/fp lookup chains (greet, field_access).

hnl typecheck passes this set to [hnl_engine_typecheck::check_module_with_prelude] so the checker's scope matches what the runtime resolves — the checker crate cannot depend on this crate (dep cycle), so the name set lives here where the wiring lives.
