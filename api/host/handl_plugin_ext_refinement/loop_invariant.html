handl_plugin_ext_refinement::loop_invariant::discover_invariant_fixpoint_real ​

Function

Discover a loop invariant by fixpoint iteration.

Algorithm:

  1. Start with I_0 = initial (typically the body's guarantee, or True for the trivial starting point).
  2. Compute the WEAKEST PRECONDITION of the loop body on the feedback channel: wp(G, I) = the weakest predicate on c such that after G executes, I(c') holds.
  3. The invariant must be a FIXPOINT: I = wp(G, I) & I (conjunction).
  4. Iterate: I_{n+1} = I_n && wp(G, I_n).
  5. Stop when I_{n+1} = I_n (fixpoint reached) or after max_iterations.

Returns: (final_invariant, how_discovered, iteration_trace, verified) where iteration_trace records every I_n so the algorithm is transparent and auditable, and verified is true iff the final invariant is preserved by one more step of the body (i.e. I ==> wp(G, I)).

fn discover_invariant_fixpoint_real(body: &handl_language::Term, registry: &crate::contracts::ContractRegistry, initial: &crate::types::Pred, max_iterations: usize) -> (crate::types::Pred, String, Vec<crate::types::Pred>, bool)

handl_plugin_ext_refinement::loop_invariant::pattern_candidates ​

Function

Collect candidate invariants from structural patterns in the loop body.

Currently recognises the "output-building loop" pattern: when the loop body contains cons (the list constructor), it adds IsPerm(input, output) as a candidate invariant. This captures the multiset-preservation property of loops that consume an input list and build an output list from its elements -- most notably insertion sort, where each iteration moves one element from the remaining input into the accumulator, so the accumulator is always a permutation of the original input.

Matching the Agda example S ys. Sorted ys * Permutation xs ys, this lets sort derive Sorted(output) && IsPerm(input, output).

The list consumption may be implicit (the loop's feedback channel shrinks each iteration) rather than an explicit tail arrow, so we only require cons to be present -- the presence of a list constructor in a loop body is a strong signal that the loop is building an output list from the input's elements.

fn pattern_candidates(body: &handl_language::Term) -> Vec<crate::types::Pred>

handl_plugin_ext_refinement::loop_invariant::weakest_precondition ​

Function

Compute the weakest precondition of G with respect to predicate I on the output. wp(G, I) = the weakest predicate on the input such that after G executes, I holds.

This is computed structurally by recursion over the Term -- not hardcoded per test case. Each graph combinator has a well-defined weakest-precondition transformer:

  • arr(id) / arr(op) with no contract : wp = I
  • arr(f) with contract : wp = precondition(f) if guarantee(f) ==> I, else True (conservative -- cannot prove)
  • seq(g, h) : wp(g, wp(h, I)) (backwards composition)
  • first(g) : I (the feedback channel C passes through unchanged on the second component)
  • choice(l, r) : wp(l, I) && wp(r, I) (the invariant must hold on both branches, so the weakest precondition is the conjunction of each arm's wp)
  • loop(g) : I (the loop's invariant is the fixpoint, so the weakest precondition is the invariant itself)
  • app(callee, args) : I (conservative -- not used by inference)
