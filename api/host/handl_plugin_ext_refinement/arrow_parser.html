handl_plugin_ext_refinement::arrow_parser::analyze_branch_ast ​

Function

Analyze the recursive case arm body AST and map it to a [Term] graph.

This mirrors the legacy analyze_branch heuristic but operates on the AST instead of raw text. The patterns recognized (in order of specificity):

  1. Nested loop_rich → recursively materialize the inner loop
  2. prim.compare identifier → comp(prim.compare, choice(cons, cons)) (insert)
  3. *.p in arrow_call (callee(arg)) → comp(filter_step, id) (filter)
  4. *.f in call with *.acc argument, no id on *.acc → fold_step (fold) 3a. *.f in call with *.acc argument, id on *.acc → comp(fold_step, first(id)) (reduce)
  5. insert in arrow_call (callee(arg)) → comp(app(insert), first(id)) (sort)
  6. *.f in arrow_call with *.acc in right args → comp(fold_step, first(list.cons)) (scan)
  7. list.head AND list.tail both in arrow_call → comp(first(list.head), comp(first(list.tail), list.cons)) (zip)
  8. list.head in arrow_call (callee(arg)) → comp(list.head, choice(cons, id)) (take)
  9. list.tail in arrow_call → comp(list.tail, first(id)) (drop)
  10. *.f in arrow_call (callee(arg)) → first(fn.apply) (map)

Patterns 2, 3, 5, and 9 use suffix-based matching (e.g. *.f matches state.f, inner_state.f, etc.) so that nested loops with different state variable names are recognized correctly.

Early-exit patterns (a match arm that returns without recursing) are inherently handled: the base-case arm ([]:) body is collected for pattern detection (e.g. id(state.acc) signals reduce vs fold) but only the recursive arm ([h, ...t]:) is analyzed for the main graph structure. Conditionals within the recursive arm (e.g. if state.n <= 0 return ...) are tracked via has_conditional for future pattern discrimination.

fn analyze_branch_ast(ast: &handl_language::Ast, root_idx: usize, base_case_idx: Option<usize>, lang: &handl_language::Language) -> Result<handl_language::Term, String>

handl_plugin_ext_refinement::arrow_parser::ast_to_scheme ​

Function

Materialize an [Ast] (produced by the Pratt parser) into a [Term].

The root node is the last node in the arena (Pratt convention: children are pushed before parents). For each node, the eval scheme is looked up via lang.eval.get_by_identity(&node.kind), then walked to produce a concrete Term with proj_child(N) placeholders replaced by the materialized Nth child.

Special placeholders ​

  • proj_child (with lit: N): recursively materialize child N.
  • $str_child0 (as op): the op name is child 0's payload string (used by arr_call / app_call for arr("name")).
  • $payload (as op): the op name is the current node's payload string (used by arrow_var for bare identifiers).
  • proj_rest (in args): expand to the materialized children 1..N (the argument expressions after the string name in arr(...) / app(...)).
  • $payload (as lit): the literal value is the node's payload.

Errors ​

Returns a String error if a node kind has no eval scheme, a placeholder cannot be resolved, or a child index is out of bounds.

rust
fn ast_to_scheme(ast: &handl_language::Ast, lang: &handl_language::Language) -> Result<handl_language::Term, String>

handl_plugin_ext_refinement::arrow_parser::parse_arrow_module ​

Function

Parse a .hnl arrow module file's content, extracting import/export and op/handl/cap declarations (ADR-0069, ADR-0077 Phase 2).

This is the module-aware counterpart to [parse_arrow_file]. It:

  1. Strips comments (reuses [strip_comments]).
  2. Scans for import, export, op, handl, and cap lines at the top level.
  3. Parses import lines: import name from "path", import name1, name2 from "path", import name as local from "path", import "path" as alias.
  4. Parses export lines: export name, export *, export name from "path", export * from "path".
  5. Parses op lines: op "name" : Type -> Type, optionally followed by indented guarantee:/requires:/termination: lines.
  6. Parses handl lines: handl "op.name" = rust_fn_name.
  7. Parses cap lines: cap "cap.name".
  8. Parses the remaining content as a [ParsedFile] (reuses [parse_arrow_file] on the non-declaration lines).

If the remaining content (after removing declaration lines) is empty, the arrows field is ParsedFile::Named with an empty map (a pure re-export or op-only module). lang is the arrow-dialect [Language] — see [parse_arrow_file].

rust
fn parse_arrow_module(lang: &handl_language::Language, src: &str) -> Result<ParsedModule, String>

handl_plugin_ext_refinement::arrow_parser::rewrite_imports ​

Function

Rewrite references to imported names in a [ParsedFile] so they become proper module_ref/project nodes.

After [parse_arrow_module] extracts the import declarations and parses the remaining content into a [ParsedFile], imported names still appear as bare Arr { op: <local_name>, args: [], source: Native, lit: None } references — indistinguishable from local arrow references. This function walks every Term in the ParsedFile and replaces such references with project(module_ref(path), remote_name) for named imports, or module_ref(path) for whole-module imports (import "path" as alias).

References to names that are locally defined in the ParsedFile are not rewritten — a local binding shadows an import of the same name.

rust
fn rewrite_imports(file: & mut ParsedFile, imports: &[ImportDecl])

handl_plugin_ext_refinement::arrow_parser::rewrite_scheme ​

Function

Recursively rewrite a [Term], replacing bare references to imported names with module_ref/project nodes.

A "reference" is either:

  • A standalone Arr { op: <name>, args: [], source: Native, lit: None } (e.g. passing an imported arrow as a higher-order argument).
  • The callee of an App { callee: Arr { op: <name>, ... }, args } — the callee is rewritten recursively, so the bare-Arr case covers this.

Only names in import_map that are not in local_names are rewritten (local bindings shadow imports).
