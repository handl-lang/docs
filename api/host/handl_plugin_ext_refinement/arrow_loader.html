handl_plugin_ext_refinement::arrow_loader::ModuleLoader ​

Struct

ModuleLoader maintains two caches keyed by module path (ADR-0069 §4):

  • Graph cache: path → named arrows (the parsed arrow graphs).
  • Contract cache: path → contracts (the inferred contracts per arrow).

On first load, the loader resolves the source, parses it (with import/export extraction), infers contracts, and stores both in the caches. Subsequent loads return cached clones. This is Strategy C (runtime module loading, lazy + cached) — see ADR-0069 §5.

handl_plugin_ext_refinement::arrow_loader::flatten_program ​

Function

Normalization Strategy B (ADR-0069 §5): whole-program flattening.

Loads the entry module and all its transitive dependencies, then resolves every App node by inlining the referenced arrow's Term graph (recursively). module_ref nodes are replaced by inlined records, and project nodes are resolved to the actual field's arrow. The result is a single Term graph with no unresolved App, no module_ref, and no project — one graph, no module boundaries.

Returns the entry's main arrow (if single-arrow) or a record of all public arrows (if multi-name).

rust
fn flatten_program(entry_path: &str, loader: &ModuleLoader) -> Result<handl_language::Term, LoadError>

Function

Normalization Strategy A (ADR-0069 §5): compile-time desugar.

Resolves the entry module, then walks its arrows: every App to an imported name is replaced by a project node from an inlined record of the referenced module's public arrows. module_ref nodes (if present) are also replaced by inlined records. project nodes are kept — Strategy A preserves projections. Returns a map of the entry module's arrow names to their normalized Term graphs (with imports replaced by projections from inlined records).

Both single-expression files and multi-name files are loaded. Files that fail to parse are silently skipped (the parser is minimal and may not handle all syntax).
