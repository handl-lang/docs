handl_test_utils::CaptureFn ​

Struct

A [Function] that records every call made to it and returns a configurable result.

Ported from plugin-vm-common's CaptureFn, adapted to the non-generic Function trait. Unlike the original (which wrapped an inner closure), this version returns a fixed [Value] configured at construction time. Use [CaptureFn::with_handler] if you need custom return logic.

ignore
use handl_test_utils::CaptureFn;
use serde_json::{Value, json};

let capture = CaptureFn::new(json!(42));
let mut ctx = handl_platform::EvalContext::new();
let result = capture.call(&[json!(1)], &mut ctx).unwrap();
assert_eq!(result, json!(42));
assert_eq!(capture.calls(), vec![vec![json!(1)]]);

handl_test_utils::MockEvalRule ​

Struct

A Behavior<Eval> rule for testing that returns a configurable value.

The rule matches a specific AstNode.kind (set at construction) and, on apply, writes the configured result into req.result. This lets tests exercise BasicEvaluator dispatch without writing a one-off rule struct.

ignore
use handl_test_utils::MockEvalRule;
use handl_platform::{BasicEvaluator, CapabilityRequest, PluginContext,
    PluginRegistry, KitRegistry, EvalBehavior};
use serde_json::json;
use std::sync::Arc;

let mut evaluator = BasicEvaluator::new();
evaluator.accept(Arc::new(MockEvalRule::new("echo", json!(42))) as Arc<dyn EvalBehavior>).unwrap();

handl_test_utils::MockExecControl ​

Struct

An [ExecControl] for testing that counts before_eval / after_eval invocations.

Each hook always returns [ControlFlow::Continue] (i.e. it never blocks or short-circuits dispatch). Use the before_count / after_count accessors to assert how many times each hook fired.

ignore
use handl_test_utils::MockExecControl;
use std::sync::Arc;

let control = Arc::new(MockExecControl::new());
assert_eq!(control.before_count(), 0);

handl_test_utils::SendSyncFunction ​

Struct

A configurable [Module] for testing.

Built via a builder API:

ignore
use handl_test_utils::{MockModule, MockFunction};
use handl_platform::{EvalContext, EvalError, Function};
use serde_json::{Value, json};

let add = MockFunction::new("add", |args, _ctx| {
    let a = args[0].as_i64().unwrap();
    let b = args[1].as_i64().unwrap();
    Ok(json!(a + b))
});
let module = MockModule::new("math").with_function("add", add);
assert_eq!(module.name(), "math");
assert!(module.function("add").is_some());
assert!(module.function("sub").is_none());

A wrapper around Arc<dyn Function + Send + Sync> that implements Function (without Send + Sync in the trait object), so it can be returned as &dyn Function from Module::function. The wrapper itself is Send + Sync because the inner Arc is.

Tuple Struct: (std::sync::Arc<dyn Function>)

Module: conformance ​

Conformance test harness for hnl-engine-* engines (ADR-0044).

Conformance test harness ​

Shared conformance test infrastructure for hnl-engine-* engines (ADR-0044 testing strategy). Contains:

  • [corpus] — (Language, Ast, expected Value) and (Language, Tokens, expected Ast) triples as data.
  • [run] — harness functions that run the corpus against any eval or parse engine.

Every eval engine crate runs the full eval conformance suite; every parse engine crate runs the full parse conformance suite. A divergence is a test failure.
