Module: collections ​

collections ops — native atoms for the collections package.

Ported verbatim from the deleted plugin-lib-collections crate:

  • [seq] — the shared sequential-container ops (new/from/ to_array). The len/is_empty/push/pop/peek surface and the end-parameterized members used by vec, list, queue, stack, and deque are now pure handl (see handl-packages/collections/{vec,list,queue,stack,deque}.hnl); the pop/peek/dequeue/pop_*/peek_* contract requires raising collection is empty on an empty structure, which is now expressible via the error.raise primitive (handl-packages/error/error.hnl). new stays native because it is nullary and from is a reserved word (it cannot be a record field); to_array stays grouped with them.
  • [array] — the array.* functional ops that take handl arrows (take_while/drop_while/scan/foldr/find_*): arrow arguments cannot cross the HandlFunction boundary, so they evaluate the serialized [crate::function_value::FunctionValue] body through EvalContext::eval_expr natively. The arrow-free array.* surface lives in handl-packages/collections/array/index.hnl as pure handl.
  • [hash_map] — the hash_map.* object ops. Native because handl has no object-key-iteration primitive (merge/pick/omit/invert need to enumerate a record's fields) and several members take arrow arguments.
  • [hash_set] — the hash_set.* set ops. Native because membership is keyed on a serialized value (value_key), which distinguishes 1 from 1.0 and differs from handl == (cross-numeric equality); a pure-handl port would change dedup semantics for mixed int/float inputs. unique_by additionally takes an arrow.

[collections_op_registry] registers every op name under its full module.fn name (matching the former build_registry); the [CollectionsModule] aggregator preserves the former collections-module lookup shape (vec.new, collections.vec.new).

Module: math ​

Rust Function impls for the math module — the handls (handlers) for the op/handl declarations in math.hnl.

All 62 functions are FFI atoms: they call f64 methods or Rust arithmetic that cannot be expressed as pure handl arrows without losing the exact TypeMismatch error messages the tests rely on. The op/handl declaration form (ADR-0077 Phase 2) declares the interface in math.hnl; these impls provide the logic and are registered in an OpRegistry.
