Module: eval ​

Generic evaluation operation and rule acceptor. Generic evaluation operation and BasicEvaluator rule acceptor.

This module defines the Eval operation, EvalBehavior trait, and a default BasicEvaluator RuleAcceptor plugin. The BasicEvaluator has no knowledge of concrete language builtins; it dispatches to registered EvalBehavior rules keyed by AstNode.kind.

Unlike other operations, Eval carries an [EvalContext] inside the [EvalRequest]. The context holds variable scopes, resource limits, a call counter, and an [EvaluatorCallback] handle that lets recursive rules evaluate child AST nodes by calling req.ctx.eval(&child).

Exec-control cross-cutting concerns (limits, tracing, caching, sandboxing) are handled by the lightweight [ExecControl] two-hook trait, invoked by BasicEvaluator before and after each dispatch.

Module: format ​

Generic format operation and rule acceptor. Generic format operation and BasicFormatter rule acceptor.

This module defines the Format operation, FormatBehavior trait, and a default BasicFormatter RuleAcceptor plugin. The BasicFormatter has no knowledge of concrete surface syntax; it dispatches to registered FormatBehavior rules keyed by AstNode.kind.

Role after ADR-0095 ​

The canonical formatter is the staged engine pipeline in hnl-engine-fmt (layout → render → post-process), surfaced by handl-plugin-ext-fmt (format_source/check_source/format_ast). Those crates depend on this crate, so platform cannot dispatch to the engine here (dependency direction). This Format capability therefore remains the generic per-node contribution seam of ADR-0014/ADR-0029: hosts and kits register FormatBehavior rules for individual node kinds. It is not the canonical formatting path — that is FormatEngine/plugin-ext-fmt. Keeping the two honest (documented) avoids a disconnected facade.
