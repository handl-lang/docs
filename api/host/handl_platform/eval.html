handl_platform::eval::AsyncFunction ​

Trait

A callable host function that supports async execution.

This is the async counterpart of [Function], per ADR 0040's "Async evaluation" section. Functions that perform IO-bound work (HTTP, WebSocket, timers, sockets) implement this trait so they can be awaited from [EvalContext::call_function_async] without blocking the calling thread.

A type can implement both [Function] and [AsyncFunction]: the sync call is used by [EvalContext::call_function], and call_async is used by [EvalContext::call_function_async]. To make the async path visible to the lookup machinery, the [Function::as_async] override must return Some(self).

The returned future is Pin<Box<dyn Future + 'a>> — single-threaded (consistent with [EvalContext]'s Rc-based handles), no Send bound.

Methods:

  • call_async: Invoke the function asynchronously.

handl_platform::eval::ControlFlow ​

Enum

Control flow outcome from an [ExecControl::before_eval] hook.

Continue lets dispatch proceed to the matching Behavior<Eval> rule. Skip(value) short-circuits dispatch: value becomes the result and no behavior rule runs (after-hooks still fire). This is how the cache plugin returns a cached result without re-executing.

  • Skip(serde_json::Value) - Skip dispatch and use value as the result.

handl_platform::eval::ExecControl ​

Trait

Lightweight execution-control hook invoked before and after each dispatch.

Exec-control concerns (limits, tracing, caching, sandboxing) are handled by this two-hook trait rather than a full middleware wrapping trait. Eval is the only operation with cross-cutting execution concerns, so this one deviation from the uniform Behavior pattern is justified (see ADR 0040).

BasicEvaluator calls all registered ExecControl rules before and after each dispatch. When none are loaded the overhead is a zero-length slice iteration.

before_eval receives a &mut AstNode so that rewriting rules (e.g. the map plugin) can mutate the node in place before dispatch. Returning [ControlFlow::Skip] short-circuits dispatch with a precomputed result (used by the cache plugin).

A callable host function, non-generic per ADR 0040.

Functions live in modules and are looked up by qualified name (e.g. math.add) via [ModuleLookup]. The call method receives the already-evaluated JSON arguments and a mutable [EvalContext] so the function can itself recurse (ctx.eval, ctx.call_function) or inspect variable bindings.
