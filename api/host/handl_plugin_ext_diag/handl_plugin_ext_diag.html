handl_plugin_ext_diag::StatementChunk ​

Struct

A top-level statement chunk: its trimmed text and byte offset in the original source.

The v0.1 Pratt parser parses a single statement per call, so tools that operate on whole files split the source into statements first. This is the single shared implementation of that split (previously each of the typechecker, linter, and test runner carried a private copy that had diverged).

Fields:

  • text: String - The trimmed statement text.
  • offset: usize - Byte offset of the trimmed text's first byte in the original source.

handl_plugin_ext_diag::split_statements ​

Function

Split src into top-level statement chunks.

The v0.1 surface separates top-level declarations by newlines or semicolons. Splits at bracket-depth zero, respecting string literals and -- comments. A -- comment that begins at a statement boundary (only whitespace precedes it in the pending chunk) is dropped entirely; a comment inside or trailing a statement is left in the chunk text — the lexer strips it at parse time. This is what keeps a -- line inside a { ... } block from truncating the in-progress statement.

Newlines are whitespace to the grammar, so a depth-0 \n is only a candidate boundary: it is not a split point when the pending chunk ends mid-expression (last significant char is an operator — no Handl statement ends with one) or when the following line cannot begin a statement (starts with =, a closer, an infix operator, …). ; is always a hard separator.

rust
fn split_statements(src: &str) -> Vec<StatementChunk>
