handl_plugin_module::ModuleRegistry ​

Struct

A registry of [Module]s providing qualified function lookup.

ModuleRegistry implements [ModuleLookup]. It splits a qualified name on the first .: the left segment is the module name, the right segment is the function name within that module. For example, math.add resolves to module "math", function "add".

If the name contains no ., the registry searches all modules in registration order and returns the first match. This allows flat names (e.g. add) to coexist with qualified names (e.g. math.add).

Architecture ​

text
       ModuleRegistry
           │
           │ lookup("math.add")
           ▼
     split on "."
      ┌────┴────┐
      ▼         ▼
  "math"     "add"
      │         │
      ▼         ▼
   Module    Function

The eval layer sees only the [ModuleLookup] interface — it does not know about modules.

A [Contribution] that registers a single [Module] with a [ModuleRuntime] [RuleAcceptor].

handl_plugin_module::ModuleRuntime ​

Struct

A [Plugin] + [RuleAcceptor] that accepts [ModuleRule] contributions and provides function lookup via the accumulated [ModuleRegistry].

Ported from plugin-vm-common::host::host::ModuleRuntime. The old ModuleRuntime implemented the VM's CallableLookup<V> trait; this new version implements the platform's non-generic [ModuleLookup] trait instead. Hosts register a ModuleRuntime plugin, library plugins contribute ModuleRules into it, and the host wires the runtime's registry into EvalContext via set_modules.

Example ​

ignore
use std::rc::Rc;
use handl_platform::{DefaultHost, ModuleLookup};
use handl_plugin_module::{ModuleRuntime, ModuleRule, ModuleRegistry};

let mut host = DefaultHost::default();
host.register_plugin(ModuleRuntime::new());
// ... library plugins contribute ModuleRule(MyModule) ...
host.load();
let runtime = host.plugins_mut().get_plugin_mut::<ModuleRuntime>().unwrap();
let registry: Rc<dyn ModuleLookup> = Rc::new(runtime.registry().clone());
