handl_plugin_ext_kit::KitModuleNames ​

Type Alias: std::sync::Arc<dyn Fn>

Resolves a built-in kit name (e.g. "stdlib", "server") to its flattened, ordered library-module names — following the manifest's extends chain.

Injected by the host (ADR-0128 §"The 0.8 seam"): the embedded kit manifests live in handl-kit-data-prelude (the lang/ repo), which this crate must not link. A host wires handl_kit_data_prelude::kit_module_names in as a capture-less closure; other languages supply their own manifest tables.

handl_plugin_ext_kit::ModuleKit ​

Struct

A kit plugin assembled from a data manifest: the module-runtime host plus an ordered set of library module plugins resolved from a [LibraryRegistry].

ModuleRuntime is registered concretely (not boxed) because rule contribution resolves acceptors by concrete type via get_plugin_mut::<ModuleRuntime>; the remaining library modules are registered as boxed plugins in manifest order, so the host's fixed-point load calls their contribute exactly as the hand-written kits did.
