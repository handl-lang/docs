handl_plugin_sdkgen::pick_doc ​

Function

Resolve a single doc slot from the three doc layers: hand-written overrides, a comment already captured into the slot, then an external [DocSource].

keys are candidate override keys in priority order (e.g. a record field tries record.field); the highest-priority override wins, and the first key with no override stops at the in-source comment. external_key is the key handed to source — None disables external resolution for slots that are not queryable symbols.

Module: targets ​

Named sdkgen targets — the link-time registry ADR-0128 puts behind hnl sdkgen <name> (§"Registration: link-time first").

A target is a data record — name, accepted flags, a backend id, an emitter id, an optional doc pass, an optional non-backend spec input — not a code path in the CLI extension. Modules in the target repos (c/modules/sdkgen-c, web/modules/sdkgen-webidl, python/modules/sdkgen-python, …) each export a register function that populates a [SdkgenRegistry]; plugin-ext-sdkgen parses the CLI and collapses to a lookup over it.

The registry key is deliberately a name: a target composes a backend and an emitter that may come from different repositories — hnl sdkgen python is backend: "c" + emitter: "python", so the python repo depends on c/'s module at resolution time, never at the crate level. A missing component is a link-time error message, not an unresolved import.
