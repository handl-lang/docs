handl-plugin-lib-tag ​

The tagged-values capability as a composable plugin-lib-* leaf crate (ADR-0055 — Tagged Values).

Tagged values are the host primitive that lets the typechecker, units, capabilities, and provenance share one value space without collision (ADR-0032 "types are values"). A tagged value is a JSON object {"__tag__": <name>, ...payload} minted by the host. Tagging is a host capability, not a user-constructible convention: the __tag__ key is reserved (the eval engines reject it in user object literals), so the only way a value acquires a __tag__ key is through this plugin's tag.tag host function. User code cannot forge a tagged value.

This crate has been migrated to the op/handl declaration form (ADR-0077 Phase 4). The tag interface is declared in handl-packages/tag/tag.hnl via op declarations, and the Rust tag/match/inspect logic is registered as handls (handlers) in an [OpRegistry]. The [TagLibraryPlugin] wraps the generic [HandlLibraryPlugin] with the op registry, eliminating the per-library Module/Plugin trait scaffolding.

This crate exposes the tag module with four callables — inspection and dispatch only; the __tag__ mint producers (tag.tag, tag.construct) were deleted with the __tag__/{tag} bridge (ADR-0152 §Migration):

CallableRole
tag.untag(v)return the payload of a tagged value (inspection)
tag.tag_of(v)return the tag name of a tagged value (inspection)
tag.is_tag(v)test whether v is a tagged value (inspection)
tag.match_type(v, cases)dispatch on the type tag of v (ADR-0054)

tag.match_type is the user-facing surface of the ADR-0054 judgment op match_type, backed by a [TypeRegistry] with registry id "handl.canonical".

Tagged values are still produced internally (law/rewrite/cell records); the inspection ops are available to any code that holds one — matching the capability discipline of ADR-0055 §1. Tag dispatch on __tag__ identity is handled by the native match construct via tag patterns (ok(v) => ...), not a dedicated op (ADR-0077).

The [TypeRegistry] (in [registry]) is the type system machinery, not a callable — it is kept in Rust as pure data.

The [TagModule] re-export is preserved for backward compatibility with downstream crates (e.g. [kit-canonical]) that register TagModule directly.
