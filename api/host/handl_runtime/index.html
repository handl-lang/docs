handl_runtime ​

handl-runtime ​

Binds a [Language] to engine impls and exposes staged lex/parse/eval plus compile/run_compiled over a Language + stage inputs (ADR-0044 §3, §7; ADR-0047 §2).

A [Runtime] owns a [Language] and optional engine impls for each stage (lex, parse, eval) plus a map of compile engines. Each stage dispatches to its bound engine or returns [LangError::NotImplemented] if no engine is attached. This enables eval-only runtimes (a JIT/cranelift runtime that compiles a pre-parsed [Ast]) as well as full lex → parse → eval pipelines.

Registry-based engine selection (ADR-0047 §2) ​

Engine selection is registry-based, not a hardcoded from_config match. The host populates an [EngineRegistry] — a name→engine map — and [Runtime::from_registry] resolves the [RuntimeConfig] names against it. handl-runtime names no engine impl crate; the engine impls (hnl-engine-lex-pattern, hnl-engine-parse-pratt, hnl-engine-exec-tree-walk, hnl-engine-exec-bytecode, hnl-engine-exec-cranelift) are deps of the host, which registers them. Adding an engine = register it; no handl-runtime edit.

[RuntimeConfig] carries engine names as strings (e.g. "pratt", "tree-walk"); an empty string leaves that stage unbound. Unknown non-empty names return [LangError::Engine].

RuntimeFactory / RuntimeHandle (ADR-0047 §2) ​

The [RuntimeFactory] / [RuntimeHandle] trait pair lets (future) plugin-lib-lang-* leaf crates depend on handl-runtime without reaching up to engines: a leaf holds a &dyn RuntimeFactory injected by the host, calls factory.build(lang, delegate) to obtain a Box<dyn RuntimeHandle>, and dispatches lex/parse/eval/compile/run_compiled through it. [Runtime] implements both traits; the factory re-injects the meta functions into the sub-runtime itself, breaking the cycle.

compile / run_compiled via CompiledHandle + CompiledArtifact (ADR-0047 §3) ​

Runtime::compile(ast, target) asks the registered [CompileEngine] for target to produce a Box<dyn CompiledArtifact>, stores it in the thread-local [COMPILED_REGISTRY], and returns a serializable [CompiledHandle]. Runtime::run_compiled(handle) looks up the artifact and runs it. The non-serializable artifact never crosses the trait boundary; only the serializable handle does. The CompileEngine / CompiledArtifact impls live in the engine crates (hnl-engine-exec-bytecode, hnl-engine-exec-cranelift), not here.

Dyn-compatibility note ​

[ParserEngine] is not dyn-compatible (its expression method references Self via [ParserContext]). The [ParseEngineDyn] wrapper trait exposes only the dyn-compatible parse method, allowing parse engines to be stored as trait objects. [LexerEngine] and [EvalEngine] are already dyn-compatible and need no wrapper.
