handl_runtime::exec_erasure_pass::apply_exec_erasure ​

Function

Apply the "exec-erasure" transform pass to ast, returning the runnable arena (ADR-0154 §6).

Delegates to [RewriteEngine::run_pass] — the rules themselves are language data (lang.transforms), so languages extend erasure by declaring rules, not by editing this pass. The output arena is then compacted through [Ast::subtree] so unreachable erased subtrees are dropped and the root is the last node (Pratt convention).

Only declarative rules (!Declarative/!Replace) are wired — a !Native rule in this pass fails loudly (no silent fallthrough, per ADR-0094); hosts needing natives run [RewriteEngine] themselves with a wired registry.

Errors ​

Returns [LangError] when a transform rule fails — e.g. a Replace path that does not resolve to a descendant.

handl_runtime::exec_erasure_pass::has_exec_erasure_rules ​

Function

Whether lang declares any exec-erasure rules.

When no rules are declared the pass is a pass-through and [apply_exec_erasure] returns the arena unchanged (fast path — most test Languages carry no transform fragments).

handl_runtime::exec_erasure_pass::prepare_exec_artifact ​

Function

Prepare the final runnable artifact (ADR-0154 §6).

Composes the two halves of erasure: the "exec-erasure" transform pass strips type-level positions ([apply_exec_erasure]), then artifact_lint::check_exec_artifact asserts the invariant — only 1-arrows + runtime values remain. Anything the pass could not consume (a stuck-but-referenced term is live code DCE cannot remove) becomes a diagnostic, not silent unsafety.

Called by every [crate::Runtime] entry point that dispatches an artifact to an exec/compile engine (eval, eval_with_globals, eval_shared_*, compile), so "type-level positions erase at exec" holds uniformly across exec engines.

Errors ​

Returns [LangError] when a transform rule fails or the artifact lint finds residual type-level content.
