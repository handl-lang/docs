handl_runtime::Runtime::eval ​

Function

Evaluate an [Ast] into a [Value].

First tries lowering the canonical AST to a Term and running the small Term interpreter. If the lowerer does not support the file, it logs a warning and falls back to the bound eval engine. If lowering succeeds but the Term interpreter cannot handle the term, it falls back to the bound eval engine so existing surface constructs (including test-only forms like keyword assert) keep working.

Errors ​

Returns [LangError::NotImplemented] if no eval engine is bound, or propagates the engine's error.

Exec-transform erasure + artifact lint (ADR-0154 §6) ​

Before dispatch, the AST runs through [exec_erasure_pass::prepare_exec_artifact]: the "exec-erasure" pass strips type-level positions (e.g. type-annot → its subject, generalizing ADR-0151's scheme-level erasure), and the artifact lint asserts only 1-arrows + runtime values remain. A stuck former application / metavariable / undecided type-level node is a LangError diagnostic here rather than a silent no-scheme payload fallback.

handl_runtime::Runtime::eval_shared_with_globals ​

Function

Like eval_with_globals, but takes the [Ast] behind an Rc and dispatches to [EvalEngine::eval_shared], so engines that hold the arena by Rc internally (the tree-walk engine) reuse the caller's allocation instead of deep-cloning it into an [EvalRequest].

This is the per-call seam for hosts that cache a parsed AST and re-evaluate it many times with different globals — e.g. plugin-lib-handl's HandlFunction bridge.

Errors ​

Returns [LangError::NotImplemented] if no eval engine is bound, or propagates the engine's error.

handl_runtime::Runtime::eval_with_globals ​

Function

Evaluate an [Ast] like [Runtime::eval], but with globals injected as additional root-scope variables for this call only.

The eval engine is cloned (via [EvalEngine::box_clone] + [EvalEngine::with_global]) so the runtime's engine is unchanged; this is the per-call "bind arguments into the env" seam used by hosts that need to pass values (e.g. closures, tagged values) into a nested evaluation rather than serializing them into source text.

Errors ​

Returns [LangError::NotImplemented] if no eval engine is bound, or propagates the engine's error.

handl_runtime::Runtime::from_registry ​

Function

Build a [Runtime] from a [Language], an [EngineRegistry], and a name-based [RuntimeConfig] (ADR-0047 §2).

Resolves config.lex / config.parse / config.eval (strings) against registry. An empty string leaves that stage unbound (None). A non-empty unknown name returns [LangError::Engine]. All compile engines in the registry are cloned into the runtime (compile is multi-target, selected per compile call).

Errors ​

Returns [LangError::Engine] for any unknown engine name.

handl_runtime::Runtime::from_registry_with_resolver ​

Function

Like [from_registry_with_globals] but also wires an [ImportResolver] into the eval engine for import "path" statements and records a module_root for relative path resolution (Phase 9.5).

The resolver is passed to the eval engine via [EvalEngine::with_import_resolver] (engines that support imports override it; others ignore it). The runtime also stores the resolver so its own [ImportResolver] impl can delegate to it, and stores module_root for path resolution.

handl_runtime::Runtime::parse ​

Function

Parse a token stream into an [Ast] using the bound parse engine, then run the "desugar" transform pass.

Errors ​

Returns [LangError::NotImplemented] if no parse engine is bound, or propagates the engine's error.

Desugar pipeline (ADR-0082, Option A) ​

The desugar pass runs at parse time for the exec pipeline: Runtime::parse (this method) is parse_raw + [desugar_pass::apply_desugar], so eval/run never observe raw data/while/for/nullish/opt-chain nodes. data declarations (ADR-0082) are rewritten into block definitions (predicate + constructors + recursor) by desugar_data.

The typecheck pipeline is the exception: run_checked and Kit::typecheck* feed the checker the raw AST from parse_raw — the type model is authored against source-level shapes, then the same raw AST is desugared for eval (see run_checked).

fn parse(self: &Self, toks: &Tokens) -> Result<Ast, LangError>

handl_runtime::Runtime::parse_raw ​

Function

Parse a token stream into an [Ast] using the bound parse engine, without running the desugar pass.

This is the source-level AST: surface forms (data, match, while, for, nullish, opt-chain, type-annot annotation positions, dim_arrow/axis_flow sugar) remain as parsed. The typecheck pipeline consumes this form — the NBE checker's type rules and judgments (synth_data, synth_match_arms, synth_assign, synth_dim_arrow, …) are written against source shapes, and the desugared output mints internal nodes (lit__sym__ payloads, __former__/__ctor__ objects, recursor folds) that have no typing rules by design.

Use parse for the exec pipeline (eval/compile): the evaluator only understands the desugared core forms.

Errors ​

Returns [LangError::NotImplemented] if no parse engine is bound, or propagates the engine's error.

handl_runtime::Runtime::run_checked ​

Function

lex → parse → typecheck → desugar → eval (ADR-0054, Phase 10.1).

Like [Runtime::run], but inserts a typecheck stage between parse and eval. The checker consumes the raw (source-level) AST — the type model is authored against surface shapes (data, match, type-annot, dim_arrow), while the desugared output mints rule-less internal nodes (lit __sym__ payloads, __former__ objects). After checking, the same raw AST runs the runtime-assert and proof-erasure rewrites (their node_types indices refer to the checked arena), then desugars for eval.

If the typecheck engine reports any Severity::Error diagnostics (or returns Err), eval is short-circuited and the error is returned immediately — surfacing type errors as compile-time diagnostics rather than runtime crashes or silent wrong results. Warnings and info-level diagnostics do not block eval.

If no typecheck engine is bound (self.typecheck_engine is None), this falls through to plain lex → parse → eval (it does not fail) — the engine may simply not be configured.

Errors ​

Propagates the first stage error. A typecheck error is returned as [LangError::Engine] carrying the first error diagnostic's message.

handl_runtime::Runtime::run_compiled ​

Function

Run a previously compiled program referenced by handle (ADR-0047 §3).

Looks up the [CompiledArtifact] in the [COMPILED_REGISTRY], clones it out under a short-lived borrow (so re-entrant compile / run_compiled calls don't panic), then executes it with this runtime's module registry attached (so Foreign dispatch — including the meta host functions — resolves).

Errors ​

Returns [LangError::Engine] if the handle is unknown, or propagates the artifact's execution error.
