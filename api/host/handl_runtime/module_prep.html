handl_runtime::module_prep::graded_arrow_is_signature ​

Function

Whether a depth-0 ~[ at byte tilde opens a graded-arrow signature Type ~[1]~> Type (erase) rather than a genuine n-cell value f ~[N]~> g (keep) — the export alpha := f ~[2]~> g footgun this guard used to erase to null. Corpus sweep (every ~[ across lib-/kit-/handl-packages, ~7,200 sites): all signatures grade ~[1]~>, and every ~[2]~>+/~[N]~> is a cell term (the effects/optimize law exports, lib-type's dependent unit/counit). So:

  • any grade other than the literal 1 → a cell value, keep;
  • grade 1 → the domain operand decides: a signature's domain is a type expression — a parenthesized params (...), a record {...}, a bare list type [T], or a Capitalized type head (Int, Result<A, B>, T). A lowercase/literal/index-led LHS (f, map inc, "a >>> b", xs[i]) is a value expression → a cell, keep.

Documented limits (no corpus instance today): a grade-1 cell over a parenthesized domain (f >>> g) ~[1]~> h still erases; a grade-1 signature over lowercase type vars a ~[1]~> b now evals (a loud unbound-name error) rather than binding null; a symbolic grade (A ~[n]~> B contract) is kept and evals — none exist outside comments.

rust
fn graded_arrow_is_signature(rhs: &str, tilde: usize) -> bool

handl_runtime::module_prep::host_import_bindings ​

Function

Lower a host-module import declaration to (local_name, expr, exported) binding triples whose expr is the qualified-name string literal "spec.name" — a string callee dispatches through call_host → the module chain, mirroring the ambient spec.name(x) dotted form.

  • from "spec" import a, b as x / import { a, b as x } → a := "spec.a", x := "spec.b"
  • from "spec" import * as m → m := "spec"
  • from "spec" export a, b → exported a := "spec.a"
  • import <name> / import <name> from "spec" → name := "spec"
  • import "<spec>" (side-effect only) → nothing

Only bare module-name specs ("bytes", "str") produce spec.name bindings — a host module is registered under its plain name. A path-like spec ("../index", "math/add", "x.hnl") that failed file resolution is a decorative declaration, not a module name: "../index.len" can never dispatch. Those names are left unbound so they keep ambient semantics — an unbound list evaluates to "list", which is exactly what list := "list" would bind anyway.

rust
fn host_import_bindings(line: &str) -> Vec<(String, String, bool)>

handl_runtime::module_prep::is_signature_rhs ​

Function

Whether rhs is a top-level arrow signature — contract data whose domain/codomain are type expressions that exec must not evaluate (Agda-style erasure; annotations are static metadata owned by the typecheck engine). Two shapes, both un-callable at runtime:

  • a grade-1 signature arrow Type ~[1]~> Type (~[ at bracket depth 0, distinguished from n-cell value exports like export alpha := f ~[2]~> g by [graded_arrow_is_signature]) — always mints an Arrow descriptor record, and codomains like Result<T, E> are generic applications (dimension nodes) that crash eval;
  • an ungraded arrow (…, [T], …) ~> B whose parenthesized params contain a bare [ element (a list type [String] — never preceded by : like a x: [T] annotation, nor part of an index expression) — closure only binds var/type-annot params, so the ~> can only ever be a signature.

Erasing binds null — the same value type-only export Name: Type gets — losing no runtime behavior. Real arrow literals (export f := (x) ~> body, export f := (x: [Int]) ~> body) and n-cell value exports (export alpha := f ~[2]~> g) are untouched.

rust
fn is_signature_rhs(rhs: &str) -> bool

handl_runtime::module_prep::prepare_module ​

Function

Prepare a module source for evaluation: strip comments and declarations, then rewrite top-level export declarations into a single object literal.

is_file_spec reports whether an import specifier resolves to a file — those are the executable import op (ADR-0096) and must survive prep. Specifiers naming host modules (from "str" import …, import <name>) are decorative declarations and are dropped.

is_bindable reports whether a name can be a := binding target — i.e. lexes as token.identifier, not a keyword like first. Keyword names can't be bound; their export field carries the expression inline under a quoted record key ({ "first": expr }).

Returns an error when a top-level export declaration cannot be transformed (e.g. export with no binding separator) — a declaration that would previously vanish into an empty module record.

rust
fn prepare_module(src: &str, is_file_spec: &dyn Fn, is_bindable: &dyn Fn) -> Result<String, handl_language::LangError>

handl_runtime::module_prep::top_level_segments ​

Function

Split a module source into its top-level statements, returning each statement's verbatim text (internal newlines and indentation preserved) in source order.

The module surface has no layout-sensitive constructs, so a statement boundary is recognized purely by structure — never by a hardcoded line shape:

  • ; at bracket depth 0,
  • a newline at depth 0 not followed by an indented line (an indented line continues the statement — export f := (x) ~>\n &lt;body> keeps its wrapped RHS),
  • an export/import/from keyword at depth 0 mid-statement — several statements sharing a line (from "x" import a export f := e, export a := e; export b := e2) split into their statements.

Inside a from/import statement the first import/export/from keyword belongs to that statement's tail (from "x" import a, from "x" export a, b, import a from "x") and does not split. String literals, -- line comments, and /-- … --/ block comments are tracked so keywords and brackets inside them are ignored.

rust
fn top_level_segments(src: &str) -> Vec<String>

handl_runtime::module_prep::transform_export_to_object ​

Function

Transform top-level export name <::|:=|:|=> expr declarations into an object literal. Type-only export Name: Type declarations are given the value null so that type expressions are not evaluated at runtime. The same erasure applies to signature exports export Name := A ~[N]~> B whose RHS is a bare graded-arrow signature ([is_signature_rhs]): its boundary children are type expressions that exec must not evaluate.

The source is consumed as top-level statements ([top_level_segments]) — not lines — so an export is recognized wherever a statement can begin: at column 0, indented, after ;, or mid-line after another statement; and its RHS expression is captured whole regardless of how newlines fall inside ~>-chained do {…} / if/else bodies. A separator-less export declaration is a [LangError] — declarations are never dropped silently.

rust
fn transform_export_to_object(src: &str, is_file_spec: &dyn Fn, op_names: &[String], is_bindable: &dyn Fn) -> Result<String, handl_language::LangError>
