handl-kit-data ​

The data-driven kit assembly framework for ADR-0044 Phase 5.

ADR-0044 §1 realizes that "selection and merge are the composition; the registry is replaced by a Language built from merged fragments." This crate replaces PluginRegistry-based kit assembly with a data-driven pipeline:

text
manifest → fragment sources → merge → Language + Runtime selection

A [DataKitManifest] is an ordered list of data-file fragment sources (ADR §6 end state) plus include/exclude filters and a [RuntimeConfig] for engine selection (ADR §7). A caller that already holds a [Language] — e.g. handl-kit-data-prelude::language_from_yaml — passes it to [DataKit::assemble] as base_language: the kit stack merges on top of it. The manifest-named Rust emitters of the ADR §6 migration scaffold are retired (see project/parked.yaml).

Data-file sources ​

A fragment source is a serialized [Language] on disk, read at assembly time ([FragmentSourceEntry::source]). [DataKitManifest::load] / [DataKitManifest::load_from_text] do the same for a kit manifest. Both dispatch on extension — JSON, YAML (canonical) or TOML — and fail with an error naming the file. This lets the module that owns a set of fragments or a kit manifest ship it as data instead of include_str!-pinning it into another crate (ADR-0128 §Deferred).

Include/exclude ​

Per ADR §1, include/exclude operate at the fragment level (by fragment id), not at the plugin/entry level. The assembler applies the filter during merge — fragments whose id is in exclude (or not in include when include is non-empty) are skipped. This is a real operation, not a silent no-op (ADR §5): excluding a fragment that another fragment declares replaces causes the dependent's merge to fail with [LangError::UnknownReplace], surfacing the broken override chain explicitly.

extends chain ​

A kit may declare extends: "parent-kit-name". The parent is assembled first (resolved via [KitRegistry::resolve_kit]), then this kit's fragments merge on top. Phase 5 supports one level of extends (parent → child); deeper chains are a straightforward recursive extension.

The legacy kit-config / kit-server / kit-cli / kit-hello / kit-stdlib Rust-monolith kits have been deleted — kit composition is now data-driven via the data/kits/*.yaml manifests in handl-kit-data-prelude (resolved through [LibraryRegistry] into ModuleKits). kit-canonical remains as the canonical runtime assembly.
