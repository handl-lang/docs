handl_plugin_lib_handl::transform::DESUGAR_FUNCS ​

Constant: &[&str]

The exported names of the desugar overlay module.

match_recursor is deliberately absent: the .hnl rewrite contract hands every rewrite the whole serialized arena (env.nodes), so a match-heavy AST paid a full arena serialization + conversion per match node (74 matches x ~50 ms on the 32k-node typecheck model). The Rust native keeps a once-per-pass constructor index instead, so handl:desugar.match_recursor falls through to it via delegate.

handl_plugin_lib_handl::transform::HANDL_REWRITE_ACTIVE ​

Constant: $crate::thread::LocalKey<std::cell::Cell<bool>>

Reentrancy guard: true while a handl: rewrite invocation is in flight on this thread. A nested handl: name — e.g. a match node inside the bridge runtime's own parse of the module source — resolves as unprovided so dispatch falls through to the fallback registry (the Rust natives). This preserves the invariant that .hnl rewrites never recurse through the transform engine.

handl_plugin_lib_handl::transform::HandlNativeRewrite ​

Struct

A [NativeRewrite] that resolves handl:<module>.<fn> rule names against registered [HandlModule]s and invokes the .hnl function.

Non-handl: names delegate to the optional fallback registry, so a single with_native_registry call can serve both handl-authored rules and Rust natives (e.g. desugar.*):

ignore
let natives = HandlNativeRewrite::new()
    .with_module(HandlModule::new("t", MY_HNL, &["rewrite"]))
    .with_fallback(Arc::new(desugar_native_registry()));
let engine = RewriteEngine::new().with_native_registry(Arc::new(natives));

handl_plugin_lib_handl::transform::RECORD_AS_BLOCK_HINT ​

Constant: &str

Diagnostic hint appended when a .hnl transform's return value fails the node-spec shape check. The most common cause is a record literal written without parentheses after ~> — a bare { there parses as a block body (lint.record-as-block), so the arrow silently evaluates to the last statement's value instead of the record.

handl_plugin_lib_handl::transform::realize ​

Function

Realize a returned node spec into the output arena.

{"__keep__": n} reuses the matched node's remapped child n; {"__fresh__": "hint"} mints a unique var leaf (reused for the same hint within one rule application); otherwise {kind, payload?, children?} builds a fresh node (children realized recursively, __keep__ / __fresh__ still indexing the matched node's children). Realized nodes inherit the matched node's span.

rust
fn realize(spec: &serde_json::Value, ctx: & mut hnl_engine_transform::native::RewriteCtx, fresh_counter: & mut usize, fresh_names: & mut std::collections::HashMap<String, usize>) -> Result<usize, handl_language::LangError>

handl_plugin_lib_handl::transform::realize_value ​

Function

Realize marker objects inside a spec's payload into arena indices.

A single-key { "__node__": <spec> }, { "__keep__": n | [path] }, or { "__fresh__": "hint" } value becomes the arena index of the node the spec/marker produces — this is how payload-carried child references (e.g. function.payload.body) are expressed. Other values pass through recursively (objects and arrays are walked).

rust
fn realize_value(v: &serde_json::Value, ctx: & mut hnl_engine_transform::native::RewriteCtx, fresh_counter: & mut usize, fresh_names: & mut std::collections::HashMap<String, usize>) -> Result<serde_json::Value, handl_language::LangError>
