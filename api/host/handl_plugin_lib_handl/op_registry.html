handl_plugin_lib_handl::op_registry::OpFunction ​

Struct

A callable [Function] that dispatches to a Rust handl registered in an [OpRegistry].

This is the eval-time bridge between the op/handl declaration form (ADR-0077 Phase 2) and the existing ModuleLookup dispatch. When a .hnl file declares op "base64.encode" and handl "base64.encode" = rust_base64_encode, the loaded HandlModule creates an OpFunction for each op. The OpFunction holds the op name and a shared Arc<OpRegistry>; on call, it looks up the op name in the registry and dispatches to the registered Rust Function.

This plugs into the existing eval engine without changes: the OpFunction is a regular Function stored in a Module, looked up via ModuleLookup::lookup(name).

  • registry: std::sync::Arc<OpRegistry> - The shared op registry.

handl_plugin_lib_handl::op_registry::OpRegistry ​

Struct

A thread-safe registry mapping op names to Rust Function impls (the handls), with optional runtime axiom checkers (ADR-0077 Phase 3).

This is the host-side counterpart to the op/handl declaration form (ADR-0077 Phase 2). A .hnl file declares op "base64.encode" : String -> String and handl "base64.encode" = rust_base64_encode; the host crate registers a Rust Function impl under the op name "base64.encode" via this registry. At eval time, [OpFunction] looks up the op name in the registry and dispatches to the registered Function.

In addition (ADR-0077 Phase 3), a [RuntimePredicateChecker] may be attached to an op via [OpRegistry::register_with_checker]. When present, [OpFunction::call] enforces the op's requires/guarantee axioms at the dispatch boundary: requires is checked before the call, guarantee is checked against the return value after the call.

The registry is Send + Sync and uses interior mutability only at construction time (via &mut self on [OpRegistry::register]). Once built, it is shared immutably via Arc<OpRegistry>.

  • checkers: std::collections::HashMap<String, std::sync::Arc<dyn RuntimePredicateChecker>> - Op name → optional runtime axiom checker.

handl_plugin_lib_handl::op_registry::RuntimePredicateChecker ​

Trait

A runtime checker for op axiom predicates (ADR-0077 Phase 3).

Op authors can optionally provide a checker when registering an op. If provided, the checker is called at eval time by [OpFunction::call]:

  • [RuntimePredicateChecker::check_requires] is called before the op executes, with the call args. If it returns Err, the call is rejected.
  • [RuntimePredicateChecker::check_guarantee] is called after the op executes, with the return value. If it returns Err, the result is rejected.

If no checker is registered for an op, its axioms are trusted (no runtime check is performed) — the op behaves exactly as before.

The checker is Send + Sync so it can be shared across threads via [Arc] alongside the [OpRegistry].

Methods:

  • check_requires: Check the requires predicate against call arguments.
  • check_guarantee: Check the guarantee predicate against the return value.
