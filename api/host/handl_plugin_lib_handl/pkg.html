handl_plugin_lib_handl::pkg::discover_funcs ​

Function

The callable names a .hnl source exposes, in source order.

Two shapes are recognised: per-file arrows (export <name> := …, the lib-<port>-handl convention) and a record ({ f: …, g: … }, every key at the record's top level). Comments (-- …) are ignored; a source matching neither shape yields an empty list rather than an error.

Order defs so a module comes after every sibling it imports.

A cycle — or an import of something outside the package — cannot be ordered; such modules stay in declaration order and their unresolved imports are left unwired (an import error at use time, never a build-time panic).

handl_plugin_lib_handl::pkg::record_keys ​

Function

Keys at depth 1 of the record that closes the source.

A byte scan, not a regex: it walks the source once, skipping string literals ("…", with \ escapes) and line comments (-- …), and records the span of every top-level { … } block. The last such span is the exported record. Ignoring literals matters: pred matches "*"/"?", and a value like "{" would otherwise desync the depth counter and hand back the keys of a nested record.

rust
fn record_keys(src: &str) -> Vec<String>
