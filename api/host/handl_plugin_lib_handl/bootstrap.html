handl_plugin_lib_handl::bootstrap::expand_tag_declarations ​

Function

Expand tag declarations in .hnl source into constructor bindings (ADR-0077).

Scans for tag name = Type lines, strips them from the source, and generates constructor bindings: name = _0 ~> hash_map.set({value: _0}, "__tag__", "name"). (The tag.tag mint producer was deleted with the __tag__ bridge — ADR-0152 §Migration; hash_map.set mints the same record shape.) If there are tag declarations, the remaining source is wrapped in a do { ... } block with the constructor bindings prepended.

If there are no tag declarations, the source is returned unchanged.

Example ​

Input:

text
tag ok = Value
tag err = Error

{
  result_ok: value ~> value >>> ok,
}

Output:

text
do {
  ok = _0 ~> hash_map.set({value: _0}, "__tag__", "ok")
  err = _0 ~> hash_map.set({value: _0}, "__tag__", "err")
  {
    result_ok: value ~> value >>> ok,
  }
}

fn expand_tag_declarations(src: &str) -> String

handl_plugin_lib_handl::bootstrap::graded_arrow_is_signature ​

Function

Whether a depth-0 ~[ at byte tilde opens a graded-arrow signature Type ~[1]~> Type (erase) rather than a genuine n-cell value f ~[N]~> g (keep) — the export alpha := f ~[2]~> g footgun this guard used to erase to null. Corpus sweep (every ~[ across lib-/kit-/handl-packages, ~7,200 sites): all signatures grade ~[1]~>, and every ~[2]~>+/~[N]~> is a cell term (the effects/optimize law exports, lib-type's dependent unit/counit). So:

  • any grade other than the literal 1 → a cell value, keep;
  • grade 1 → the domain operand decides: a signature's domain is a type expression — a parenthesized params (...), a record {...}, a bare list type [T], or a Capitalized type head (Int, Result<A, B>, T). A lowercase/literal/index-led LHS (f, map inc, "a >>> b", xs[i]) is a value expression → a cell, keep.

Documented limits (no corpus instance today): a grade-1 cell over a parenthesized domain (f >>> g) ~[1]~> h still erases; a grade-1 signature over lowercase type vars a ~[1]~> b now evals (a loud unbound-name error) rather than binding null; a symbolic grade (A ~[n]~> B contract) is kept and evals — none exist outside comments. Mirrors handl_runtime::module_prep::graded_arrow_is_signature.

fn graded_arrow_is_signature(rhs: &str, tilde: usize) -> bool

handl_plugin_lib_handl::bootstrap::is_signature_rhs ​

Function

Whether rhs is a top-level arrow signature — contract data whose domain/codomain are type expressions that exec must not evaluate (Agda-style erasure; annotations are static metadata owned by the typecheck engine). Signature exports (export Run := (Params) ~[1]~> Codomain) mint an Arrow descriptor record — never a callable — and codomains like Result<T, E> are generic applications (dimension nodes) that crash eval, so the binding erases to null (the same value type-only export Name: Type gets). A depth-0 ~[ is only a signature when [graded_arrow_is_signature] holds — an n-cell value export like export alpha := f ~[2]~> g is kept. Ungraded A ~> B is untouched unless its params carry a bare list/record type (closure binds only var/type-annot params, so (…, [T], …) ~> B can only be a signature). Mirrors handl_runtime::module_prep::is_signature_rhs.

fn is_signature_rhs(rhs: &str) -> bool

handl_plugin_lib_handl::bootstrap::parse_cap_declarations ​

Function

Parse cap declarations from a .hnl source string (ADR-0077 Phase 5).

Scans each line for the top-level cap "name" form, extracting the quoted capability name. Comment lines (-- ...) are skipped. Lines that do not match the cap form are silently ignored (resilient parsing).

This is a lightweight line-based scan that avoids a dependency on plugin-ext-refinement (which is inference-side). It mirrors the parse_cap_line logic in arrow_parser.rs.

Example ​

use handl_plugin_lib_handl::parse_cap_declarations;

let src = r#"
cap "fs.read"
cap "fs.write"
op "fs.read" : Path -> Bytes
"#;
let caps = parse_cap_declarations(src);
assert_eq!(caps, vec!["fs.read".to_string(), "fs.write".to_string()]);

fn parse_cap_declarations(src: &str) -> Vec<String>

handl_plugin_lib_handl::bootstrap::strip_declaration_lines ​

Function

Strip cap/op/handl declaration lines (and their indented continuation lines) from a .hnl source, leaving only the handl logic.

This is the companion to [strip_comment_lines]: strip_comment_lines removes --/--- comment lines, while this function removes the ADR-0077 declaration forms (cap "...", op "..." : ..., handl "..." = ...) and their indented continuation lines (guarantee:, requires:, termination:). Together they prepare a .hnl source for evaluation as a bare handl expression.

This is necessary because .hnl files may now contain cap/op/handl declarations (ADR-0077) alongside the handl logic. The [HandlModule] evaluates the source as a single handl expression, so declaration lines (which are not valid handl expressions) must be removed first.

Example ​

use handl_plugin_lib_handl::strip_declaration_lines;

let src = r#"cap "hello.greet"
op "hello.greet" : String -> String
  guarantee: True
name ~> "Hello, " + name + "!"
"#;
let cleaned = strip_declaration_lines(src);
assert!(!cleaned.contains("cap"));
assert!(!cleaned.contains("op "));
assert!(cleaned.contains("name ~>"));
rust
fn strip_declaration_lines(src: &str) -> String

handl_plugin_lib_handl::bootstrap::top_level_segments ​

Function

Split a module source into its top-level statements, returning each statement's verbatim text (internal newlines and indentation preserved) in source order.

Mirrors handl_runtime::module_prep::top_level_segments. A statement boundary is recognized purely by structure — never by a hardcoded line shape:

  • ; at bracket depth 0,
  • a newline at depth 0 not followed by an indented line (an indented line continues the statement — export f := (x) ~>\n &lt;body> keeps its wrapped RHS),
  • an export/import/from keyword at depth 0 mid-statement — several statements sharing a line (from "x" import a export f := e, export a := e; export b := e2) split into their statements.

Inside a from/import statement the first import/export/from keyword belongs to that statement's tail (from "x" import a, from "x" export a, b, import a from "x") and does not split. String literals, -- line comments, and /-- … --/ block comments are tracked so keywords and brackets inside them are ignored.

rust
fn top_level_segments(src: &str) -> Vec<String>

handl_plugin_lib_handl::bootstrap::transform_export_to_object ​

Function

Transform top-level export name = expr declarations into an object literal { name: expr, ... } so the source evaluates to a record of exported functions.

The source is consumed as top-level statements ([top_level_segments]) — not lines — so an export is recognized wherever a statement can begin: at column 0, indented, after ;, or mid-line after another statement; and its RHS expression is captured whole regardless of how newlines fall inside ~>-chained do {…} / if/else bodies. A declaration that cannot be transformed (an export with no ::/:=/:/= separator, or an empty binding name) panics — a module prep must never silently drop an export into an empty record (mirrors handl_runtime::module_prep's LangError).

When the source contains top-level import/from statements they are hoisted -- in original order -- ahead of the record literal inside a do { ... } block, so the runtime can evaluate them (prim_import) and bind their names for the record. This is required because the (source).func(args) applied form needs a single expression; a bare import statement followed by a record is not one.

If no export statements are found and there are no imports, the source is returned unchanged (the existing object-literal form is preserved).

fn transform_export_to_object(src: &str) -> String
