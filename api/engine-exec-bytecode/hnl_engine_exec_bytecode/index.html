hnl_engine_exec_bytecode ​

hnl-engine-exec-bytecode ​

The bytecode eval engine for the eval operation (ADR-0044 §4, §7).

This engine compiles [handl_language::Term] (the v2 arrow-calculus kernel, ADR-0052) data to a bytecode representation and executes it via a stack-based VM. It shares the same Term vocabulary as the hnl-engine-exec-tree-walk reference interpreter (a dev-dependency); conformance tests verify both produce identical results.

Compilers erase data dispatch (ADR-0044 §7) ​

The tree-walk pays for per-node scheme lookup (lang.eval[node.kind] → Term) on every execution. The bytecode engine compiles this lookup away: at compile time, every node kind's scheme is resolved to a fixed instruction sequence. The compiled artifact has no hash lookups, no string matching, no lang.eval access at execution time.

A per-node compilation cache (compile each node's scheme once, cache by [AstRef]) is used to demonstrate this. When [Instr::EvalChild] runs, it looks up the child's AstRef in the cache; on a miss, it compiles the child's scheme (one-time lang.eval lookup) and caches the result. On subsequent executions, the cached instructions are reused — no data dispatch occurs. Full ahead-of-time compilation of the whole AST is a future refinement.

Bytecode ISA ​

See the [instr] module for the full instruction set documentation. The ISA covers all six Term combinators (Arr, Seq, First, Choice, Loop, App); see the [instr] module's combinator-to-instruction mapping table for details.

Conventions (matched to the tree-walk) ​

  • proj_child(n) = nth child of current node: reads node.payload["children"][n] to get the absolute AstRef, then recurses.
  • proj_env("$payload") reads node.payload as the variable name.
  • extend_env("$payload") reads node.payload["name"] as the bind name.
  • No-scheme fallback: if a node kind has no eval scheme, returns node.payload directly.
  • Closure representation: Value::Object with {"__arrow__": true, "params": [...], "body_def": {"__ast__": &lt;arena>}, "binds": {...}, "handlers": [...]} — self-contained serializable data (ADR-0106), created by Instr::Closure.
  • Native ops: add, sub, mul, div, mod, neg, eq, neq, lt, gt, lte, gte, and, or, not, tag, id, closure, bind — identical semantics to the tree-walk.
  • Scope: Vec<HashMap<String, Value>> scope stack; extend_env pushes a child scope; lookup searches innermost-first. Arrow applications install the arrow's binds as the captured root, bind params, eval the body_def arena, restore.
