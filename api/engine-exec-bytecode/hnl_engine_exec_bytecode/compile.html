hnl_engine_exec_bytecode::compile::arith_instr ​

Function

Map a native op name to an [ArithOp] for the ADR-0103 Arith hardware-boundary instruction, if the op is one of the arithmetic/logic ops not already covered by [typed_binary_instr].

Returns Some for neg (unary), and/or (binary logic), and not (unary). These currently go through NativeOp; emitting Arith instead begins the migration to the target minimal ISA. The common binary numeric ops (add/sub/mul/…) remain on the dedicated typed bytecodes for now (hot-path optimization); they will migrate to Arith in a later step. All other native ops fall through to NativeOp.

fn arith_instr(op: &str) -> Option<crate::instr::ArithOp>

hnl_engine_exec_bytecode::compile::compile_into ​

Function

Recursively append instructions for scheme into out.

After execution of the appended instructions, exactly one value remains on the operand stack. No trailing [Instr::Return] is emitted -- the caller ([compile]) adds it once at the top level.

Returns Ok(true) if the compiled code pushes a scope that the caller is responsible for popping (i.e. extend_env was emitted). This mirrors the tree-walk's did_push discipline.

This is the &Term entry point: it converts the scheme to [TermData] (ADR-0103 Phase 6) and delegates to [compile_into_td], which dispatches on the __tag__ field instead of matching the Term enum.

fn compile_into(scheme: &handl_language::Term, lang: &handl_language::Language, ast: &handl_language::Ast, node: &handl_language::AstNode, out: & mut Vec<crate::instr::Instr>) -> Result<bool, handl_language::LangError>

hnl_engine_exec_bytecode::compile::compile_op_arg ​

Function

Compile a single Arr/Op argument. A bare 0-arg native op that uses incoming (id, inc, truthy, ...) in arg position sees the enclosing op's incoming — the region's current incoming — per the tree-walk's arg evaluation (eval_arr evaluates each arg with the Arr's incoming). Emitting a bare NativeOp(op, 0) there would instead pop the previous arg's pushed result and underflow the enclosing op, so emit [Instr::PushIncoming] first — the NativeOp then pops that copy and applies the op.

hnl_engine_exec_bytecode::compile::try_extract_closure_params_body ​

Function

Try to extract the param names and body node index from a function (closure) AST node's payload at compile time.

Mirrors the two payload shapes handled by the closure native op in vm.rs:

  • Rich: {"params": ["n", "a", ...], "body": <node_idx>} — the params are literal strings and body is a node index.
  • Pratt-parsed: {"children": [param_idx, body_idx]} — param_idx points to a node that is either a single var (one param) or a paren/array of var children (multiple params); body_idx points to the body node.

Returns Ok(None) if the payload shape is unrecognized or a param node lacks a string payload, so the compiler falls back to NativeOp("closure", n). Returns Err only for AST lookup failures (malformed arena indices), matching the runtime handler's behavior.

rust
fn try_extract_closure_params_body(lang: &handl_language::Language, ast: &handl_language::Ast, node: &handl_language::AstNode) -> Result<Option<StaticClosure>, handl_language::LangError>

hnl_engine_exec_bytecode::compile::try_extract_static_object_keys ​

Function

Try to extract static keys from an object AST node's children payload.

The object node's payload["children"] is an array of entry-node arena indices. Each entry node has payload["children"] = [key_idx, val_idx]. A key is static when the entry shape declares the key child's kind in its literal_children list for the key role (ADR-0081 — e.g. var/string; the payload string is used directly as the key — see the object handler in vm.rs). Computed keys (e.g. [expr]: desugared to paren) cause this function to return None, so the compiler falls back to NativeOp("object", n).

The var/string kind fallback below is redundant when the lower pass has normalized string keys to var (BytecodeEngine::with_lowering), and when the entry shape declares literal_children for key. It is retained only for the non-lowering path and for role-less entry shapes.

Returns None if the payload shape is not children (e.g. the entries rich-payload shape) or if any key is dynamic.

rust
fn try_extract_static_object_keys(lang: &handl_language::Language, ast: &handl_language::Ast, node: &handl_language::AstNode) -> Result<Option<StaticObjectKeys>, handl_language::LangError>
