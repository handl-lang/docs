handl_plugin_compile_js::lower::primitive::check_sequential ​

Function

ADR-0120 Phase 5: Seq{axis: k} is ∘ₖ. The JS backend lowers only the sequential regime — ∘₀ on 1-cells (dim(fst) ≤ 1). The globular pasting regime (k < dim(fst) — including axis 0 on cell operands) needs the Cell2 value model, which generated JS does not carry; those terms are rejected here rather than silently compiled to sequencing.

fn check_sequential(axis: &hnl_engine::Term, fst: &hnl_engine::Term) -> Result<(), handl_plugin_compile::CompileError>

Function

await — the js.await op. Takes exactly one argument (the promise) and emits (await __handl_rt.await(<arg>)): the helper resolves to a Result — tag.tag("ok", {value: v}) or tag.tag("err", {value: e}) — never rejects — so a rejection is data, not an exception unwinding out of the Handl program, and callers read it with tag.tag_of / tag.untag exactly as they do at eval time.

handl_plugin_compile_js::lower::primitive::lower_bound_arrow_record ​

Function

Emit a {__term__, __bound__} bound-arrow record (Op{record} with that literal key pair) as a JS arrow value:

js
(await (async () => {
  const __b = <bound>;
  return async __args => (await (<term>)(__handl_rt.__appInput(__b, __args)));
})())

__b is evaluated once at construction against the enclosing input — the record-freeze point — and the call packs bound ++ call-args into the inner arrow's __in (the term_interpreter application rule: a lone arg stays bare, a tuple spreads). __term__ lowers through the ordinary value path: a quoted Arr is already a JS arrow, and a nested bound-arrow record is its own wrapper — both are callable. Returns None (fall back to the plain-record emit) for any other shape.

rust
fn lower_bound_arrow_record(args: &[hnl_engine::Term], lit: Option<&serde_json::Value>, param: &super::JsAst) -> Result<Option<super::JsAst>, handl_plugin_compile::CompileError>

handl_plugin_compile_js::lower::primitive::lower_seq_body ​

Function

fst >>> snd: evaluate fst's result once into a const when it is not a trivially-reusable expression, then run snd on the name.

Without the binding, snd's lowering clones the expression into every input position it touches (branch cond + both arms, product args, …), so a stage like fetch(...) or pair_tag(product(...)) would re-evaluate per use. The IIFE keeps statement context legal and preserves the source's eager evaluation order — the const runs at exactly the point the Seq stage runs.

rust
fn lower_seq_body(fst: &hnl_engine::Term, snd: &hnl_engine::Term, input: &super::JsAst) -> Result<super::JsAst, handl_plugin_compile::CompileError>
