hnl_engine_typecheck_nbe::predicate_eval::SymExpr ​

Enum

A symbolic expression built during partial evaluation of a predicate body. This is a mini-IR that covers the common operations in predicate bodies (arithmetic, equality, boolean logic). Anything outside this subset normalizes to [SymExpr::Stuck], which maps to [Proof::blocked].

Variants:

  • Int(i64) - A concrete integer.
  • Bool(bool) - A concrete boolean.
  • Var(String) - A free symbolic variable (e.g. the predicate parameter).
  • Add(Box<SymExpr>, Box<SymExpr>) - Integer addition a + b.
  • Sub(Box<SymExpr>, Box<SymExpr>) - Integer subtraction a - b.
  • Mul(Box<SymExpr>, Box<SymExpr>) - Integer multiplication a * b.
  • Mod(Box<SymExpr>, Box<SymExpr>) - Integer modulo a % b.
  • Eq(Box<SymExpr>, Box<SymExpr>) - Integer equality a == b.
  • Neq(Box<SymExpr>, Box<SymExpr>) - Integer inequality a != b.
  • Lt(Box<SymExpr>, Box<SymExpr>) - Integer less-than a < b.
  • Gt(Box<SymExpr>, Box<SymExpr>) - Integer greater-than a > b.
  • Lte(Box<SymExpr>, Box<SymExpr>) - Integer less-than-or-equal a <= b.
  • Gte(Box<SymExpr>, Box<SymExpr>) - Integer greater-than-or-equal a >= b.
  • And(Box<SymExpr>, Box<SymExpr>) - Boolean AND a && b.
  • Or(Box<SymExpr>, Box<SymExpr>) - Boolean OR a || b.
  • If(Box<SymExpr>, Box<SymExpr>, Box<SymExpr>) - Conditional if c then t else e.
  • Call(Box<SymExpr>, Vec<SymExpr>) - Function application callee(args...).
  • Stuck(String) - An expression the normalizer cannot handle.

hnl_engine_typecheck_nbe::predicate_eval::SymFn ​

Type Alias: fn(...)

Type of a symbolic translation handler registered in [sym_registry].

Each handler takes the full AST, the node to translate, and the symbolic environment. It returns Some(SymExpr) if it can handle the node kind, or None if not (the caller falls through to the Stuck case).

hnl_engine_typecheck_nbe::predicate_eval::ast_to_sym ​

Function

Translate a Handl AST node into a symbolic expression, given a mapping from variable names to their symbolic values (the predicate parameter is bound to the expression's symbolic representation).

Dispatch is table-driven via [sym_registry]: the node's kind is looked up in the registry and, if a handler is registered, it is invoked. Unregistered kinds produce [SymExpr::Stuck].

fn ast_to_sym(ast: &handl_language::Ast, node_ref: handl_language::AstRef, env: &std::collections::HashMap<String, SymExpr>) -> SymExpr

hnl_engine_typecheck_nbe::predicate_eval::function_param_body ​

Function

Extract parameter names and body index from a function node, handling both the rich params/body payload and the legacy children array format (Phase 3.2).

  • Rich format: {params: ["name", ...], body: idx} — names are inline.
  • Legacy format: {children: [param_idx, body_idx]} — param_idx points to a var node (or a paren/array wrapper of var nodes) whose payload is the param name.

Returns (param_names, body_idx).

hnl_engine_typecheck_nbe::predicate_eval::sym_registry ​

Function

Build (once) and return the static sym registry — a table mapping node kind strings to symbolic translation handler functions.

This is a data-driven dispatch: the registry is a HashMap table, not a hardcoded match statement. New node kinds can be added by inserting a new entry here (or, in the future, by loading entries from language data). The handlers themselves still know about the kinds they translate — this is inherent to a symbolic translator — but the dispatch is table-driven and extensible.

rust
fn sym_registry() -> &'static std::collections::HashMap<&'static str, fn(...)>
