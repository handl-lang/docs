hnl_engine_typecheck_nbe ​

hnl-engine-typecheck-nbe ​

A data-driven, normalization-based typecheck engine implementing the [TypecheckEngine] trait (ADR-0054 — Generic Typecheck Engine).

This crate is a new, minimal, real engine that proves the ADR-0054 architecture end-to-end. It is not a rewrite of the legacy plugin-typecheck-nbe crate; the full rewrite is gated on spikes per the ADR's Status section.

Architecture (ADR-0054 §4) ​

The engine:

  1. Implements [TypecheckEngine].
  2. Holds a bound [EvalEngine] (for value-level computation in type rules — "types are values", ADR-0032). The bound eval engine is the pure-eval path: effectful Foreign ops are rejected. For this initial impl, the host constructs the typecheck engine with a pure eval engine; the purity boundary is the host's responsibility.
  3. Reads lang.types[node.kind] → [TypeRuleDef] → [Term] (the synth scheme; check is optional) and interprets it.
  4. Implements the judgment ops (ADR-0054 §2) as Arr ops with [ArrSource::Judgment].
  5. Produces tagged type values via the [TypeRegistry] from plugin-lib-tag (ADR-0055): construct mints {"__tag__":"type.<tag>","__registry__":"handl.canonical",...}, match_type dispatches on the tag.

Threading convention ​

[Term::Seq] threads the fst result into snd as the incoming value. The last Seq's result is the scheme's result. To recall a previously-computed value, use the bind / result judgment ops:

text
synth_child(0) >>> bind("t") >>> ... >>> result("t")

bind(name) stores incoming under name; result(name) recalls it.

Choice convention ​

[Term::Choice] routes on an Either value encoded as {"__choice__": "left"|"right", "value": v}. l handles left, r handles right.

Limitations of this initial impl ​

  • [Term::Loop] and [Term::App] are not supported (return [LangError::NotImplemented]).
  • Native Arr ops in type rules are supported only for const and id (trivial, common); other native ops return an engine error. The ADR notes the op set is "refined during implementation". ForeignArr ops in type rules are rejected (ADR-0054 pure-eval path): type rules are static data and must never invoke effectful host calls. The eval_child/proj_child judgment ops additionally perform a static purity check on the child's AST subtree (gated by the pure flag, default true).
  • unify uses structural equality, metavariable solving, and recursive structural unification of tagged type values with the same tag from the same registry (ADR-0054 legacy migration); no occurs-check or higher-rank polymorphism. For dependent Pi/Sigma types with body_closure fields, unify skips the closure marker (only unifies param); use the unify_pi judgment op for full closure-based unification (fresh var, apply both, unify bodies).
  • Dependent-type closure machinery (construct_pi, construct_sigma, pi_apply, unify_pi, check_pi_body) brings NBE closures into the data-driven engine for Pi/Sigma types (ADR-0054). A Pi/Sigma type value carries a body_closure field recording the variable name and the AST child index of the body; closure application marks Γ, extends it, synths the body child, and restores Γ — mirroring the legacy Closure::apply.
  • Forall (parametric polymorphism) and Vau (fexpr) type support (construct_forall, forall_apply, unify_forall, construct_vau_type, vau_apply, unify_vau) extends the closure machinery to type.forall (universal quantification — parameter is a type, field is kind) and type.vau (unevaluated-parameter functions — like type.pi but marked as fexpr). Both reuse the same body_closure/apply_type_closure machinery as Pi/Sigma (ADR-0054).
  • Equality type support (construct_eq, construct_empty, check_refl, eq_reduce) brings propositional equality into the data-driven engine (ADR-0054): Eq(a, b) is the equality type (inhabited by Refl iff a == b), Refl is the proof, and Empty is the empty type (contradiction, used when equality fails). These mirror the legacy Value::Eq, Value::Refl, Value::Empty.
