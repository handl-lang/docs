hnl_engine_typecheck_nbe::NbeTypecheckEngine::synth_handle_judgment ​

Function

synth_handle — handle <body> with <h> typed-effect handler typing (phase-2 WS-F; ADR-0153 §4 "effects are objects in the codomain").

The body's IO(S) former has its op set checked against h's declared impls, and the result re-wraps as IO(S') mirroring the runtime's interpret-in-place semantics ([engine-exec-tree-walk] interpret_io_former): each covered entry's declared type is replaced by the impl's declared return type (the op is interpreted, its result is data); each uncovered entry keeps its declared signature (the op stays IO data for an outer handler or user destructuring). The residual sig is therefore S' = (S \ S_h) ∪ {op: ret_ty} — the spec's IO(S \ S_h) × results shape.

Coverage rules:

  • h's op names are its record fields (type.record{fields}). A covered impl h_k : dom ~> ret must accept the op's declared sig entry — S[k] <: dom — and ret is the result type.
  • An impl h declares for an op S never names → diagnostic (spurious — the impl can never fire).
  • S non-empty with h covering none of it → diagnostic (the handle is a guaranteed no-op — almost certainly a bug).
  • h op-untyped (meta / type.Obj / type.unknown) or S symbolic (a sig meta/var — row-polymorphic IO(s)) → the check is undecidable → pass through unchanged (honest bound).
  • body's type is A ~> IO(S) (a type.function whose codomain is an IO former) — the deep-handler case (handle f with h binds the handled arrow, runtime attach_carried_handler): the codomain's sig is checked the same way, producing A ~> IO(S'). A type.pi codomain (a closure) can't rewrite statically → passthrough.

hnl_engine_typecheck_nbe::NbeTypecheckEngine::synth_match_dependent ​

Function

Dependent elimination (ADR-0152 §3): each ctor-pattern arm instantiates the constructor's ctor_sig, unifies its family_app result indices with the scrutinee's (rigid var indices rewrite through results + an eq_<name> Path witness), binds the pattern fields to the instantiated domains, and checks the body — against the motive applied at the refined indices when a return … with clause is present. A decided index-unsatisfiable arm is auto-discharged: coverage doesn't require it, its body is unchecked but allowed, and absurd stays legal purely as explicit documentation of the dead branch. absurd on a reachable arm remains an error. How the per-arm expected type of a dependent match is produced: an explicit return … with AST motive, or an inferred motive built from the expected result type (phase-2 WS-C) — {vars, template} where template is a type value carrying var{vars[i]} holes substituted with the refined index terms per arm.

hnl_engine_typecheck_nbe::NbeTypecheckEngine::unify ​

Function

Unify two type values (structural equality + metavariable solving + recursive structural unification of tagged type values).

If both sides are equal, succeeds. If one side is an unsolved metavariable ({"__meta__": id}), solves it to the other side (after an occurs-check). If both sides are tagged type values from the same registry with the same tag, recursively unifies their payload fields (ADR-0054 legacy migration). Otherwise returns an engine error.
