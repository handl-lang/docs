hnl_engine_typecheck_nbe::NbeTypecheckEngine ​

Struct

A data-driven, normalization-based typecheck engine (ADR-0054).

Implements [TypecheckEngine] by interpreting the arrow-calculus [Term]s found in lang.types[node.kind]. Value-level computation within type rules is delegated to a bound [EvalEngine] (the pure-eval path); judgment ops are interpreted directly.

Module: checker ​

The Val-domain checking core (phase-1 spec WS-B; ADR-0154 §§2–5, ADR-0152 §1, ADR-0153 §1).

This module is the semantic kernel the lang.types[kind] judgment ops dispatch into: types are values in handl_value::nbe::Val — nominal sym formers with index args — and checking is

  • infer — synthesize the type of a domain value;
  • check — infer then subtype (directed checking);
  • conv — nominal heads + structural bodies + meta solving (delegates to [handl_value::nbe::conv]);
  • subtype — conv else the parent walk over nominal heads (ADR-0154 §2: subtyping is the parent link; membership x : T is the type link — two relations, not one chain).

No host closures anywhere: a former's signature is an explicit [Telescope] — params + result data where dependent positions mention earlier params as Rigid level heads — and Pi's universe rule is max(domain, codomain) computed by [Checker::infer_pi] after the caller has inferred the body under an extended Γ.

Literals are constrained metas (ADR-0154 §5): infer on an integer/float literal mints Flex constrained DescendantOf(type.number)/DescendantOf(type.float); unresolved metas default to the constraint anchor (default_unsolved).

Module: predicate_eval ​

Predicate-as-type checking via the bound eval engine (ADR-0068 step B1).

When a type annotation is a predicate (a function value that returns type.bool), the typechecker normalizes predicate(expr) via the bound [EvalEngine]. The result determines the annotation outcome (ADR-0068 §1, "graduated guarantees"):

  • Value::Bool(true) → [Proof::ok] — proven statically, no runtime check.
  • Value::Bool(false) → [Proof::no] — disproved, the annotation is rejected.
  • Any other value or an eval error → [Proof::blocked] — normalization could not finish; the caller accepts the annotation with a runtime backstop assert T(e).

This is the concrete-annotation case (B1): the expression value is fully known, so the predicate is run rather than reasoned about symbolically. Symbolic normalization for dependent annotations (B2) is a later step.

Closure bodies are self-contained (ADR-0106) ​

A closure value carries its body as a body_def {"__ast__": <arena>} value — a standalone arena with every free variable substituted at mint time — plus a binds map for the residual bindings that could not be substituted (rec binders, non-serializable captures). The B2 symbolic path decodes that arena directly, so it no longer depends on indices into the caller's AST. (The B1 path below still clones the original AST before appending the call node the eval engine runs — harmless, since indices are preserved and the subtree is self-contained.)

Module: totality_check ​

Totality checking via structural recursion analysis (Phase 7.1).

When a function is annotated Total(A -> B), the typechecker checks whether the function is total (terminates on all inputs) by verifying structural recursion:

  • Generated recursors: if the function node carries termination metadata (via [read_termination_metadata]), it is recognized as structurally recursive — the data desugaring guarantees termination.
  • User-written recursive functions: a syntactic check finds all recursive calls (calls to the function being checked within its body) and verifies each call's argument is a strict sub-structure of a parameter (e.g. n.pred is a sub-structure of n). "Strict sub-structure" means: the argument is a chain of field-access nodes ending in a parameter variable.
  • Non-recursive functions: trivially total (no recursive calls → no infinite recursion).

This is a conservative check: it only recognizes field-access decreasing (matching the inductive-type pattern). Arithmetic decreasing (e.g. n - 1) is not recognized — such functions are Disproved by this simple check, which is acceptable per the Phase 7 design.
