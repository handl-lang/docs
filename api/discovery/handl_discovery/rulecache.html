handl_discovery::rulecache::HookSigs ​

Struct

Stability signatures for a rule's hooks — the _hook_sig seam.

Rust dyn Fn hooks are opaque (no inspect.getsource); the domain supplies a tag — its rule-bank version, or a content hash of the spec the hooks were compiled from. An unstable signature only ever causes a cache miss, never a wrong hit — conservative by design.

handl_discovery::rulecache::dec_rule ​

Function

Rebuild a rule — _dec_rule.

Guarded rules re-run [compose_guards] on the stored re-expression maps; the parents must resolve (by name) in by_name, or the error propagates and the whole load is a miss. The composite derive attaches only where the RHS carries the "@i:" placeholders it refills — the spec's offer/load policy.

rust
fn dec_rule(rec: &RuleRecord, by_name: &std::collections::BTreeMap<std::rc::Rc<str>, std::rc::Rc<crate::terms::Mint>>) -> Result<std::rc::Rc<crate::terms::Mint>, String>

handl_discovery::rulecache::synthesize_rules_cached ​

Function

meta.synthesize_rules with persistence — rulecache.synthesize_rules_cached.

On a repeat call with the same ruleset, seeds, and parameters the derived rules load from the cache (composite guards rebuilt from the parent hooks) instead of re-deriving. synthesize is the domain engine, injected: the search machinery is out of this crate's scope — the cache contract is what is ported.

rust
fn synthesize_rules_cached<impl FnOnce(&[Rc<Mint>], &[Term], &SynthParams) -> Vec<Rc<Mint>>>(cache: &RuleCache, rules: &[std::rc::Rc<crate::terms::Mint>], seed_terms: &[handl_egraph::Term], params: &SynthParams, sig: &dyn Fn, synthesize: impl Trait) -> io::Result<Vec<std::rc::Rc<crate::terms::Mint>>>
