handl_discovery::terms::ReExpr ​

Struct

A re-expression spec: the maps pat1/pat2 of the spec's guard_pats — each parent's metavariables expressed as patterns over the derived rule's metavariables.

terms maps a parent term metavariable to a pattern term; attrs maps a parent attribute metavariable to either a concrete value (TermAttr::Lit) or a reference to a derived-rule attr metavariable (TermAttr::Meta — resolved through the fired binding at guard time). The typed Meta/Lit split is a named improvement over the spec's wire form, where a plain string attr is ambiguously both.

Fields:

  • terms: std::collections::BTreeMap<std::rc::Rc<str>, handl_egraph::Term> - Parent term metavariable -> pattern over derived metavars.
  • attrs: std::collections::BTreeMap<std::rc::Rc<str>, handl_egraph::TermAttr> - Parent attr metavariable -> literal value or meta reference.

Build the derived rule's (check, derive) from the parents' — meta._compose_guards.

The composite check on a fired binding bound is r1.check(b1) && r2.check(b2) where b_i is the parent's re-expressed binding; derive hooks re-run (they can veto) and their outputs fill the "@i:" placeholders the derived RHS carries. Returns (None, None) when neither parent is guarded.

handl_discovery::terms::match_pattern ​

Function

Structural match of a pattern against a plain term — egraph.terms._term_match.

subst.terms maps metavariables to subterms (the term-level convention — the e-graph maps them to e-class ids instead). Repeated metavariables must bind structurally equal subterms; TermAttr::Meta binds into subst.attrs; literal attrs compare with AttrValue::match_eq (numeric leniency, the spec's !=).

Returns false on mismatch; subst may be partially extended on failure — the spec's contract, kept (callers pass a fresh env).

rust
fn match_pattern(pat: &handl_egraph::Term, term: &handl_egraph::Term, subst: & mut handl_egraph::BoundEnv) -> bool
